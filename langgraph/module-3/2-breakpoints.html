LangGraph’ta Breakpoint’ler: İnsan Onayıyla Tool Çalıştırma

Bu ders, tool çağırabilen bir agent graph’ında yürütmeyi belirli bir node’dan önce durdurmayı, checkpoint üzerinden state’i incelemeyi ve insan onayı verildikten sonra aynı state’ten devam etmeyi açıklar.

Kapsam ve Bağlam

Bu bölümde ele alınan temel problem, agent’ın hassas bir işlem yapmadan önce insan denetimine açılmasıdır. Örnek basit aritmetik tool’ları üzerinden ilerler; fakat aynı desen veritabanına yazma, dış servis çağırma, dosya değiştirme veya finansal işlem başlatma gibi daha riskli eylemler için de aynı mantığı kurar.

Bu Dersin Ana Tezi

Breakpoint, LangGraph yürütmesini belirli bir node’dan önce veya sonra durdurarak insan onayı, hata ayıklama ve state düzenleme iş akışlarına kontrollü bir giriş noktası sağlar. Bu derste odak, tools node’u çalışmadan önce durmak ve checkpoint’ten güvenli biçimde devam etmektir.

Öğrenme Hedefleri

  • interrupt_before=["tools"] ile graph’ın tool node’u başlamadan nasıl kesildiğini açıklayabilecek.
  • MemorySaver ve thread_id ilişkisinin checkpoint sürekliliğindeki rolünü yorumlayabilecek.
  • graph.get_state(thread) ve state.next çıktısıyla graph’ın nerede durduğunu doğrulayabilecek.
  • graph.stream(None, thread, ...) çağrısının yeni input vermeden checkpoint’ten devam etmek anlamına geldiğini ayırt edebilecek.
  • İnsan onayını graph state’i ile uygulama katmanı kararı olarak birbirinden ayırabilecek.
  • LangGraph SDK üzerinden interrupt_before argümanını run düzeyinde kullanabilecek.

Ön Koşullar

  • Python fonksiyonları, listeler, dictionary yapıları ve type hint okuma becerisi.
  • LLM, chat message, tool call ve agent döngüsü hakkında temel sezgi.
  • StateGraph, node, edge, START, MessagesState ve compile kavramlarına giriş düzeyinde aşinalık.
  • Checkpoint ve thread kavramlarının graph state’ini yürütmeler arasında saklamak için kullanıldığını bilmek.
  • API örnekleri için yerel geliştirme sunucusunun http://127.0.0.1:2024 adresinde çalıştığını varsaymak.

Büyük Resim

Human-in-the-loop yaklaşımında amaç, agent’ın her adımını durdurmak değildir; riskli veya denetlenmesi gereken adımı açık bir karar noktasına çevirmektir. Bu derste riskli adım tool yürütmedir. Assistant önce tool call üretir, graph tool node’una gitmek üzereyken durur, uygulama bu state’i kullanıcıya gösterebilir ve onay gelirse aynı checkpoint’ten devam eder.

Ana Anlatım

Breakpoint neden gereklidir?

Agent sistemlerinde tool call üretmek ile tool’u gerçekten çalıştırmak aynı risk seviyesinde değildir. Modelin “multiply aracını şu argümanlarla çağırmak istiyorum” demesi denetlenebilir bir öneridir; tool node’unun çalışması ise gerçek eylemdir. Breakpoint bu iki anı ayırır.

Onay, debugging ve editing

Bu ders onay akışına odaklanır. Aynı mekanizma hata ayıklamada geçmiş checkpoint’e bakmak veya state’i insan geri bildirimiyle değiştirmek için de temel oluşturur. Bu yüzden breakpoint yalnızca UI onay butonu değil, state denetimi için bir runtime primitive’idir.

Checkpoint ve thread ilişkisi

Breakpoint’in çalışması için graph’ın durduğu state’in saklanması gerekir. MemorySaver bu örnekte state checkpoint’lerini bellekte tutar. thread_id ise hangi checkpoint zincirinin okunacağını belirler. Bu ikisi olmadan input=None ile devam etmek için güvenilir bir “son state” bulunamaz.

Kritik ayrım

input=None, “boş mesaj gönder” anlamına gelmez. Bu çağrı, aynı thread’in son checkpoint’inden graph yürütmesini devam ettirme talimatıdır.

Aritmetik araçları ve tool binding

Agent’ın çağırabileceği üç Python fonksiyonu tanımlanır ve chat modeline araç olarak bağlanır.

Aritmetik araçları ve tool binding
from langchain_openai import ChatOpenAI


def multiply(a: int, b: int) -> int:
    """Multiply a and b.

    Args:
        a: first int
        b: second int
    """
    return a * b


# This will be a tool
def add(a: int, b: int) -> int:
    """Adds a and b.

    Args:
        a: first int
        b: second int
    """
    return a + b


def divide(a: int, b: int) -> float:
    """Divide a by b.

    Args:
        a: first int
        b: second int
    """
    return a / b


tools = [add, multiply, divide]
llm = ChatOpenAI(model="gpt-4o")
llm_with_tools = llm.bind_tools(tools)

LangGraph açısından önemi

llm.bind_tools(tools), modelin doğal dil cevabı yerine yapılandırılmış tool call üretebilmesini sağlar.

Dikkat edilmesi gereken nokta

Araçların kendisi basit aritmetik yapar; pedagojik amaç hassas tool kullanımı öncesinde insan onayı noktasını göstermek içindir.

Breakpoint içeren agent graph’ını kurma

Bu blok, mesaj state’i taşıyan iki node’lu agent graph’ını kurar: assistant modeli çağırır, tools ise seçilen aracı yürütür. Derleme sırasında interrupt_before=["tools"] verilerek tool node’undan önce durma noktası tanımlanır.

Breakpoint içeren agent graph’ını kurma
from IPython.display import Image, display

from langchain_core.messages import AIMessage, HumanMessage, SystemMessage
from langgraph.checkpoint.memory import MemorySaver
from langgraph.graph import MessagesState
from langgraph.graph import START, StateGraph
from langgraph.prebuilt import ToolNode, tools_condition

# System message
sys_msg = SystemMessage(
    content=(
        "You are a helpful assistant tasked with performing arithmetic "
        "on a set of inputs."
    )
)


# Node
def assistant(state: MessagesState):
    """
    Run the assistant graph node.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    return {
        "messages": [
            llm_with_tools.invoke([sys_msg] + state["messages"])
        ]
    }


# Graph
builder = StateGraph(MessagesState)

# Define nodes: these do the work
builder.add_node("assistant", assistant)
builder.add_node("tools", ToolNode(tools))

# Define edges: these determine the control flow
builder.add_edge(START, "assistant")
builder.add_conditional_edges(
    "assistant",
    # If the latest message (result) from assistant is a tool call -> tools_condition routes to tools
    # If the latest message (result) from assistant is a not a tool call -> tools_condition routes to END
    tools_condition,
)
builder.add_edge("tools", "assistant")

memory = MemorySaver()
graph = builder.compile(interrupt_before=["tools"], checkpointer=memory)

# Show
display(Image(graph.get_graph(xray=True).draw_mermaid_png()))

LangGraph açısından önemi

builder.add_conditional_edges("assistant", tools_condition), assistant cevabında tool call varsa akışı tools node’una yönlendirir; aksi durumda graph biter.

Dikkat edilmesi gereken nokta

interrupt_before=["tools"] tool’u çalıştırmaz; tool çalışmadan hemen önce checkpoint üzerinde durur ve insan onayı için state’i incelemeyi mümkün kılar.

Graph görseli

Çıktı Yorumu

Görsel, START → assistant başlangıcını, assistant sonrasındaki koşullu rotayı ve tool çalıştıktan sonra tekrar assistant’a dönen döngüyü gösterir. Breakpoint graph topolojisini değiştirmez; yürütme zamanında tools öncesinde durdurma davranışı ekler.

İnsan onayı adımını kodla birleştirme

Bu blok aynı breakpoint davranışını basit bir onay girdisiyle birleştirir. Kullanıcı onay verirse graph son checkpoint’ten devam eder; aksi durumda işlem iptal edilir.

İnsan onayı adımını kodla birleştirme
# Input
initial_input = {"messages": HumanMessage(content="Multiply 2 and 3")}

# Thread
thread = {"configurable": {"thread_id": "2"}}

# Run the graph until the first interruption
for event in graph.stream(initial_input, thread, stream_mode="values"):
    event['messages'][-1].pretty_print()

# Get user feedback
user_approval = input("Do you want to call the tool? (yes/no): ")

# Check approval
if user_approval.lower() == "yes":
    # If approved, continue the graph execution
    for event in graph.stream(None, thread, stream_mode="values"):
        event['messages'][-1].pretty_print()
else:
    print("Operation cancelled by user.")

LangGraph açısından önemi

user_approval, graph state’i içinde değil, uygulama katmanında alınan insan kararıdır. Onay verilirse graph.stream(None, thread, ...) aynı checkpoint’ten devam eder.

API üzerinden breakpoint ile stream başlatma

initial_input = {"messages": HumanMessage(content="Multiply 2 and 3")}
thread = await client.threads.create()
async for chunk in client.runs.stream(
    thread["thread_id"],
    assistant_id="agent",
    input=initial_input,
    stream_mode="values",
    interrupt_before=["tools"],
):
    print(f"Receiving new event of type: {chunk.event}...")
    messages = chunk.data.get('messages', [])
    if messages:
        print(messages[-1])
    print("-" * 50)

Çıktı Yorumu

Devam çıktısı üç önemli state görünümü taşır: bekleyen tool call, multiply tool mesajı ve tool sonucuna dayalı final assistant mesajı. Bu sıra, breakpoint’in tool öncesinde durduğunu ve onaydan sonra normal agent döngüsünün sürdüğünü gösterir.

Çıktıların Yorumlanması

Çıktılar üç ayrı kanıt sunar. İlk olarak graph görseli, assistant ile tools arasındaki döngüyü doğrular. İkinci olarak state.next çıktısı, breakpoint sonrası sıradaki node’un tools olduğunu gösterir. Üçüncü olarak yerel graph ve API stream çıktıları, input=None sonrasında önce bekleyen tool call’ın yeniden görünür kılındığını, sonra tool sonucunun ve final assistant cevabının geldiğini gösterir.

Graph Akışı

Koddan çıkarılan gerçek graph akışı aşağıdaki gibidir:

STARTGraph yürütmesinin sanal başlangıcı.
assistantllm_with_tools.invoke ile model çağrısı yapar.
tools_conditionTool call varsa tools, yoksa bitiş yönü seçer.
toolsToolNode(tools) seçilen tool’u yürütür.
assistant / ENDTool sonucundan sonra assistant final cevap üretir.

Derleme ayarı interrupt_before=["tools"] olduğu için graph topolojisi aynı kalır; yalnızca yürütme tools node’u başlamadan önce checkpoint üzerinde durur.

State’in Evrimi

1. Başlangıç

messages alanında HumanMessage(content="Multiply 2 and 3") bulunur.

2. Assistant update’i

Assistant node’u messages kanalına tool call içeren bir AI mesajı ekler.

3. Breakpoint snapshot’ı

Checkpoint, tool çalışmadan önceki state’i ve next=('tools',) bilgisini saklar.

4. Onay sonrası devam

input=None aynı checkpoint’ten devam eder; tool node’u 6 sonucunu üretir.

5. Final assistant cevabı

Assistant tool mesajını okuyarak “The result of multiplying 2 and 3 is 6.” cevabını üretir.

Agent / Tool Etkileşimi

KullanıcıMultiply 2 and 3
Assistantmultiply tool’u için a=2, b=3 argümanlarıyla tool call üretir.
BreakpointGraph tools node’u başlamadan durur; insan onayı beklenebilir.
ToolOnaydan sonra multiply çalışır ve 6 döndürür.
AssistantTool sonucunu okuyarak final cevabı üretir.

Bu akışta tool çıktısı doğrudan nihai assistant cevabı değildir. Tool sonucu state’e mesaj olarak eklenir; son doğal dil cevabını assistant node’u üretir.

Yaygın Hatalar

  • interrupt_before ayarının node’u tamamen devre dışı bıraktığını düşünmek. Gerçekte node yalnızca başlamadan önce durdurulur.
  • Checkpoint olmadan input=None ile devam edilebileceğini varsaymak.
  • thread_id değiştiğinde eski breakpoint state’ine dönüleceğini sanmak.
  • Tool call mesajını tool’un gerçekten çalıştığı anlamına almak.
  • state.next bilgisini kontrol etmeden uygulamada onay ekranı açmak.
  • İnsan onayını graph state’iyle karıştırmak; onay çoğu zaman uygulama katmanı kararıdır.
  • API tarafında interrupt_before run parametresiyle verilebildiğini gözden kaçırmak.
  • Yerel geliştirme sunucusu çalışmadan SDK stream örneklerinin çalışmasını beklemek.

Son Çıkarımlar

  1. Breakpoint, agent yürütmesinde riskli adımı denetlenebilir bir karar noktasına dönüştürür.
  2. interrupt_before=["tools"], tool node’u çalışmadan hemen önce graph’ı durdurur.
  3. Tool call mesajı, tool’un çalıştığı anlamına gelmez; yalnızca modelin tool çalıştırma isteğidir.
  4. Checkpoint, breakpoint sonrası devam etmenin teknik temelidir.
  5. thread_id, hangi checkpoint zincirinden devam edileceğini belirler.
  6. graph.get_state(thread), durulan state’i ve sıradaki node’u incelemek için kullanılır.
  7. input=None, yeni input değil, mevcut checkpoint’ten devam talimatıdır.
  8. Onay akışı uygulama katmanında alınabilir; graph ancak onay sonrası devam ettirilir.
  9. SDK kullanırken interrupt_before derleme zamanında değil, stream çağrısında da verilebilir.
  10. Tool sonucu state’e mesaj olarak eklenir; final doğal dil cevabı tekrar assistant node’u tarafından üretilir.

import getpass
import os


def _set_env(var: str):
    """
    Set an environment variable when it is missing.

    Args:
        var: Environment variable name.
    """
    if not os.environ.get(var):
        os.environ[var] = getpass.getpass(f"{var}: ")


_set_env("OPENAI_API_KEY")

from langchain_openai import ChatOpenAI


def multiply(a: int, b: int) -> int:
    """Multiply a and b.

    Args:
        a: first int
        b: second int
    """
    return a * b


# This will be a tool
def add(a: int, b: int) -> int:
    """Adds a and b.

    Args:
        a: first int
        b: second int
    """
    return a + b


def divide(a: int, b: int) -> float:
    """Divide a by b.

    Args:
        a: first int
        b: second int
    """
    return a / b


tools = [add, multiply, divide]
llm = ChatOpenAI(model="gpt-4o")
llm_with_tools = llm.bind_tools(tools)

from IPython.display import Image, display

from langchain_core.messages import AIMessage, HumanMessage, SystemMessage
from langgraph.checkpoint.memory import MemorySaver
from langgraph.graph import MessagesState
from langgraph.graph import START, StateGraph
from langgraph.prebuilt import ToolNode, tools_condition

# System message
sys_msg = SystemMessage(
    content=(
        "You are a helpful assistant tasked with performing arithmetic "
        "on a set of inputs."
    )
)


# Node
def assistant(state: MessagesState):
    """
    Run the assistant graph node.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    return {
        "messages": [
            llm_with_tools.invoke([sys_msg] + state["messages"])
        ]
    }


# Graph
builder = StateGraph(MessagesState)

# Define nodes: these do the work
builder.add_node("assistant", assistant)
builder.add_node("tools", ToolNode(tools))

# Define edges: these determine the control flow
builder.add_edge(START, "assistant")
builder.add_conditional_edges(
    "assistant",
    # If the latest message (result) from assistant is a tool call -> tools_condition routes to tools
    # If the latest message (result) from assistant is a not a tool call -> tools_condition routes to END
    tools_condition,
)
builder.add_edge("tools", "assistant")

memory = MemorySaver()
graph = builder.compile(interrupt_before=["tools"], checkpointer=memory)

# Show
display(Image(graph.get_graph(xray=True).draw_mermaid_png()))

# Input
initial_input = {"messages": HumanMessage(content="Multiply 2 and 3")}

# Thread
thread = {"configurable": {"thread_id": "1"}}

# Run the graph until the first interruption
for event in graph.stream(initial_input, thread, stream_mode="values"):
    event['messages'][-1].pretty_print()

state = graph.get_state(thread)
state.next

for event in graph.stream(None, thread, stream_mode="values"):
    event['messages'][-1].pretty_print()

# Input
initial_input = {"messages": HumanMessage(content="Multiply 2 and 3")}

# Thread
thread = {"configurable": {"thread_id": "2"}}

# Run the graph until the first interruption
for event in graph.stream(initial_input, thread, stream_mode="values"):
    event['messages'][-1].pretty_print()

# Get user feedback
user_approval = input("Do you want to call the tool? (yes/no): ")

# Check approval
if user_approval.lower() == "yes":
    # If approved, continue the graph execution
    for event in graph.stream(None, thread, stream_mode="values"):
        event['messages'][-1].pretty_print()
else:
    print("Operation cancelled by user.")
