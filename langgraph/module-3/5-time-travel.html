LangGraph’ta Time Travel: Checkpoint, Replay ve Fork

Bu ders, LangGraph’ta geçmiş state kayıtlarını incelemeyi, belirli checkpoint’lerden replay yapmayı ve eski bir state’ten yeni yürütme dalları fork etmeyi açıklar.

Kapsam ve Bağlam

Human-in-the-loop akışlarında onay ve state düzenleme kadar, agent’ın hangi ara durumlardan geçtiğini görmek de önemlidir. LangGraph bu ihtiyacı checkpoint tabanlı time travel yaklaşımıyla karşılar: current state okunur, history gezilir, eski checkpoint replay edilir veya eski checkpoint değiştirilerek yeni bir dal fork edilir.

Temel fikir

Her thread, zaman içinde üretilmiş checkpoint’lerden oluşan bir yürütme geçmişidir. get_state current checkpoint’i, get_state_history geçmiş checkpoint listesini, checkpoint_id ise belirli bir zaman noktasını hedefler.

RunAgent bir thread içinde çalışır ve state adımları üretir.
CheckpointHer önemli adım state, metadata ve config ile kaydedilir.
HistoryGeçmiş snapshot’lar current state’ten geriye doğru okunur.
ReplayÖnceden yürütülmüş checkpoint’ler yeniden çağrılmadan oynatılır.
ForkEski checkpoint değiştirilir ve yeni dal yeniden yürütülür.

Öğrenme Hedefleri

  • StateSnapshot içindeki values, next, config ve checkpoint_id alanlarını yorumlamak.
  • graph.get_state ile current checkpoint’i, graph.get_state_history ile geçmiş checkpoint dizisini okumak.
  • Replay ile re-execution arasındaki farkı teknik olarak ayırmak.
  • update_state çağrılarıyla eski checkpoint’ten fork oluşturmak.
  • MessagesState içindeki mesaj ID’sinin append/overwrite davranışını nasıl etkilediğini açıklamak.

Kavramsal Model

Graph topolojisi node ve edge’lerden oluşur; time travel ise bu topolojinin çalışırken bıraktığı state izlerini kullanır. Aynı graph üzerinde iki farklı zaman işlemi mümkündür: geçmişte zaten yürütülmüş adımları replay etmek veya geçmiş bir checkpoint’i değiştirerek yeni bir dalı re-execute etmek.

Current stateThread’in en yeni checkpoint’i. Graph bitmişse next boştur.
Historical stateHistory içindeki eski snapshot. next devam node’unu gösterebilir.
Replay configÖnceden yürütülmüş checkpoint_id ile aynı yolu yeniden yayınlar.
Fork configUpdate sonrası oluşan yeni checkpoint_id ile downstream node’ları yeniden çalıştırır.

        b: second int
    """

    """
    Adds a and b.

    Args:
        a: first int
        b: second int
    """
    return a + b


def divide(a: int, b: int) -> float:
    """
    Divide a by b.

    Args:
        a: first int
        b: second int
    """
    return a / b

Agent graph’ını kurma

Assistant node’u model çağrısını, tools node’u seçilen Python fonksiyonunu yürütür; checkpoint desteği eklenir.

Agent graph’ını kurma
from IPython.display import Image, display

from langgraph.checkpoint.memory import MemorySaver
from langgraph.graph import MessagesState
from langgraph.graph import START, END, StateGraph
from langgraph.prebuilt import ToolNode, tools_condition

from langchain_core.messages import AIMessage, HumanMessage, SystemMessage

# System message
sys_msg = SystemMessage(
    content=(
        "You are a helpful assistant tasked with performing arithmetic "
        "on a set of inputs."
    )
)

# Node
def assistant(state: MessagesState):
    """
    Run the assistant graph node.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    return {
        "messages": [
            llm_with_tools.invoke([sys_msg] + state["messages"])
        ]
    }

# Graph
builder = StateGraph(MessagesState)

# Define nodes: these do the work
builder.add_node("assistant", assistant)
builder.add_node("tools", ToolNode(tools))

# Define edges: these determine the control flow
builder.add_edge(START, "assistant")
builder.add_conditional_edges(
    "assistant",
    # If the latest message from assistant is a tool call,
    # tools_condition routes to tools.
    # If it is not a tool call, tools_condition routes to END.
    tools_condition,
)
builder.add_edge("tools", "assistant")

memory = MemorySaver()
graph = builder.compile(checkpointer=MemorySaver())

# Show
display(Image(graph.get_graph(xray=True).draw_mermaid_png()))

Replay ve Fork Ayrımı

Replay başlangıcıVar olan checkpoint seçilir.
Replay davranışıÖnceden çalışmış adımlar tekrar yayınlanır.
Fork başlangıcıEski checkpoint üzerinde state update yapılır.
Fork davranışıYeni checkpoint daha önce çalışmadığı için downstream node’lar yeniden çalışır.

Replay, debugging için hızlı ve maliyetsiz bir yeniden izleme sağlar. Fork ise alternatif girdinin agent davranışını nasıl değiştireceğini test eder; bu yüzden model ve tool çağrıları yeniden yapılır.

Studio Üzerinden Alternatif Dallar

Aynı kavramlar görsel arayüz üzerinden de uygulanabilir. Bir node öncesinde durup payload düzenlendiğinde Studio yeni bir fork oluşturur ve seçilen noktadan sonraki graph yürütmesini yeni state üzerinden ilerletir. Karmaşık graph’larda bu yaklaşım alternatif trajectory araştırması için özellikle değerlidir.

Pedagojik sonuç

Time travel, yalnızca hata ayıklama kolaylığı değildir. Agent davranışını kontrollü deneylere dönüştürür: aynı geçmiş bağlamı tutup tek bir state farkının downstream kararları nasıl etkilediğini gözlemlemeyi sağlar.

Yaygın Hatalar ve Kontroller

  • checkpoint_id vermeden replay beklemek: yalnızca thread verilirse current state hedeflenir.
  • Fork sırasında mesaj id alanını unutmak: MessagesState yeni mesaj append edebilir.
  • State update yaptıktan sonra run başlatmamak: fork checkpoint’i oluşur ama downstream sonuç üretilmez.
  • Replay ile re-execution’ı aynı sanmak: önceden execute edilmiş checkpoint replay edilir, yeni fork checkpoint’i execute edilir.
