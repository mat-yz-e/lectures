LangGraph’ta State Düzenleme ve İnsan Geri Bildirimi

Bu ders, breakpoint ile durdurulan bir LangGraph çalışmasında graph state’inin nasıl okunacağını, güncelleneceğini ve insan geri bildirimiyle kontrollü biçimde nasıl sürdürüleceğini açıklar.

Kapsam ve Bağlam

Bu bölümde amaç, breakpoint ile durdurulmuş bir graph çalışmasında state’i yalnızca incelemekle kalmayıp güvenli biçimde değiştirmektir. Önce assistant node’u çalışmadan önce durulur, ardından messages alanı güncellenir ve aynı checkpoint hattından devam edilir.

Ders, insan denetimli akışın üçüncü motivasyonuna odaklanır: editing. Onay akışında insan yalnızca “devam et” veya “dur” kararı verirken, editing akışında insan state’in belirli bir alanını değiştirerek graph’ın sonraki davranışını etkiler.

Bu Dersin Ana Tezi

Breakpoint, graph yürütmesini geçici olarak durdurduğu için state üzerinde denetlenebilir bir düzenleme penceresi açar. Bu pencere graph.update_state, client.threads.update_state ve gerektiğinde as_node parametresiyle uygulama katmanındaki insan geri bildirimiyle birleştirilebilir.

Öğrenme Hedefleri

  • interrupt_before=["assistant"] ayarının assistant node’u başlamadan önce graph’ı neden durdurduğunu açıklayabilecek.
  • graph.get_state(thread) çıktısındaki values, next, checkpoint ve task alanlarını yorumlayabilecek.
  • graph.update_state çağrısının messages reducer davranışıyla append veya overwrite sonucuna nasıl gittiğini ayırt edebilecek.
  • input=None kullanımının yeni mesaj değil, son checkpoint’ten devam talimatı olduğunu açıklayabilecek.
  • LangGraph SDK üzerinde thread state’ini okuyup son mesajı düzenleyerek API tabanlı state update uygulayabilecek.
  • as_node="human_feedback" parametresinin state update’i belirli bir node çalışmış gibi kaydetmedeki rolünü yorumlayabilecek.
  • Tool sonucu ile assistant’ın nihai doğal dil cevabı arasındaki farkı state akışı üzerinden gösterebilecek.

Ön Koşullar

  • Python fonksiyonları, dictionary/list yapıları, type hint ve temel async kullanımını okuyabilmek.
  • LLM mesajları, tool call, assistant message ve tool message kavramlarına giriş düzeyinde aşina olmak.
  • StateGraph, node, edge, conditional edge, checkpoint ve thread kavramlarını temel seviyede bilmek.
  • Ortam değişkeniyle API anahtarı okuma mantığını anlamak.
  • SDK örnekleri için yerel LangGraph API/Studio sürecinin çalışıyor olması gerektiğini bilmek.

Büyük Resim

State düzenleme, graph’ın çalışmasını dışarıdan keyfi olarak bozmak değildir. Graph belirli bir checkpoint üzerinde durur; uygulama mevcut state’i okur, kontrollü bir update uygular ve aynı thread üzerinden yürütmeyi sürdürür.

DurmaGraph assistant veya human feedback node’u başlamadan checkpoint üzerinde bekler.
Okuma`get_state` ile mevcut mesajlar ve sıradaki node incelenir.
Düzenleme`update_state` state kanalına yeni veya değiştirilmiş mesaj yazar.
Devam`input=None` aynı checkpoint hattından yürütmeyi ilerletir.
SonuçAssistant/tool döngüsü güncellenmiş state’e göre sonuç üretir.

Ana Anlatım

Breakpoint bir düzenleme penceresidir

Önceki onay akışlarında breakpoint, tool node’u çalışmadan önce “insan onayı” istemek için kullanılmıştı. Bu derste aynı mekanizma daha genel bir amaçla kullanılır: graph henüz sonraki node’u çalıştırmadan state’i değiştirmek.

Append ve overwrite ayrımı

messages kanalı add_messages reducer davranışına sahiptir. Yeni bir mesaj ID’siz eklenirse listeye append edilir; mevcut mesajın ID’si korunarak gönderilirse ilgili mesaj overwrite edilebilir. Bu ayrım state düzenlemenin beklenen sonucu için kritiktir.

SDK ve yerel graph aynı fikri paylaşır

Yerel Python graph’ında graph.update_state kullanılırken, API tarafında client.threads.update_state kullanılır. Yüzey farklıdır; ancak temel model aynıdır: thread state’i okunur, uygun payload hazırlanır, update uygulanır ve run input=None ile sürdürülür.

Human feedback node deseni

Dersin son bölümünde human_feedback adlı no-op node eklenir. Bu node’un amacı hesaplama yapmak değil, insan geri bildiriminin graph akışında açık bir temas noktası kazanmasıdır. as_node="human_feedback" ile update, bu node çalışmış gibi state’e yazılır.

from langchain_openai import ChatOpenAI

def multiply(a: int, b: int) -> int:
    """
    Multiply a and b.

    Args:
        a: first int
        b: second int
    """
    return a * b

# This will be a tool
def add(a: int, b: int) -> int:
    """
    Adds a and b.

    Args:
        a: first int
        b: second int
    """
    return a + b

def divide(a: int, b: int) -> float:
    """
    Divide a by b.

    Args:
        a: first int
        b: second int
    """
    return a / b

tools = [add, multiply, divide]
llm = ChatOpenAI(model="gpt-4o")
llm_with_tools = llm.bind_tools(tools)

llm.bind_tools(tools), assistant node’unun doğal dil cevabı yerine gerektiğinde tool call üretmesini sağlar.

Assistant öncesinde duran graph’ı kurma

Bu blok iki node’lu agent graph’ını kurar ve yürütmeyi assistant node’u başlamadan önce kesilecek şekilde derler.

Assistant öncesinde duran graph’ı kurma
from IPython.display import Image, display

from langgraph.checkpoint.memory import MemorySaver
from langgraph.graph import MessagesState
from langgraph.graph import START, StateGraph
from langgraph.prebuilt import ToolNode, tools_condition

from langchain_core.messages import HumanMessage, SystemMessage

# System message
sys_msg = SystemMessage(
    content=(
        "You are a helpful assistant tasked with performing arithmetic "
        "on a set of inputs."
    )
)

# Node
def assistant(state: MessagesState):
    """
    Run the assistant graph node.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    return {
        "messages": [
            llm_with_tools.invoke([sys_msg] + state["messages"])
        ]
    }

# Graph
builder = StateGraph(MessagesState)

# Define nodes: these do the work
builder.add_node("assistant", assistant)
builder.add_node("tools", ToolNode(tools))

# Define edges: these determine the control flow
builder.add_edge(START, "assistant")
builder.add_conditional_edges(
    "assistant",
    # If the latest message (result) from assistant is a tool call -> tools_condition routes to tools
    # If the latest message (result) from assistant is a not a tool call -> tools_condition routes to END
    tools_condition,
)
builder.add_edge("tools", "assistant")

memory = MemorySaver()
graph = builder.compile(interrupt_before=["assistant"], checkpointer=memory)

# Show
display(Image(graph.get_graph(xray=True).draw_mermaid_png()))

# System message
sys_msg = SystemMessage(
    content=(
        "You are a helpful assistant tasked with performing arithmetic "
        "on a set of inputs."
    )
)

# no-op node that should be interrupted on
def human_feedback(state: MessagesState):
    """
    Run the human_feedback helper.

    Args:
        state: Current graph state.
    """
    pass

# Assistant node
def assistant(state: MessagesState):
    """
    Run the assistant graph node.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    return {
        "messages": [
            llm_with_tools.invoke([sys_msg] + state["messages"])
        ]
    }

# Graph
builder = StateGraph(MessagesState)

# Define nodes: these do the work
builder.add_node("assistant", assistant)
builder.add_node("tools", ToolNode(tools))
builder.add_node("human_feedback", human_feedback)

# Define edges: these determine the control flow
builder.add_edge(START, "human_feedback")
builder.add_edge("human_feedback", "assistant")
builder.add_conditional_edges(
    "assistant",
    # If the latest message (result) from assistant is a tool call -> tools_condition routes to tools
    # If the latest message (result) from assistant is a not a tool call -> tools_condition routes to END
    tools_condition,
)
builder.add_edge("tools", "human_feedback")

memory = MemorySaver()
graph = builder.compile(interrupt_before=["human_feedback"], checkpointer=memory)
display(Image(graph.get_graph().draw_mermaid_png()))

Çıktıların Yorumlanması

Çıktılar üç ana kontrol noktası gösterir. İlk olarak, assistant öncesi breakpoint yalnızca insan mesajını görünür kılar. State’in Evrimi

1. İlk input`messages` alanında `HumanMessage(content="Multiply 2 and 3")` bulunur; `next` assistant node’unu gösterir.
2. Append updateID verilmeden yeni `HumanMessage` eklendiği için mesaj listesinde iki insan mesajı oluşur.
3. Devam çağrısıAssistant güncellenmiş mesajları okuyarak `multiply(a=3, b=3)` tool call’ını üretir.
4. Tool sonucuTool node’u `9` değerini tool mesajı olarak state’e yazar.
5. SDK overwriteMevcut mesaj ID’si korunduğu için mesaj içeriği append edilmeden güncellenir.
6. Human feedback update`as_node="human_feedback"`, insan düzeltmesini graph’ın açık geri bildirim noktasına bağlar.

Agent / Tool Etkileşimi

İlk kullanıcı isteğiMultiply 2 and 3
State düzenlemeNo, actually multiply 3 and 3!
Assistant tool call`multiply` aracı `a=3`, `b=3` argümanlarıyla çağrılmak üzere seçilir.
Tool sonucu`multiply` sonucu `9` olarak state’e eklenir.
Final cevapAssistant tool mesajını okuyarak doğal dil cevabını üretir.

Yaygın Hatalar

  • input=None değerini boş kullanıcı mesajı sanmak; gerçekte son checkpoint’ten devam talimatıdır.
  • update_state çağrısının her zaman mevcut mesajı ezdiğini düşünmek; mesaj ID’si yoksa append davranışı oluşabilir.
  • StateSnapshot çıktısını yalnızca debug metni zannetmek; bu çıktı devam ve düzenleme kararları için runtime bilgisidir.
  • interrupt_before ayarının node’u graph’tan kaldırdığını düşünmek; node yalnızca başlamadan önce durdurulur.
  • Tool call mesajını tool’un çalıştığı anla karıştırmak; tool sonucu ayrı bir tool message olarak state’e eklenir.
  • as_node kullanmadan insan geri bildiriminin graph’ta hangi semantik noktaya ait olduğunu belirsiz bırakmak.
  • SDK örneklerinde yerel API sunucusu çalışmadan thread/run çağrılarının çalışmasını beklemek.

Son Çıkarımlar

  • Breakpoint, state üzerinde kontrollü düzenleme yapabilmek için yürütmeyi güvenli bir noktada durdurur.
  • graph.get_state(thread), hem mevcut değerleri hem de graph’ın sıradaki node’unu gösterir.
  • graph.update_state, checkpoint hattına yeni bir state versiyonu yazar.
  • messages alanı reducer davranışı nedeniyle append veya overwrite edilebilir.
  • Aynı mesaj ID’sini korumak overwrite davranışı için kritik bir işarettir.
  • input=None, graph’ın yeni input almadan son checkpoint’ten devam etmesini sağlar.
  • SDK tarafında client.threads.get_state ve client.threads.update_state aynı state düzenleme fikrini API üzerinden uygular.
  • human_feedback gibi no-op node’lar insan girdisini graph akışında açık bir temas noktasına dönüştürür.
  • as_node, state update’in hangi node bağlamında yazılacağını belirler.
  • Tool sonucu nihai assistant cevabı değildir; assistant tool mesajını okuyarak final cevabı üretir.

graph = builder.compile(interrupt_before=["human_feedback"], checkpointer=memory)
display(Image(graph.get_graph().draw_mermaid_png()))

# Input
initial_input = {"messages": "Multiply 2 and 3"}

# Thread
thread = {"configurable": {"thread_id": "5"}}

# Run the graph until the first interruption
for event in graph.stream(initial_input, thread, stream_mode="values"):
    event["messages"][-1].pretty_print()

# Get user input
user_input = input("Tell me how you want to update the state: ")

# We now update the state as if we are the human_feedback node
graph.update_state(thread, {"messages": user_input}, as_node="human_feedback")

# Continue the graph execution
for event in graph.stream(None, thread, stream_mode="values"):
    event["messages"][-1].pretty_print()
