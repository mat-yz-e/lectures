LangGraph’ta Dinamik Breakpoint’ler ve NodeInterrupt

Bu ders, graph’ın kendi iç koşullarına göre yürütmeyi durdurmasını, durma nedenini state snapshot’ında okumayı ve state update ile güvenli biçimde devam etmeyi açıklar.

Kapsam ve Bağlam

Önceki bölümlerde breakpoint, geliştiricinin belirli node’ları derleme veya run aşamasında durdurması için kullanılmıştı. Bu derste odak değişir: graph, node içinde oluşan bir koşula göre kendisini durdurabilir.

Bu desen dinamik breakpoint olarak düşünülebilir. NodeInterrupt, node içinde fırlatılır; kesinti mesajı task kayıtlarına yazılır; uygulama state’i okuyup gerekirse update ederek aynı checkpoint hattından devam eder.

Bu Dersin Ana Tezi

Dinamik breakpoint, sabit bir durma noktası değil, state’e bağlı bir güvenlik ve kontrol mekanizmasıdır. Koşul değişmediği sürece resume aynı kesintiye döner; state güncellendiğinde graph ilerleyebilir.

Öğrenme Hedefleri

  • NodeInterrupt ile node içinden koşullu kesinti üretmeyi açıklayabilecek.
  • state.next ve state.tasks alanlarını kullanarak graph’ın nerede ve neden durduğunu yorumlayabilecek.
  • State değişmeden yapılan resume denemesinin neden aynı node’a döndüğünü açıklayabilecek.
  • graph.update_state ile interrupt koşulunu değiştiren state update uygulayabilecek.
  • LangGraph SDK üzerinde threads.get_state, threads.update_state ve runs.stream çağrılarını aynı kavramlarla eşleştirebilecek.

Ön Koşullar

  • Python sözlükleri, type hint, fonksiyon tanımı ve exception fırlatma mantığını okuyabilmek.
  • StateGraph, node, edge, checkpoint ve thread kavramlarını temel düzeyde bilmek.
  • Önceki breakpoint ve state update derslerinde kullanılan get_state, update_state ve input=None kalıplarını tanımak.
  • SDK bölümü için yerel LangGraph API/Studio sürecinin ayrıca çalıştırılması gerektiğini bilmek.

Ana Anlatım

Sabit breakpoint ile dinamik breakpoint farklıdır

Sabit breakpoint’te geliştirici önceden belirli node adlarını durma noktası olarak verir. Dinamik breakpoint’te ise node, kendi state okumasına göre durma kararı verir. Bu ayrım özellikle validasyon, güvenlik kontrolü, insan onayı ve düzeltme döngüleri için önemlidir.

Resume tek başına yeterli değildir

Graph aynı state ile devam ettirilirse aynı node aynı koşulu yeniden değerlendirir ve yine durur. Bu nedenle dinamik breakpoint’i geçmek için state’in interrupt koşulunu artık sağlamayacak biçimde güncellenmesi gerekir.

SDK yüzeyi aynı modeli taşır

Yerel Python graph’ındaki graph.get_state ve graph.update_state çağrıları, API tarafında client.threads.get_state ve client.threads.update_state çağrılarıyla aynı kavrama karşılık gelir. Fark yalnızca çalıştırma yüzeyidir.

Koşullu interrupt üreten graph’ı kurma

Graph üç adımdan oluşur. İkinci adım, input uzunluğu beş karakteri aşarsa NodeInterrupt fırlatır.

Koşullu interrupt üreten graph’ı kurma
from IPython.display import Image, display

from typing_extensions import TypedDict
from langgraph.checkpoint.memory import MemorySaver
from langgraph.errors import NodeInterrupt
from langgraph.graph import START, END, StateGraph

class State(TypedDict):
    """
    Define the state schema used by the graph.
    """
    input: str

def step_1(state: State) -> State:
    """
    Run the step_1 helper.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    print("---Step 1---")
    return state

def step_2(state: State) -> State:
    """
    Run the step_2 helper.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    # Raise a NodeInterrupt if the input is longer than 5 characters.
    if len(state["input"]) > 5:
        raise NodeInterrupt(
            f"Received input that is longer than 5 characters: {state['input']}"
        )

    print("---Step 2---")
    return state

def step_3(state: State) -> State:
    """
    Run the step_3 helper.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    print("---Step 3---")
    return state

builder = StateGraph(State)
builder.add_node("step_1", step_1)
builder.add_node("step_2", step_2)
builder.add_node("step_3", step_3)
builder.add_edge(START, "step_1")
builder.add_edge("step_1", "step_2")
builder.add_edge("step_2", "step_3")
builder.add_edge("step_3", END)

memory = MemorySaver()
graph = builder.compile(checkpointer=memory)

display(Image(graph.get_graph().draw_mermaid_png()))

  • Dinamik breakpoint, node içindeki koşullu mantıkla oluşur.

  • State değişmeden resume edilirse graph aynı koşula yeniden takılır.
  • update_state, interrupt koşulunu ortadan kaldıracak yeni state’i checkpoint hattına yazar.
  • input=None, yeni input değil, son checkpoint’ten devam komutudur.
  • SDK tarafındaki thread ve run işlemleri yerel graph davranışıyla aynı state modeline dayanır.
