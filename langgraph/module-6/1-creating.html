LangGraph Platform Deployment: Docker Image ve Servis Bileşenleri

Bu ders, LangGraph tabanlı bir uygulamanın deployment için hangi dosya yapısına ihtiyaç duyduğunu, CLI ile Docker image üretimini ve Redis/PostgreSQL destekli yerel çalışma düzenini akademik bir akış içinde açıklar.

Kapsam ve Bağlam

Bu bölümde amaç, LangGraph ile geliştirilmiş bir uygulamanın yerel veya kendi altyapısında çalıştırılabilecek bir deployment biçimine nasıl hazırlandığını anlamaktır. Odak, graph kodunu yeniden yazmak değil; graph’ı, bağımlılıklarını, yapılandırma dosyasını ve çalışma zamanı servislerini birlikte paketleyebilecek doğru deployment zihinsel modelini kurmaktır.

Bu Dersin Ana Tezi

LangGraph deployment, yalnızca bir Python dosyasını çalıştırmak değildir. Graph tanımı, API yapılandırması, bağımlılıklar, ortam değişkenleri, Docker image, Redis ve PostgreSQL birlikte ele alındığında uygulama LangGraph Server tarafından yönetilebilir bir servis haline gelir.

Ders, önce deployment için gereken dosya yapısını tanımlar; ardından LangGraph CLI ile Docker image oluşturmayı ve bu image’ın Redis/PostgreSQL destekli bir yerel deployment içinde nasıl ayağa kaldırılacağını açıklar.

Öğrenme Hedefleri

  • LangGraph Platform deployment için gereken temel dosya bileşenlerini açıklayabilecek.
  • langgraph.json yapılandırmasının graph’ı API tarafından bulunabilir hale getirmedeki rolünü yorumlayabilecek.
  • langgraph build -t my-image komutunun graph kodunu ve bağımlılıkları Docker image içine paketlediğini açıklayabilecek.
  • Tek container çalıştırma ile docker compose up yaklaşımı arasındaki farkı ayırt edebilecek.
  • Redis ve PostgreSQL servislerinin LangGraph Server deployment bağlamında neden gerekli olduğunu kavrayabilecek.
  • API anahtarlarının ve servis URI’larının kaynak koda yazılmak yerine ortam değişkenleriyle verilmesi gerektiğini açıklayabilecek.

Ön Koşullar

  • Python projesinde bağımlılık dosyası, modül dosyası ve ortam değişkeni kavramlarına aşinalık.
  • LangGraph graph’ının bir Python dosyasında tanımlanıp derlenmiş bir graph nesnesi olarak dışa açılabileceğini bilmek.
  • Docker image ile Docker container arasındaki temel farkı ayırt edebilmek.
  • Komut satırında dizin değiştirme, paket kurma ve servis başlatma komutlarını okuyabilmek.
  • Redis ve PostgreSQL’in, LangGraph Server deployment mimarisinde çalışma zamanı iletişimi ve kalıcı veri/metadata için kullanılan servisler olduğunu kavramaya hazır olmak.

Büyük Resim

LangGraph uygulaması geliştirme aşamasında çoğu zaman notebook, yerel script veya Studio üzerinden denenir. Deployment aşamasında ise aynı uygulamanın bir API sunucusu tarafından yüklenmesi, bağımlılıklarıyla birlikte paketlenmesi ve destek servisleriyle çalışması gerekir. Bu nedenle deployment akışı üç ana soruya cevap verir: graph nerede tanımlı, hangi paketlerle çalışır ve hangi servislerle birlikte ayağa kalkar?

Graph kodu ile deployment sınırı

Bu derste graph’ın node/edge topolojisi yeniden inşa edilmez. Var olan graph, LangGraph Server tarafından çalıştırılabilir bir servis olarak paketlenir. Dolayısıyla odak graph davranışından çok deployment sözleşmesidir.

Ana Anlatım

Deployment dosya yapısı

LangGraph Platform deployment için uygulamanın yalnızca graph kodunu içermesi yeterli değildir. API yapılandırma dosyası graph’ın hangi isimle servis edileceğini belirtir; Python modülü graph mantığını taşır; bağımlılık dosyası container içinde hangi paketlerin kurulacağını tanımlar; ortam değişkenleri ise gizli değerleri ve servis bağlantılarını koddan ayırır.

Deployment sözleşmesi

Deployment sözleşmesi, LangGraph Server’ın graph’ı bulabilmesi, yükleyebilmesi ve dışarıdan API aracılığıyla çalıştırabilmesi için gereken yapısal bilgidir. Bu sözleşme doğru kurulmadığında graph kodu doğru olsa bile server graph’ı servis edemez.

Docker image neden kullanılır?

Docker image, uygulamayı çalıştırmak için gereken kodu, paketleri ve çalışma zamanı ortamını taşınabilir bir şablona dönüştürür. LangGraph CLI bu image’ı üretirken graph kodunu ve bağımlılıkları LangGraph Server ile birlikte paketler. Böylece deployment, geliştiricinin yerel Python ortamına bağımlı kalmaz.

Redis ve PostgreSQL’in yeri

LangGraph Server tek başına yalnızca graph kodunu barındıran bir süreç gibi düşünülmemelidir. Deployment mimarisinde Redis ve PostgreSQL gibi servisler, server’ın çalışma zamanı koordinasyonu ve kalıcı veri gereksinimlerini karşılar. Hazır Compose örneği bu yüzden üç container’lı bir düzen kurar: server, Redis ve PostgreSQL.

Kritik ayrım

langgraph build deployment’ı başlatmaz; yalnızca çalıştırılabilir image üretir. Deployment’ın ayağa kalkması için image’ın bir container olarak başlatılması ve gerekli servislerle bağlanması gerekir.

Kod Yürüyüşü

LangGraph CLI kurulumunu hazırlama

İlk çalıştırılabilir blok, notebook ortamında LangGraph CLI paketini kurar. Komutun sessiz çalıştırılması, ders akışında kurulum çıktılarının görünmesini engeller.

LangGraph CLI kurulumu 
%%capture --no-stderr
%pip install -U langgraph-cli

LangGraph açısından önemi

langgraph-cli, deployment image üretimi için gereken langgraph build komutunu sağlar.

Dikkat edilmesi gereken nokta

Bu kurulum satırı Jupyter ortamına özgüdür; gerçek projelerde bağımlılık yönetimi genellikle proje dosyaları ve sabitlenmiş sürümler üzerinden yapılır.

Çıktı Yorumu

Bu blokta anlamlı bir çıktı gösterilmez; kurulum çıktısı özellikle bastırılır. Ders açısından önemli sonuç, CLI komutlarının kullanılabilir hale gelmesidir.

LangGraph Server için Docker image oluşturma

Deployment akışının ilk operasyonel adımı, graph uygulamasını Docker image içine paketlemektir. Komut, deployment klasöründe çalıştırılır ve image’a my-image etiketi verilir.

Docker image build 
$ cd module-6/deployment
$ langgraph build -t my-image

LangGraph açısından önemi

langgraph build -t my-image, graph kodunu, bağımlılıkları ve LangGraph Server çalışma zamanını container üretilebilir bir image altında toplar.

Dikkat edilmesi gereken nokta

my-image yalnızca örnek bir image etiketidir. Daha sonra Docker veya Compose komutlarında aynı adın kullanılması gerekir.

Çıktı Yorumu

Bu derste build log’u gösterilmez. Öğrencinin izlemesi gereken ana fikir, build komutunun image ürettiği; ancak server, Redis ve PostgreSQL servislerini henüz çalıştırmadığıdır.

Redis ve PostgreSQL hazırsa tek server container çalıştırma

Redis ve PostgreSQL zaten çalışan servislerse, yalnızca LangGraph Server container’ı başlatılabilir. Bu durumda server container’a Redis ve veritabanı URI bilgileri ortam değişkenleriyle verilir.

Tek container çalıştırma 
docker run \
    --env-file .env \
    -p 8123:8000 \
    -e REDIS_URI="foo" \
    -e DATABASE_URI="bar" \
    -e LANGSMITH_API_KEY="baz" \
    my-image

LangGraph açısından önemi

REDIS_URI ve DATABASE_URI, server container’ın dış servislerle nasıl iletişim kuracağını belirler.

Dikkat edilmesi gereken nokta

Komuttaki değerler pedagojik placeholder niteliğindedir. Gerçek anahtarlar ve bağlantı bilgileri kaynak koda yazılmamalı, güvenli ortam yapılandırmasıyla verilmelidir.

Çıktı Yorumu

Bu yaklaşımda LangGraph Server tek container olarak başlar; destek servislerinin ayrı yerde hazır olduğu varsayılır. Bu yüzden compose tabanlı üç servisli akıştan daha fazla dış yapılandırma sorumluluğu taşır.

Docker Compose ile deployment’ı ayağa kaldırma

Destek servisleri hazır değilse, örnek Compose dosyası üzerinden server, Redis ve PostgreSQL container’ları birlikte başlatılır. Bu dosyada image adı ve gerekli API anahtarları sağlanır.

Docker Compose ile başlatma 
$ cd module-6/deployment
$ docker compose up

LangGraph açısından önemi

docker compose up, Compose dosyasında tanımlı birden fazla servisi birlikte başlatır ve yerel deployment düzenini ayağa kaldırır.

Dikkat edilmesi gereken nokta

Compose dosyasında IMAGE_NAME, LANGSMITH_API_KEY ve OPENAI_API_KEY gibi değerler doğru verilmelidir; aksi halde server image bulamayabilir veya model/izleme servislerine erişemeyebilir.

Çıktı Yorumu

Bu komutla deployment üç ana container üzerinden çalışır: LangGraph Server, Redis ve PostgreSQL. Dersin sonraki aşamalarında bu deployment ile API üzerinden etkileşim kurulabilir.

Çıktıların Yorumlanması

Bu derste doğrudan saklanmış bir çalışma çıktısı yer almaz; bunun yerine çalıştırılması beklenen komutlar ve bu komutların deployment sürecindeki anlamı incelenir. Bu nedenle yorumlama, terminal log’unu satır satır okumaktan çok hangi komutun hangi deployment aşamasını temsil ettiğini ayırt etmeye dayanır.

Kurulum bloğuCLI kurulumu sessiz çalışır; anlamlı çıktı yerine komut kullanılabilirliği hedeflenir.

Log okumada odak noktası

Gerçek çalıştırmada build veya compose log’ları uzun olabilir. Öğrenci özellikle image adının doğru üretilip üretilmediğine, environment variable eksiklerine, port bağlama hatalarına ve Redis/PostgreSQL bağlantı problemlerine bakmalıdır.

Graph Akışı

Bu derste graph’ın iç node/edge akışı kurulmaz. Var olan graph, deployment server tarafından yüklenebilir bir uygulama bileşeni olarak ele alınır. Bu nedenle gerçek akış, graph topolojisinden çok deployment yaşam döngüsüdür.

Graph tanımıUygulama graph’ı Python modülünde bulunur.
API yapılandırmasılanggraph.json graph adını ve entrypoint’i bildirir.
Image üretimiCLI graph’ı server image’ına paketler.
Servis başlatmaServer destek servisleriyle birlikte ayağa kalkar.
API erişimiSonraki adımda deployment dış istemciler tarafından kullanılabilir.

State’in Evrimi

Bu bölümde LangGraph runtime state’i üzerinde get_state, update_state veya checkpoint düzenleme işlemi yapılmaz. Bunun yerine deployment açısından “state” kavramı, uygulamanın çalışma biçiminin hangi aşamada olduğuna dair operasyonel bir durumu ifade eder.

Kod yapısı hazırGraph kodu, API yapılandırması ve bağımlılık listesi deployment sözleşmesini oluşturur.
Image hazırBuild tamamlandığında uygulama taşınabilir bir Docker image olarak temsil edilir.
Servisler bağlıRedis, PostgreSQL ve server container’ı aynı çalışma düzeninde buluşur.
Deployment çalışıyorServer artık graph’ı API üzerinden çalıştırabilecek bir runtime sağlar.

LangGraph’ın uygulama state’i, graph çalıştırmaları sırasında ayrı bir kavram olarak kalır. Bu ders o state’in içeriğini değiştirmez; state’i taşıyacak server ortamının nasıl oluşturulduğunu açıklar.

Agent / Tool Etkileşimi

Bu derste yeni bir agent-tool döngüsü kurulmaz ve tool call çıktısı üretilmez. Arka planda deployment’a konu olan uygulama agentic bir graph içerebilir; ancak bu bölümün öğretim odağı agent kararları değil, o uygulamanın LangGraph Server üzerinde çalıştırılabilir hale getirilmesidir.

GeliştiriciGraph kodunu, bağımlılıkları ve yapılandırmayı hazırlar.
LangGraph CLIBu yapıyı Docker image haline getirir.
Docker / ComposeImage ve destek servislerini container olarak çalıştırır.

Bu ayrım önemlidir: deployment süreci tool call semantiğini değiştirmez; yalnızca agent uygulamasının nerede ve hangi servislerle çalışacağını belirler.

Yaygın Hatalar

  • langgraph build komutunu deployment’ı başlatan komut sanmak.
  • langgraph.json dosyasını yalnızca Studio’ya özgü bir dosya gibi düşünmek.
  • Graph entrypoint adını yanlış verip server’ın graph’ı yükleyememesine neden olmak.
  • Bağımlılıkları yerel ortamda kurulu olduğu için Docker image içinde de var sanmak.
  • API anahtarlarını doğrudan kaynak koda yazmak.
  • Redis ve PostgreSQL servislerini başlatmadan yalnızca server container’ını çalıştırmaya çalışmak.
  • Compose dosyasında image adını build sırasında kullanılan etiketle eşleştirmemek.
  • Port eşlemesini karıştırıp server’ın dışarıdan erişilemediğini sanmak.
  • .env dosyasını güvenli yapılandırma aracı yerine ders içeriğinin parçası gibi yayımlamak.
  • Yerel deployment ile production güvenlik, secret yönetimi ve ağ yapılandırmasını aynı düzeyde kabul etmek.

Son Çıkarımlar

  • LangGraph deployment, graph kodu ile runtime servisleri arasındaki sözleşmeyi kurar.
  • langgraph.json graph’ın API tarafından bulunabilir olmasını sağlar.
  • Docker image, graph kodunu ve bağımlılıkları taşınabilir bir çalışma zamanı şablonuna dönüştürür.
  • langgraph build -t my-image image üretir; container çalıştırmaz.
  • Tek server container yaklaşımı, Redis ve PostgreSQL’in zaten hazır olduğu durumlar için uygundur.
  • Docker Compose, server, Redis ve PostgreSQL’i birlikte başlatmak için daha bütünlüklü bir yerel akış sağlar.
  • API anahtarları ve servis URI’ları kaynak koda değil, ortam yapılandırmasına verilmelidir.
  • Build log’u başarıyı, compose log’u ise servislerin birlikte ayağa kalkıp kalkmadığını doğrulamak için okunur.
  • Bu ders graph state’ini düzenlemez; graph’ı barındıracak deployment kabuğunu oluşturur.
  • Deployment başarıyla çalıştığında sonraki adım, çalışan server ile API üzerinden etkileşim kurmaktır.

Dersin Kod Akışı

Aşağıdaki blok, derste kullanılan çalıştırılabilir komutları tek akış halinde toplar. Komutlar deployment aşamalarının sırasını gösterir; gerçek ortamda gizli değerler ve servis URI’ları güvenli biçimde verilmelidir.

Dersin Kod Akışı 
%%capture --no-stderr
%pip install -U langgraph-cli

# Build Docker image for the LangGraph Server
$ cd module-6/deployment
$ langgraph build -t my-image

# Run only the LangGraph Server container when Redis and PostgreSQL already exist
docker run \
    --env-file .env \
    -p 8123:8000 \
    -e REDIS_URI="foo" \
    -e DATABASE_URI="bar" \
    -e LANGSMITH_API_KEY="baz" \
    my-image

# Launch the local deployment with Docker Compose
$ cd module-6/deployment
$ docker compose up
