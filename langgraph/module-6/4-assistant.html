LangGraph Platform’da Assistant Sürümleri ve Konfigürasyon Yönetimi

Bu ders, aynı deployed graph üzerinde farklı assistant davranışları oluşturmayı, konfigürasyon alanlarını sürümlemeyi ve SDK ile assistant yaşam döngüsünü yönetmeyi açıklar.

Kapsam ve Bağlam

Bu bölümde amaç, LangGraph Platform üzerinde yayınlanmış bir graph için birden fazla assistant davranışı tanımlamaktır. Aynı task_maistro graph’ı korunur; buna karşılık todo_category, user_id ve task_maistro_role gibi yapılandırılabilir alanlar assistant seviyesinde farklılaştırılır.

Bu Dersin Ana Tezi

Assistant, deployed graph’ın kendisi değildir; graph üzerinde varsayılan konfigürasyon, sürüm ve davranış politikası taşıyan yönetilebilir bir çalışma profilidir.

Öğrenme Hedefleri

  • Bir deployed graph için assistant kaydı oluşturmanın graph çalıştırmaktan nasıl ayrıldığını açıklayabilecek.
  • config.configurable alanının davranışı nasıl etkilediğini yorumlayabilecek.
  • client.assistants.create, update, search ve delete çağrılarını ayırt edebilecek.
  • assistant_id ile run başlatıldığında hangi assistant varsayılanlarının kullanıldığını takip edebilecek.
  • stream_mode="values" çıktılarında insan mesajı, tool çağrısı, tool mesajı ve final cevabı ayırabilecek.

Ön Koşullar

Python sözlükleri, listeler, asenkron await kullanımı, mesaj temelli LLM etkileşimi ve deployment kavramı temel düzeyde bilinmelidir. Bu derste graph’ın daha önce deploy edilmiş olduğu ve SDK istemcisinin bu deployment ile konuştuğu kabul edilir.

Kritik Ayrım

Bu derste yeni bir StateGraph kurulmaz. Odak, daha önce deploy edilmiş graph’ın assistant API ile farklı varsayılanlara bağlanmasıdır.

Ana Anlatım

LangGraph Platform’daki assistant yapısı, agent uygulamasını tek bir sabit prompt veya tek bir bellek alanıyla sınırlamaz. Deployed graph aynı kalırken farklı görev kategorileri ve davranış politikaları assistant konfigürasyonu üzerinden tanımlanabilir.

Assistant Sürümleme Mantığı

Bir assistant oluşturulduğunda platform bir assistant_id, graph_id, konfigürasyon ve sürüm bilgisi döndürür. Güncelleme yapıldığında aynı assistant kimliği yeni bir konfigürasyonla sürümlenir.

Personal ve Work Ayrımı

Kişisel assistant daha destekleyici bir rol metni kullanır. Work assistant deadline ve süre tahmini konusunda daha katı davranacak şekilde yapılandırılır.

task_maistro_role = """You are a friendly and organized personal task assistant. Your main focus is helping users stay on top of their personal tasks and commitments. Specifically:

- Help track and organize personal tasks
- When providing a 'todo summary':
  1. List all current tasks grouped by deadline (overdue, today, this week, future)
  2. Highlight any tasks missing deadlines and gently encourage adding them
  3. Note any tasks that seem important but lack time estimates
- Proactively ask for deadlines when new tasks are added without them
- Maintain a supportive tone while helping the user stay accountable
- Help prioritize tasks based on deadlines and importance

Your communication style should be encouraging and helpful, never judgmental.

When tasks are missing deadlines, respond with something like "I notice [task] doesn't have a deadline yet. Would you like to add one to help us track it better?"""

    "user_id": "lance",

}

Work assistant ile tarihli görevler oluşturma
from langchain_core.messages import HumanMessage
from langchain_core.messages import convert_to_messages

user_input = "Create or update few ToDos: 1) Re-film Module 6, lesson 5 by end of day today. 2) Update audioUX by next Monday."
thread = await client.threads.create()
async for chunk in client.runs.stream(
    thread["thread_id"],
    work_assistant_id,
    input={"messages": [HumanMessage(content=user_input)]},
    stream_mode="values",
):

    if chunk.event == 'values':
        state = chunk.data
        convert_to_messages(state["messages"])[-1].pretty_print()

Çıktı Yorumu

Çıktıda assistant kaydı, konfigürasyon, tool çağrısı veya mesaj akışı okunur; yorumda özellikle kimlik, sürüm ve mesaj türlerine dikkat edilmelidir.

Çıktıların Yorumlanması

Assistant oluşturma ve güncelleme çıktılarında assistant_id, graph_id, version ve config.configurable alanlarına bakılır. Run çıktılarında ise insan mesajı, modelin tool çağrısı, tool mesajı ve final assistant cevabı ayrı ayrı okunmalıdır.

Uzun Çıktı Okuma Rehberi

Uzun dict çıktılarında konfigürasyon alanlarına; uzun mesaj çıktılarında ise Tool Calls, Tool Message ve final assistant metni ayrımına odaklanmak gerekir.

Graph Akışı

Graph node ve edge tanımı burada yeniden kurulmaz; yürütme deployment içindeki task_maistro graph’ı üzerinden yapılır.

Kullanıcı mesajıHumanMessage ile thread’e verilir.
Assistant configSeçilen kimlik varsayılan rol ve kategori sağlar.
Graph runDeployment üzerinde streaming yürütme başlar.
Tool işlemiGörev belleği okunur, oluşturulur veya güncellenir.
Final cevapAssistant sonucu kullanıcıya döndürür.

State’in Evrimi

State iki seviyede düşünülmelidir: assistant kaydının konfigürasyon state’i ve run sırasında stream edilen mesaj state’i.

Assistant oluşturmaPersonal assistant önce yalnızca todo_category="personal" ile oluşturulur.
Assistant güncellemeuser_id, todo_category ve task_maistro_role yeni sürüm konfigürasyonu olur.
Run başlangıcıThread oluşturulur, kullanıcı mesajı assistant kimliğiyle graph’a verilir.
Mesaj listesivalues çıktısında insan mesajı, AI tool call, tool mesajı ve final AI cevabı görünür.

Agent / Tool Etkileşimi

Bu derste agent-tool döngüsü çıktı üzerinden gözlemlenir. Model bazı görevlerde UpdateMemory tool çağrısı üretir; tool mesajı belleğin nasıl değiştiğini bildirir; assistant sonrasında kullanıcıya özetlenmiş cevap verir.

KullanıcıGörev ekleme veya özet isteme mesajı gönderir.
AssistantGerekirse UpdateMemory tool çağrısını oluşturur.
ToolToDo kaydını oluşturur, günceller veya değişiklik gerekmediğini bildirir.
AssistantTool sonucunu okunabilir yanıt olarak döndürür.

Yaygın Hatalar

  • Assistant kaydını graph’ın kendisi sanmak.
  • graph_id ile assistant_id değerlerini aynı amaçla kullanmak.
  • configurable alanlarını yalnızca metadata zannetmek.
  • task_maistro_role değiştiğinde graph kodunun da değiştiğini varsaymak.
  • Tool mesajını final assistant cevabı gibi yorumlamak.
  • stream_mode="values" çıktısını token streaming ile karıştırmak.
  • Thread sürekliliğini kullanmadan takip mesajı bağlamının korunacağını varsaymak.

Son Çıkarımlar

  1. Assistant, deployed graph üzerinde varsayılan konfigürasyon taşıyan yönetim katmanıdır.
  2. Aynı graph farklı assistant kayıtlarıyla farklı davranabilir.
  3. todo_category bellek ayrımı için pratik bir namespace anahtarıdır.
  4. task_maistro_role assistantın kullanıcıya nasıl yaklaşacağını değiştirir.
  5. update davranış sürümleme aracıdır.
  6. Run başlatırken assistant kimliği ilgili konfigürasyonu yürütmeye taşır.
  7. values modu graph state ve mesaj evrimini okumak için uygundur.
  8. Tool çağrısı ile final assistant cevabı farklı aşamalardır.
  9. Thread devamlılığı takip mesajlarının önceki niyetle bağlanmasını sağlar.
  10. SDK, assistant yaşam döngüsünü programatik olarak yönetilebilir kılar.
