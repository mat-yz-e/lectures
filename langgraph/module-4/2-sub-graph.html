LangGraph’ta Alt Graph Mimarisi: State Paylaşımı ve Kapsüllenmiş Akışlar

Bu ders, parent graph ile alt graph’ların ortak state anahtarları üzerinden nasıl iletişim kurduğunu, output schema kullanımının neden kritik olduğunu ve paralel sub-graph akışlarında reducer tasarımının ne zaman gerekli hale geldiğini açıklar.

Kapsam ve Bağlam

Bu bölümde amaç, LangGraph içinde büyük bir iş akışını tek parça graph olarak büyütmek yerine, anlamlı alt graph’lara ayırarak yönetmektir. Örnek senaryoda sistem logları alır; bir alt graph başarısızlık örüntülerini çıkarır, diğer alt graph soru içeriklerini özetler. Parent graph ise bu iki çalışmayı aynı yürütme içinde birleştirir.

Bu Dersin Ana Tezi

Alt graph iletişimi sihirli bir global paylaşım üzerinden değil, parent graph ve sub-graph state şemalarında ortak bulunan anahtarlar üzerinden gerçekleşir. Hangi alanların dışarı yayımlanacağını output_schema ile sınırlandırmak, paralel graph tasarımını daha güvenli ve okunabilir hale getirir.

Öğrenme Hedefleri

  • StateGraph ile parent graph ve alt graph state şemalarını ayırabilecek.
  • Overlapping key ilkesinin parent-subgraph iletişimindeki rolünü açıklayabilecek.
  • output_schema kullanarak alt graph’ın dışarı yayımladığı alanları sınırlandırabilecek.
  • Paralel alt graph’lar aynı state alanına yazdığında neden reducer gerektiğini yorumlayabilecek.
  • xray graph görselinin nested graph yapısını okumadaki değerini açıklayabilecek.

Ön Koşullar

Bu dersi izleyebilmek için Python fonksiyonları, dictionary/list yapıları, class tanımı ve type hint kullanımına aşinalık gerekir. TypedDict, Optional, List ve Annotated gibi tip araçları state sözleşmesini açık hale getirir. LangGraph tarafında ise node, edge, START, END, compile ve invoke kavramlarının temel anlamı bilinmelidir.

API anahtarı ve ortam değişkeni mantığı da önemlidir; çünkü izleme ayarları kod içine gizli değer yazmadan yapılır. Bu derste tam bir LLM agent-tool döngüsü kurulmaz; odak state paylaşımı, sub-graph kapsülleme ve trace okunabilirliğidir.

Büyük Resim

Alt graph, parent graph içinde tek node gibi kullanılabilen ama kendi iç state’i, node’ları ve edge’leri olan kapsüllenmiş bir graph parçasıdır. Bu yapı özellikle çok ajanlı sistemlerde değerlidir: her ekip ya da alt görev kendi state ayrıntılarını yönetirken parent graph yalnızca ortak giriş ve sonuç alanlarını taşır.

State yalnızca local değişken değildir

State, graph yürütmesi boyunca node’lar arasında taşınan sözleşmedir. Parent graph ve sub-graph aynı anahtar adını paylaştığında veri aktarımı bu sözleşme üzerinden gerçekleşir.

Ana Anlatım

Bir parent graph’ın alt graph’la iletişim kurması için iki tarafın state şemalarında ortak anahtarların bulunması gerekir. Örnekte cleaned_logs, parent graph tarafından üretilir ve her iki alt graph tarafından okunur. Bu alan alt graph’lar için girdidir; parent graph’a geri döndürülmesi gerekmez.

Alt graph’ın parent graph’a döndürmesi gereken alanlar ise işin sonucunu temsil eder. Failure analysis akışı fa_summary ve processed_logs üretir. Question summarization akışı report ve processed_logs üretir. Bu nedenle processed_logs iki paralel alt graph’tan geldiği için reducer ile birleştirilir.

İç stateAlt graph’ın kendi ara hesaplarını tutar.
Ortak girişParent ile alt graph arasında aynı adla bulunur.
Yayımlanan çıktıoutput_schema içinde seçilen alanlardır.

Log sözleşmesini kurma

Parent graph ve alt graph’lar aynı kayıt nesnesini okuyacağı için log yapısı açık bir TypedDict sözleşmesiyle ifade edilir.

Log sözleşmesini kurma
from operator import add
from typing_extensions import TypedDict
from typing import List, Optional, Annotated

# The structure of the logs
class Log(TypedDict):
    """
    Define the Log data model.
    """
    id: str
    question: str
    docs: Optional[List]
    answer: str
    grade: Optional[int]
    grader: Optional[str]
    feedback: Optional[str]

LangGraph açısından önemi

Log, parent graph’tan alt graph’lara taşınan verinin biçimini netleştirir; overlapping key mantığı bu tür ortak sözleşmelere dayanır.

Dikkat edilmesi gereken nokta

Bazı alanlar örnek loglarda bulunmayabilir. Node fonksiyonları bu nedenle alanın varlığını kontrol ederek davranmalıdır.

Failure analysis alt graph’ı

İlk alt graph, temizlenmiş logları alır, başarısızlık sinyali taşıyan kayıtları ayıklar ve yalnızca parent graph’ın ihtiyaç duyduğu alanları dışarı verir.

Failure analysis alt graph’ı
from IPython.display import Image, display
from langgraph.graph import StateGraph, START, END

# Failure Analysis Sub-graph
class FailureAnalysisState(TypedDict):
    """
    Define the state schema used by the graph.
    """
    cleaned_logs: List[Log]
    failures: List[Log]
    fa_summary: str
    processed_logs: List[str]

class FailureAnalysisOutputState(TypedDict):
    """
    Define the state schema used by the graph.
    """
    fa_summary: str
    processed_logs: List[str]

def get_failures(state):
    """ Get logs that contain a failure """
    cleaned_logs = state["cleaned_logs"]
    failures = [log for log in cleaned_logs if "grade" in log]
    return {"failures": failures}

def generate_summary(state):
    """ Generate summary of failures """
    failures = state["failures"]
    # Add fxn: fa_summary = summarize(failures)
    fa_summary = "Poor quality retrieval of Chroma documentation."
    return {
        "fa_summary": fa_summary,
        "processed_logs": [
            f"failure-analysis-on-log-{failure['id']}"
            for failure in failures
        ],
    }

fa_builder = StateGraph(
    state_schema=FailureAnalysisState,
    output_schema=FailureAnalysisOutputState,
)
fa_builder.add_node("get_failures", get_failures)
fa_builder.add_node("generate_summary", generate_summary)
fa_builder.add_edge(START, "get_failures")
fa_builder.add_edge("get_failures", "generate_summary")
fa_builder.add_edge("generate_summary", END)

graph = fa_builder.compile()
display(Image(graph.get_graph().draw_mermaid_png()))

Question summarization alt graph’ı

İkinci alt graph aynı cleaned_logs girdisini kullanır, soru odaklı bir özet üretir ve temsilî bir rapor alanı döndürür.

Question summarization alt graph’ı
# Summarization subgraph
class QuestionSummarizationState(TypedDict):
    """
    Define the state schema used by the graph.
    """
    cleaned_logs: List[Log]
    qs_summary: str
    report: str
    processed_logs: List[str]

class QuestionSummarizationOutputState(TypedDict):
    """
    Define the state schema used by the graph.
    """
    report: str
    processed_logs: List[str]

def generate_summary(state):
    """
    Run the generate_summary helper.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    cleaned_logs = state["cleaned_logs"]
    # Add fxn: summary = summarize(generate_summary)
    summary = "Questions focused on usage of ChatOllama and Chroma vector store."
    return {
        "qs_summary": summary,
        "processed_logs": [
            f"summary-on-log-{log['id']}"
            for log in cleaned_logs
        ],
    }

def send_to_slack(state):
    """
    Run the send_to_slack helper.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    qs_summary = state["qs_summary"]
    # Add fxn: report = report_generation(qs_summary)
    report = "foo bar baz"
    return {"report": report}

qs_builder = StateGraph(
    QuestionSummarizationState,
    output_schema=QuestionSummarizationOutputState,
)
qs_builder.add_node("generate_summary", generate_summary)
qs_builder.add_node("send_to_slack", send_to_slack)
qs_builder.add_edge(START, "generate_summary")
qs_builder.add_edge("generate_summary", "send_to_slack")
qs_builder.add_edge("send_to_slack", END)

graph = qs_builder.compile()
display(Image(graph.get_graph().draw_mermaid_png()))

Parent state için reducer ihtimalini tartışma

Bu ara tanım, paralel alt graph’ların aynı anahtarı geri döndürmesi halinde reducer ihtiyacının nasıl ortaya çıkacağını görünür kılar.

Parent state için reducer ihtimalini tartışma
# Entry Graph
class EntryGraphState(TypedDict):
    """
    Define the state schema used by the graph.
    """
    raw_logs: List[Log]
    cleaned_logs: Annotated[List[Log], add] # This will be USED BY in BOTH sub-graphs
    fa_summary: str # This will only be generated in the FA sub-graph
    report: str # This will only be generated in the QS sub-graph
    processed_logs:  Annotated[List[int], add] # This will be generated in BOTH sub-graphs

LangGraph açısından önemi

Parent graph, alt graph’lardan dönen alanları aynı state sözleşmesinde toplar; birden fazla dal aynı anahtara yazarsa reducer gerekir.

Dikkat edilmesi gereken nokta

cleaned_logs yalnızca girdi olarak kullanılsa bile alt graph tüm state’i dışarı verirse çakışabilir. Bu dersin çözümü, bu alanı reducer ile taşımak değil output schema ile dışarı vermemektir.

Parent graph’a alt graph’ları bağlama

Son parent graph, ham logları temizlenmiş loglara dönüştürür ve ardından iki alt graph’ı paralel dallar olarak çalıştırır.

Parent graph’a alt graph’ları bağlama
# Entry Graph
class EntryGraphState(TypedDict):
    """
    Define the state schema used by the graph.
    """
    raw_logs: List[Log]
    cleaned_logs: List[Log]
    fa_summary: str # This will only be generated in the FA sub-graph
    report: str # This will only be generated in the QS sub-graph
    processed_logs:  Annotated[List[int], add] # This will be generated in BOTH sub-graphs

def clean_logs(state):
    """
    Run the clean_logs helper.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    # Get logs
    raw_logs = state["raw_logs"]
    # Data cleaning raw_logs -> docs
    cleaned_logs = raw_logs
    return {"cleaned_logs": cleaned_logs}

entry_builder = StateGraph(EntryGraphState)
entry_builder.add_node("clean_logs", clean_logs)
entry_builder.add_node("question_summarization", qs_builder.compile())
entry_builder.add_node("failure_analysis", fa_builder.compile())

entry_builder.add_edge(START, "clean_logs")
entry_builder.add_edge("clean_logs", "failure_analysis")
entry_builder.add_edge("clean_logs", "question_summarization")
entry_builder.add_edge("failure_analysis", END)
entry_builder.add_edge("question_summarization", END)

graph = entry_builder.compile()

from IPython.display import Image, display

# Setting xray to 1 will show the internal structure of the nested graph
display(Image(graph.get_graph(xray=1).draw_mermaid_png()))

processed_logs iki alt graph tarafından üretildiği için reducer taşır. Buna karşılık cleaned_logs, output schema sayesinde geri yayınlanmadığından reducer gerektirmez.

Örnek loglarla graph’ı çalıştırma

Son blok, iki temsilî log üretir ve parent graph’ı bu girişle çalıştırır. Final state, parent girdilerini ve iki alt graph’tan gelen çıktıları birlikte gösterir.

raw_logs = [
    question_answer,
    question_answer_feedback,
]
graph.invoke({"raw_logs": raw_logs})

Çıktı Yorumu

Final state içinde raw_logs ve cleaned_logs parent akışından gelir; fa_summary failure analysis alt graph’ından, report question summarization alt graph’ından, processed_logs ise iki alt graph’ın reducer ile birleşen çıktılarından oluşur.

Çıktıların Yorumlanması

Bu dersteki görsel çıktılar graph topolojisini, metin çıktısı ise final state’i gösterir. Görsellerde dikkat edilmesi gereken nokta, alt graph’ların kendi iç node dizilerini koruması ve parent graph içinde kapsüllenmiş biçimde kullanılabilmesidir.

Okuma rehberi

Final state çıktısında fa_summary alanı failure analysis akışından, report alanı soru özetleme akışından gelir. processed_logs alanı iki alt graph’ın aynı parent alanına yazdığı değerlerin reducer ile birleştirilmiş halidir. cleaned_logs ise output schema sayesinde alt graph’lardan geri dönen bir çakışma alanı olmaktan çıkar.

Graph Akışı

Parent graph akışı

START -> clean_logsHam log listesi temizlenmiş log alanına aktarılır.
clean_logs -> iki alt graphFailure analysis ve question summarization paralel çalışır.
alt graph -> ENDHer alt graph kendi output schema alanlarını parent state’e döndürür.

Alt graph akışları

Failure analysisget_failures logları filtreler, generate_summary failure özetini üretir.
Question summarizationgenerate_summary soru özetini üretir, send_to_slack rapor alanını yazar.
Nested görünümxray=1, parent graph içindeki alt graph node’larını açarak yapıyı görünür kılar.

State’in Evrimi

1. Girişraw_logs, iki log nesnesinden oluşan parent graph girdisidir.
2. Temizlemeclean_logs, raw_logs değerini cleaned_logs olarak yazar.
3. Failure branchcleaned_logs okunur, failures iç state’i üretilir, fa_summary ve failure işlem kayıtları yayımlanır.
4. Summary branchAynı cleaned_logs okunur, qs_summary iç state’i üretilir, report ve summary işlem kayıtları yayımlanır.
5. Reducer birleşimiprocessed_logs, iki alt graph’tan gelen liste parçalarını add ile birleştirir.
6. Final stateParent graph, ortak girişleri ve alt graph sonuçlarını tek dictionary içinde döndürür.

Agent / Tool Etkileşimi

Bu derste henüz tam agent-tool döngüsü kurulmaz. send_to_slack adı bir entegrasyon fikrini temsil eder, fakat gerçek bir tool binding, ToolNode veya model tarafından üretilen tool call akışı yoktur. Odak, farklı alt görevlerin ayrı graph state’leriyle yönetilmesi ve parent graph’a kontrollü çıktı vermesidir.

Parent graphcleaned_logs alanını alt graph’lara ortak girdi olarak sağlar.
Failure analysisfa_summary ve kendi işlem kayıtlarını döndürür.
Question summarizationreport ve kendi işlem kayıtlarını döndürür.

Yaygın Hatalar

  • Alt graph state’ini parent graph state’iyle tamamen aynı sanmak.
  • Overlapping key yoksa verinin otomatik taşınacağını varsaymak.
  • output_schema kullanmadan tüm alt graph state’inin parent graph’a döneceğini hesaba katmamak.
  • Paralel alt graph’ların aynı state anahtarına reducer olmadan yazabileceğini düşünmek.
  • cleaned_logs gibi yalnızca giriş olan alanları gereksiz yere çıktı olarak yayımlamak.
  • Derlenmiş alt graph’ın parent graph içinde node gibi kullanılabileceğini gözden kaçırmak.
  • Graph görselini runtime çıktısı sanmak; görsel topolojiyi, final output ise state sonucunu gösterir.
  • İzleme ayarlarını graph davranışının parçası sanmak; trace ayarları gözlemlenebilirliği etkiler.

Son Çıkarımlar

  1. Alt graph, parent graph içinde node gibi kullanılabilir ama kendi state sözleşmesini korur.
  2. Parent-subgraph iletişimi ortak state anahtarlarıyla gerçekleşir.
  3. cleaned_logs, iki alt graph’ın ortak girdisidir.
  4. fa_summary, failure analysis alt graph’ının dışarı verdiği sonuçtur.
  5. report, question summarization alt graph’ının dışarı verdiği sonuçtur.
  6. output_schema, alt graph’ın parent graph’a hangi anahtarları yayımladığını sınırlar.
  7. processed_logs iki paralel alt graph’tan geldiği için reducer ile birleştirilir.
  8. xray görünümü nested graph yapısını debug ve öğretim için açar.
  9. Sub-graph kapsülleme, büyük agentic sistemlerde trace okunabilirliğini artırır.
  10. Bu dersteki yapı, daha karmaşık çok ajanlı graph mimarileri için temel oluşturur.

# Failure Analysis Sub-graph
class FailureAnalysisState(TypedDict):
    """
    Define the state schema used by the graph.
    """
    cleaned_logs: List[Log]
    failures: List[Log]
    fa_summary: str
    processed_logs: List[str]

class FailureAnalysisOutputState(TypedDict):
    """
    Define the state schema used by the graph.
    """
    fa_summary: str
    processed_logs: List[str]

def get_failures(state):
    """ Get logs that contain a failure """
    cleaned_logs = state["cleaned_logs"]
    failures = [log for log in cleaned_logs if "grade" in log]
    return {"failures": failures}

def generate_summary(state):
    """ Generate summary of failures """
    failures = state["failures"]
    # Add fxn: fa_summary = summarize(failures)
    fa_summary = "Poor quality retrieval of Chroma documentation."
    return {
        "fa_summary": fa_summary,
        "processed_logs": [
            f"failure-analysis-on-log-{failure['id']}"
            for failure in failures
        ],
    }

fa_builder = StateGraph(
    state_schema=FailureAnalysisState,
    output_schema=FailureAnalysisOutputState,
)
fa_builder.add_node("get_failures", get_failures)
fa_builder.add_node("generate_summary", generate_summary)
fa_builder.add_edge(START, "get_failures")
fa_builder.add_edge("get_failures", "generate_summary")
fa_builder.add_edge("generate_summary", END)

graph = fa_builder.compile()
display(Image(graph.get_graph().draw_mermaid_png()))
