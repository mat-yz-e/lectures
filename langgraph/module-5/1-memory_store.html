LangGraph’ta Uzun Süreli Bellek: Memory Store ile Kişiselleştirilmiş Chatbot

Bu ders, LangGraph Store ve checkpointer kavramlarını birlikte kullanarak kısa süreli konuşma belleği ile uzun süreli kullanıcı belleğini aynı chatbot graph’ında birleştirir.

Kapsam ve Bağlam

Bu bölümde amaç, bir chatbot’un yalnızca aynı konuşma içindeki mesajları değil, aynı kullanıcıya ait kalıcı bilgileri de kullanabilmesini sağlayan LangGraph bellek mimarisini açıklamaktır. Kısa süreli bellek, bir thread içindeki mesaj geçmişini korur; uzun süreli bellek ise user ID üzerinden farklı thread’lerde yeniden kullanılabilecek semantik kullanıcı bilgilerini saklar.

Bu Dersin Ana Tezi

State, checkpointer ve Store aynı şey değildir. State graph yürütmesinin sözleşmesini, checkpointer thread içi konuşma geçmişini, Store ise kullanıcıya göre namespaced uzun süreli belleği temsil eder.

Öğrenme Hedefleri

  • InMemoryStore ile namespace, key ve value ilişkisini açıklayabilecek.
  • search ve get metodlarının dönüş mantığını ayırt edebilecek.
  • MemorySaver ile thread içi kısa süreli belleğin rolünü yorumlayabilecek.
  • StateGraph içinde call_model ve write_memory node’larının sorumluluklarını ayırabilecek.
  • compile(checkpointer=..., store=...) çağrısının node’lara Store erişimi sağlamadaki önemini açıklayabilecek.
  • configurable.thread_id ile configurable.user_id arasındaki farkı kod üzerinden gösterebilecek.
  • stream_mode="values" çıktısını token streaming değil, state değeri akışı olarak okuyabilecek.
  • Output bloklarında mesaj çıktısı, Store çıktısı ve graph görselini ayrı teknik kanıtlar olarak yorumlayabilecek.

Ön Koşullar

Öğrencinin Python fonksiyonları, dictionary/list yapıları, ortam değişkenleri, type hint kullanımı, LLM mesaj rolleri ve temel LangGraph node-edge mantığı hakkında fikir sahibi olması beklenir. Checkpoint, thread ve state snapshot kavramları ilk kez görülüyorsa bunlar şu sezgiyle okunmalıdır: checkpoint konuşmanın belli bir yürütme çizgisindeki kayıtlı state’idir; thread bu kayıtların konuşma oturumu sınırıdır; Store ise thread sınırını aşan kullanıcı belleğidir.

Büyük Resim

Bu dersteki chatbot iki ayrı bellek hattını birlikte kullanır. Thread ID, aynı konuşma içindeki mesaj geçmişini tutar. User ID ise farklı konuşmalar arasında taşınacak kullanıcı bilgisini Store içinde adresler. Ana Anlatım

LangGraph Store, uzun süreli bellek için açık bir adresleme modeli sağlar. Bir bellek nesnesi namespace, key ve value ile saklanır. Namespace kullanıcıya veya bellek türüne göre ayrım yapar; key aynı namespace içindeki tekil kaydı seçer; value ise genellikle dictionary biçimli içeriktir. Bu model, düz bir Python değişkeninden farklıdır çünkü graph node’ları aynı Store sözleşmesini kullanarak belleği okuyabilir ve yazabilir.

Kısa ve uzun süreli bellek ayrımı

Kısa süreli bellek konuşma geçmişidir ve thread ile ilişkilidir. Uzun süreli bellek kullanıcı profilidir ve user ID ile ilişkilidir. Aynı kullanıcı yeni bir thread başlattığında kısa süreli geçmiş temiz olabilir; fakat Store belleği aynı user ID üzerinden yeniden bulunabilir.

Modelin kişiselleştirme noktası

Model doğrudan Store’u bilmek zorunda değildir. Node fonksiyonu Store’dan bellek okur, bunu sistem mesajı içine yerleştirir ve modeli bu mesaj listesiyle çağırır. Böylece kişiselleştirme açık, denetlenebilir ve graph akışına bağlı hale gelir.

Bellek kullanan chatbot graph’ını kurma

Bu ana blok, short-term memory için checkpointer, long-term memory için Store, iki graph node’u ve graph topolojisini bir araya getirir.

Bellek kullanan chatbot graph’ını kurma
from IPython.display import Image, display

from langgraph.checkpoint.memory import MemorySaver
from langgraph.graph import StateGraph, MessagesState, START, END
from langgraph.store.base import BaseStore

from langchain_core.messages import HumanMessage, SystemMessage
from langchain_core.runnables.config import RunnableConfig

# Chatbot instruction
MODEL_SYSTEM_MESSAGE = (
    "You are a helpful assistant with memory that provides "
    "information about the user.\n"
    "If you have memory for this user, use it to personalize "
    "your responses.\n"
    "Here is the memory (it may be empty): {memory}"
)

# Create new memory from the chat history and any existing memory
CREATE_MEMORY_INSTRUCTION = (
    "\"You are collecting information about the user to personalize "
    "your responses.\n\n"
    "CURRENT USER INFORMATION:\n"
    "{memory}\n\n"
    "INSTRUCTIONS:\n"
    "1. Review the chat history below carefully\n"
    "2. Identify new information about the user, such as:\n"
    "   - Personal details (name, location)\n"
    "   - Preferences (likes, dislikes)\n"
    "   - Interests and hobbies\n"
    "   - Past experiences\n"
    "   - Goals or future plans\n"
    "3. Merge any new information with existing memory\n"
    "4. Format the memory as a clear, bulleted list\n"
    "5. If new information conflicts with existing memory, keep the "
    "most recent version\n\n"
    "Remember: Only include factual information directly stated by "
    "the user. Do not make assumptions or inferences.\n\n"
    "Based on the chat history below, please update the user "
    "information:"
)


def call_model(
    state: MessagesState,
    config: RunnableConfig,
    store: BaseStore,
):
    """
    Load memory from the store and use it to personalize the
    chatbot response.
    """

    # Get the user ID from the config
    user_id = config["configurable"]["user_id"]

    # Retrieve memory from the store
    namespace = ("memory", user_id)
    key = "user_memory"
    existing_memory = store.get(namespace, key)

    # Extract the actual memory content if it exists and add a prefix
    if existing_memory:
        # Value is a dictionary with a memory key
        existing_memory_content = existing_memory.value.get("memory")
    else:
        existing_memory_content = "No existing memory found."

    # Format the memory in the system prompt
    system_msg = MODEL_SYSTEM_MESSAGE.format(
        memory=existing_memory_content
    )

    # Respond using memory as well as the chat history
    response = model.invoke(
        [SystemMessage(content=system_msg)] + state["messages"]
    )

    return {"messages": response}


def write_memory(
    state: MessagesState,
    config: RunnableConfig,
    store: BaseStore,
):
    """Reflect on the chat history and save a memory to the store."""

    # Get the user ID from the config
    user_id = config["configurable"]["user_id"]

    # Retrieve existing memory from the store
    namespace = ("memory", user_id)
    existing_memory = store.get(namespace, "user_memory")

    # Extract the memory
    if existing_memory:
        existing_memory_content = existing_memory.value.get("memory")
    else:
        existing_memory_content = "No existing memory found."

    # Format the memory in the system prompt
    system_msg = CREATE_MEMORY_INSTRUCTION.format(
        memory=existing_memory_content
    )
    new_memory = model.invoke(
        [SystemMessage(content=system_msg)] + state["messages"]
    )

    # Overwrite the existing memory in the store
    key = "user_memory"

    # Write value as a dictionary with a memory key
    store.put(namespace, key, {"memory": new_memory.content})


# Define the graph
builder = StateGraph(MessagesState)
builder.add_node("call_model", call_model)
builder.add_node("write_memory", write_memory)
builder.add_edge(START, "call_model")
builder.add_edge("call_model", "write_memory")
builder.add_edge("write_memory", END)

# Store for long-term (across-thread) memory
across_thread_memory = InMemoryStore()

# Checkpointer for short-term (within-thread) memory
within_thread_memory = MemorySaver()

# Compile the graph with the checkpointer and store
graph = builder.compile(
    checkpointer=within_thread_memory,
    store=across_thread_memory,
)

# View
display(Image(graph.get_graph(xray=1).draw_mermaid_png()))

LangGraph açısından önemi

call_model node’u Store’dan kullanıcı belleğini okuyup sistem mesajına yerleştirir. write_memory node’u konuşma geçmişinden yeni kullanıcı bilgisini çıkarıp aynı Store alanına yazar.

Dikkat edilmesi gereken nokta

Store graph compile sırasında verildiği için node fonksiyonlarına parametre olarak erişilebilir. Store’u sıradan global değişken gibi düşünmek, LangGraph çalışma sözleşmesini yanlış yorumlatır.

Çıktıların Yorumlanması

Bu derste üç çıktı türü özellikle önemlidir. Store çıktıları key, namespace, value ve metadata alanlarını gösterir. Mesaj çıktıları graph’ın kullanıcı ve model mesajlarını state içinde nasıl taşıdığını gösterir. Graph görseli ise yürütme topolojisini doğrular. Bu üç kanıt birlikte okunduğunda kişiselleştirme mekanizması netleşir: bilgi önce konuşmada görünür, sonra Store’a yazılır, sonra yeni thread’de sistem mesajına taşınır.

Okuma rehberi

Out [ ] bloklarında siyah düz metin görünümü özellikle korunmuştur. Bu çıktılar kod değildir; çalışma sonucudur. Mesaj çıktılarında insan ve model rolleri, Store çıktılarında ise value ve namespace alanları öncelikli okunmalıdır.

Graph Akışı

STARTGraph yürütmesinin giriş sentinel değeridir.
call_modelStore’dan bellek okur, sistem mesajını oluşturur ve model cevabı üretir.
write_memoryKonuşma geçmişinden kullanıcı bilgisi çıkarır ve Store’a yazar.
ENDGraph yürütmesini sonlandırır.

Graph’ta conditional edge yoktur. Akış doğrusal olarak ilerler: önce cevap üretilir, sonra bellek yazılır. Bu tasarım, kullanıcının yanıtı gecikmeden almasını ve bellek güncellemesinin ayrı sorumluluk olarak tutulmasını sağlar.

State’in Evrimi

Başlangıç input’u{"messages": input_messages} state’e kullanıcı mesajını verir.
call_modelstate["messages"] okunur, Store belleği sistem mesajına eklenir, assistant mesajı döndürülür.
write_memoryMesaj geçmişi okunur, mevcut Store belleğiyle birleştirilecek yeni kullanıcı profili üretilir.
Checkpoint ve StoreCheckpointer thread mesajlarını saklar; Store kullanıcı belleğini ("memory", user_id) altında saklar.

Burada reducer tanımı yapılmaz; MessagesState hazır mesaj state sözleşmesini sağlar. Store update’i state alanı update’i değildir; graph runtime’ına bağlı harici bellek yazımıdır.

Agent / Tool Etkileşimi

Bu derste henüz tam agent-tool döngüsü kurulmaz. ToolNode, tool binding veya tools_condition kullanılmaz. Odak state/message yönetimi, Store API ve kişiselleştirilmiş model çağrısıdır. Bu yapı sonraki agent örnekleri için zemin hazırlar; çünkü agent’ın araç kullanırken de kullanıcı belleğini aynı Store yaklaşımıyla okuyup yazması mümkündür.

Yaygın Hatalar

  • State’i local değişken sanmak; state graph yürütmesinin sözleşmesidir.
  • Checkpointer ile Store’u aynı bellek türü sanmak; biri thread içi, diğeri thread’ler arasıdır.
  • thread_id ile user_id değerlerini aynı amaçla kullanmak.
  • search sonucunu tek kayıt beklemek; sonuç liste döner.
  • get sonucunun her zaman dolu olacağını varsaymak.
  • Store’a yazılan value değerini düz string olarak düşünmek; örnekte dictionary sözleşmesi kullanılır.
  • compile sırasında Store verilmeden node içinde Store erişimi beklemek.
  • stream_mode="values" davranışını token streaming ile karıştırmak.
  • Model cevabını bellek kaydı sanmak; bellek yazımı ayrı write_memory node’unda yapılır.
  • API anahtarını kod içine yazmak; ortam değişkeni yaklaşımı kullanılmalıdır.
  • Uzun süreli belleğin otomatik doğruluk garantisi verdiğini sanmak; prompt yalnızca kullanıcı tarafından açıkça söylenen olguları yazmalıdır.
  • Graph görselinde state değerlerinin göründüğünü sanmak; görsel yalnızca topolojiyi gösterir.

Son Çıkarımlar

  1. LangGraph Store uzun süreli belleği namespace, key ve value sözleşmesiyle adresler.
  2. Checkpointer konuşma geçmişini thread düzeyinde saklar.
  3. User ID, Store belleğinin kullanıcıya göre ayrılmasını sağlar.
  4. Thread ID değişse bile aynı user ID ile Store belleği yeniden okunabilir.
  5. call_model belleği okur ve model bağlamına ekler.
  6. write_memory konuşma geçmişinden yeni bellek üretir ve Store’a yazar.
  7. compile(checkpointer=..., store=...) kısa ve uzun süreli bellek hattını aynı graph runtime’ında birleştirir.
  8. stream_mode="values" state değerlerinin akışını gösterir.
  9. Store çıktıları metadata ile birlikte gelir; bu yüzden bellek kayıtları denetlenebilir nesnelerdir.
  10. Bu örnek agent-tool döngüsü değil, bellek destekli chatbot mimarisinin temelidir.

    "Based on the chat history below, please update the user "

)


def call_model(
    state: MessagesState,
    config: RunnableConfig,
    store: BaseStore,
):
    """
    Load memory from the store and use it to personalize the
    chatbot response.
    """

    # Get the user ID from the config
    user_id = config["configurable"]["user_id"]

    # Retrieve memory from the store
    namespace = ("memory", user_id)
    key = "user_memory"
    existing_memory = store.get(namespace, key)

    # Extract the actual memory content if it exists and add a prefix
    if existing_memory:
        # Value is a dictionary with a memory key
        existing_memory_content = existing_memory.value.get("memory")
    else:
        existing_memory_content = "No existing memory found."

    # Format the memory in the system prompt
    system_msg = MODEL_SYSTEM_MESSAGE.format(
        memory=existing_memory_content
    )

    # Respond using memory as well as the chat history
    response = model.invoke(
        [SystemMessage(content=system_msg)] + state["messages"]
    )

    return {"messages": response}


def write_memory(
    state: MessagesState,
    config: RunnableConfig,
    store: BaseStore,
):
    """Reflect on the chat history and save a memory to the store."""

    # Get the user ID from the config
    user_id = config["configurable"]["user_id"]

    # Retrieve existing memory from the store
    namespace = ("memory", user_id)
    existing_memory = store.get(namespace, "user_memory")

    # Extract the memory
    if existing_memory:
        existing_memory_content = existing_memory.value.get("memory")
    else:
        existing_memory_content = "No existing memory found."

    # Format the memory in the system prompt
    system_msg = CREATE_MEMORY_INSTRUCTION.format(
        memory=existing_memory_content
    )
    new_memory = model.invoke(
        [SystemMessage(content=system_msg)] + state["messages"]
    )

    # Overwrite the existing memory in the store
    key = "user_memory"

    # Write value as a dictionary with a memory key
    store.put(namespace, key, {"memory": new_memory.content})


# Define the graph
builder = StateGraph(MessagesState)
builder.add_node("call_model", call_model)
builder.add_node("write_memory", write_memory)
builder.add_edge(START, "call_model")
builder.add_edge("call_model", "write_memory")
builder.add_edge("write_memory", END)
