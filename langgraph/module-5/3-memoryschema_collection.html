LangGraph’ta Koleksiyon Şemasıyla Uzun Süreli Bellek

Bu ders, kullanıcı hakkında büyüyebilen bellek kayıtlarını Pydantic şemaları, Trustcall ve LangGraph Store ile nasıl yöneteceğinizi teknik bir akış içinde açıklar.

Kapsam ve Bağlam

Bu bölümde amaç, uzun süreli belleğin tek bir profil nesnesiyle sınırlı kalmadığı durumları ele almaktır. Kullanıcı hakkında zamanla biriken bilgi, tekil bir alanın sürekli ezilmesi yerine, bağımsız bellek kayıtlarından oluşan bir koleksiyon olarak tutulur.

Bu yaklaşım özellikle sohbet tabanlı sistemlerde önemlidir: kullanıcı bir konuşmada adını, başka bir konuşmada ilgi alanlarını, daha sonra da tercihlerini paylaşabilir. LangGraph Store bu bilgileri kullanıcıya bağlı bir namespace içinde taşırken, graph state kısa süreli mesaj akışını yönetir.

Bu Dersin Ana Tezi

Uzun süreli bellek yalnızca tek bir profil kaydı değildir; doğru şema, key ve metadata tasarımıyla güncellenebilir ve büyüyebilir bir koleksiyon olarak yönetilebilir.

Öğrenme Hedefleri

  • Memory ve MemoryCollection şemalarının hangi problemi çözdüğünü açıklayabilecek.
  • with_structured_output ile Pydantic tabanlı bellek çıkarımını yorumlayabilecek.
  • LangGraph Store içinde namespace, key ve value ayrımını kod üzerinden ayırt edebilecek.
  • Trustcall metadata'sındaki json_doc_id alanının güncelleme mantığındaki rolünü açıklayabilecek.
  • StateGraph, MessagesState, checkpointer ve store sorumluluklarını birbirinden ayırabilecek.
  • stream_mode="values" çıktılarında kullanıcı ve asistan mesajlarını state evrimi açısından okuyabilecek.

Ön Koşullar

Bu dersi izlemek için Python fonksiyonları, list/dict yapıları, class tanımları, type hint kullanımı ve ortam değişkeni mantığı bilinmelidir. BaseModel, Field, HumanMessage, SystemMessage, StateGraph ve InMemoryStore gibi terimler ilk kez kullanıldığında kod bağlamında açıklanacaktır.

LLM tarafında temel mesaj rolleri ve model çağrısı sezgisi; LangGraph tarafında ise state, node, edge, store ve checkpoint ayrımı yeterlidir. Async yürütme bu bölümün odağı değildir.

Büyük Resim

Bu derste bellek üç katmanda düşünülür. İlk katman, modelin serbest metinden yapılandırılmış bellek nesneleri üretmesidir. İkinci katman, bu nesnelerin LangGraph Store içinde kullanıcı namespace'i altında saklanmasıdır. Üçüncü katman, graph çalışırken store'daki belleklerin prompt bağlamına geri yüklenmesidir.

Kullanıcı mesajıMesaj state'ine giren doğal dil verisi.
ŞemaMemory ve MemoryCollection ile doğrulanabilir yapı.
TrustcallMevcut kaydı güncelleme veya yeni kayıt ekleme kararı.
StoreNamespace ve key ile uzun süreli kayıt.
Graph cevabıBelleklerin prompt bağlamına taşınması.

State bir local değişken değildir

Graph state, node'lar arasında taşınan sözleşmeli yürütme verisidir. Store ise thread dışına taşan uzun süreli bellek alanıdır. Bu iki katman aynı veri yapısı gibi düşünülürse bellek davranışı yanlış yorumlanır.

Ana Anlatım

Profil ve koleksiyon farkı

Profil yaklaşımında kullanıcı hakkında tek bir nesne tutulur ve yeni bilgi geldikçe aynı nesne güncellenir. Koleksiyon yaklaşımında ise kullanıcı hakkında birden fazla bellek kaydı bulunabilir. Bu, yapılacaklar listesi, tercih geçmişi, ilgi alanları veya olay temelli anılar gibi açık uçlu büyüyen veriler için daha uygundur.

Trustcall'ın rolü

Trustcall, modelin çıkardığı bilgiyi bir şemaya bağlarken mevcut belleklerin güncellenmesini ve yeni belleklerin eklenmesini birlikte ele alır. enable_inserts=True ayarı bu dersin merkezindedir; çünkü koleksiyon yalnızca var olan kaydı düzeltmez, gerektiğinde yeni kayıt da açar.

Store ve checkpointer ayrımı

InMemoryStore, kullanıcıya bağlı uzun süreli belleği temsil eder. MemorySaver ise belirli bir thread içindeki kısa süreli mesaj state'ini korur. Aynı kullanıcı yeni bir thread açtığında eski thread mesajları taşınmayabilir, fakat store içindeki kullanıcı belleği yeniden kullanılabilir.

import getpass
import os


def _set_env(var: str):
    """
    Prepare an environment variable for the current process.

    Args:
        var: Environment variable to check. If missing,
            request the value from the user.

    Returns:
        None: The function updates `os.environ` in place.
    """
    env_value = os.environ.get(var)
    if not env_value:
        env_value = getpass.getpass(f"{var}: ")

    os.environ[var] = env_value

Bellek koleksiyonu için Pydantic şeması
from pydantic import BaseModel, Field


class Memory(BaseModel):
    """
    Represent one memory record to store about the user.
    """

    content: str = Field(
        description=(
            "The main content of the memory. "
            "For example: User expressed interest in "
            "learning about French."
        )
    )


class MemoryCollection(BaseModel):
    """
    Carry memory records as an open-ended collection.
    """

    memories: list[Memory] = Field(
        description="A list of memories about the user."
    )

from IPython.display import Image, display

import uuid

from langchain_core.messages import HumanMessage, SystemMessage
from langchain_core.messages import merge_message_runs
from langchain_core.runnables.config import RunnableConfig
from langgraph.checkpoint.memory import MemorySaver
from langgraph.graph import (
    END,
    START,
    MessagesState,
    StateGraph,
)
from langgraph.store.base import BaseStore
from langgraph.store.memory import InMemoryStore

model = ChatOpenAI(model="gpt-4o", temperature=0)


class Memory(BaseModel):
    """
    Represent one memory record to store about the user.
    """

    content: str = Field(
        description=(
            "The main content of the memory. "
            "For example: User expressed interest in "
            "learning about French."
        )
    )


trustcall_extractor = create_extractor(
    model,
    tools=[Memory],
    tool_choice="Memory",
    enable_inserts=True,
)

MODEL_SYSTEM_MESSAGE = (
    "You are a helpful chatbot. You are designed to be a "
    "companion to a user.\n\n"
    "You have a long term memory which keeps track of "
    "information you learn about the user over time.\n\n"
    "Current Memory (may include updated memories "
    "from this conversation):\n\n"
    "{memory}"
)

TRUSTCALL_INSTRUCTION = (
    "Reflect on following interaction.\n\n"
    "Use the provided tools to retain any necessary memories "
    "about the user.\n\n"
    "Use parallel tool calling to handle updates "
    "and insertions simultaneously:"
)


def call_model(
    state: MessagesState,
    config: RunnableConfig,
    store: BaseStore,
):
    """
    Load long-term memories from the store and personalize the
    chatbot response with that context.

    Args:
        state: Message state carried by LangGraph.
        config: Runtime configuration with values such as
            `thread_id` and `user_id`.
        store: Store that holds long-term memories for the
            user.

    Returns:
        dict: Model response to append to the `messages` field.
    """
    user_id = config["configurable"]["user_id"]

    namespace = ("memories", user_id)
    memories = store.search(namespace)

    info = "\n".join(
        f"- {mem.value['content']}" for mem in memories
    )
    system_msg = MODEL_SYSTEM_MESSAGE.format(memory=info)

    response = model.invoke(
        [SystemMessage(content=system_msg)] + state["messages"]
    )

    return {"messages": response}


def write_memory(
    state: MessagesState,
    config: RunnableConfig,
    store: BaseStore,
):
    """
    Reflect on the chat history and update the memory
    collection.

    Args:
        state: Message history accumulated during graph
            execution.
        config: Runtime settings that identify the user receiving
            memory writes.
        store: LangGraph store where existing and new memories are
            saved.

    Returns:
        None: Memory updates are written to the store as a side
            effect.
    """
    user_id = config["configurable"]["user_id"]
    namespace = ("memories", user_id)

    existing_items = store.search(namespace)

    tool_name = "Memory"
    existing_memories = (
        [
            (existing_item.key, tool_name, existing_item.value)
            for existing_item in existing_items
        ]
        if existing_items
        else None
    )

    updated_messages = list(
        merge_message_runs(
            messages=(
                [SystemMessage(content=TRUSTCALL_INSTRUCTION)]
                + state["messages"]
            )
        )
    )

    result = trustcall_extractor.invoke(
        {
            "messages": updated_messages,
            "existing": existing_memories,
        }
    )

    for r, rmeta in zip(
        result["responses"],
        result["response_metadata"],
    ):
        store.put(
            namespace,
            rmeta.get("json_doc_id", str(uuid.uuid4())),
            r.model_dump(mode="json"),
        )


builder = StateGraph(MessagesState)
builder.add_node("call_model", call_model)
builder.add_node("write_memory", write_memory)
builder.add_edge(START, "call_model")
builder.add_edge("call_model", "write_memory")
builder.add_edge("write_memory", END)

across_thread_memory = InMemoryStore()
within_thread_memory = MemorySaver()

graph = builder.compile(
    checkpointer=within_thread_memory,
    store=across_thread_memory,
)

display(Image(graph.get_graph(xray=1).draw_mermaid_png()))

Çıktıların Yorumlanması

Çıktılarda üç farklı temsil görülür. Pydantic repr çıktıları, modelden çıkarılan doğrulanmış bellek nesnelerini gösterir. Store çıktıları, value/key/namespace/metadata ayrımını görünür kılar. Okuma rehberi

Graph Akışı

STARTYürütme mesaj state'i ile başlar.
call_modelStore'daki bellekler okunur ve model cevabı üretilir.
write_memorySohbet geçmişi Trustcall ile değerlendirilir ve store güncellenir.
ENDGraph bu turu tamamlar.

Bu graph'ta conditional edge yoktur; yürütme her çağrıda model cevabından sonra bellek yazma adımına geçer. Bu tasarım, kullanıcıya cevap üretme ile bellek güncelleme sorumluluğunu ayrı node'larda tutar.

State’in Evrimi

Başlangıç state'imessages alanına kullanıcı mesajı eklenir.
Model cevabıcall_model, store'dan okunan bellekleri sistem mesajına ekler ve assistant mesajını döndürür.
Bellek yazımıwrite_memory, state'teki mesajları Trustcall'a verir ve store üzerinde yan etki üretir.
Yeni threadthread_id değişse bile aynı user_id ile uzun süreli store belleği yeniden okunur.

Bu bölümde reducer veya conditional routing kullanılmaz. Odak, mesaj state'i ile store belleğinin ayrı fakat birlikte çalışan iki katman olarak tasarlanmasıdır.

Agent / Tool Etkileşimi

Bu derste tam bir agent-tool döngüsü veya ToolNode kullanılmaz. Buna rağmen Trustcall içinde model tool calling davranışı vardır: model Memory şemasına uygun tool call üretir, Trustcall bunu doğrulanmış response nesnelerine ve metadata kayıtlarına dönüştürür.

KullanıcıYeni kişisel bilgi verir.
ModelSohbet cevabı üretir.
TrustcallGüncellenecek veya eklenecek bellekleri şemaya bağlı çıkarır.
StoreBelirlenen namespace ve key altında kayıtları saklar.

Yaygın Hatalar

  • State'i local değişken sanmak ve node'lar arası sözleşme olduğunu gözden kaçırmak.
  • Store ile checkpointer'ı aynı bellek katmanı gibi düşünmek.
  • Tek profil güncelleme mantığını koleksiyon belleğine aynen uygulamak.
  • json_doc_id alanını dikkate almadan her sonucu yeni UUID ile kaydetmek.
  • Tool call çıktısını doğrudan nihai kullanıcı cevabı sanmak.
  • Namespace sırasını tutarsız kurarak kayıtları yanlış kullanıcı altında aramak.
  • stream_mode="values" çıktısını token streaming ile karıştırmak.
  • API anahtarını kod içine açık değer olarak yazmak.
  • Çok geniş veya belirsiz şema açıklamalarıyla yinelenen bellekler üretmek.

Son Çıkarımlar

  1. Koleksiyon belleği, kullanıcı hakkında birden çok bağımsız kaydı saklamak için profil belleğinden daha uygundur.
  2. Memory şeması tek kayıt biçimini; MemoryCollection birden fazla kaydı temsil eder.
  3. with_structured_output, model çıktısını doğrulanmış Pydantic nesnelerine yaklaştırır.
  4. Store yazımı namespace, key ve value ayrımıyla düşünülmelidir.
  5. Yeni belleklerde UUID, güncellemelerde json_doc_id kaynaklı mevcut key kullanılmalıdır.
  6. call_model ve write_memory ayrımı graph sorumluluklarını sadeleştirir.
  7. Checkpointer thread içi sürekliliği; store kullanıcılar arası uzun süreli belleği temsil eder.
  8. Aynı user_id, farklı thread içinde önceki uzun süreli belleğin yeniden kullanılmasını sağlar.
  9. Pretty print çıktıları mesaj temsilidir; store çıktıları kalıcı bellek kayıtlarını gösterir.
  10. Bu yapı, sonraki daha kapsamlı memory agent tasarımları için temel oluşturur.

        state: Message state carried by LangGraph.
        config: Runtime configuration with values such as
            `thread_id` and `user_id`.
        store: Store that holds long-term memories for the
            user.

    Returns:
        dict: Model response to append to the `messages` field.
    """
    user_id = config["configurable"]["user_id"]

    namespace = ("memories", user_id)
    memories = store.search(namespace)

    info = "\n".join(
        f"- {mem.value['content']}" for mem in memories
    )
    system_msg = MODEL_SYSTEM_MESSAGE.format(memory=info)

    response = model.invoke(
        [SystemMessage(content=system_msg)] + state["messages"]
    )

    return {"messages": response}


def write_memory(
    state: MessagesState,
    config: RunnableConfig,
    store: BaseStore,
):
    """
    Reflect on the chat history and update the memory
    collection.

    Args:
        state: Message history accumulated during graph
            execution.
        config: Runtime settings that identify the user receiving
            memory writes.
        store: LangGraph store where existing and new memories are
            saved.

    Returns:
        None: Memory updates are written to the store as a side
            effect.
    """
    user_id = config["configurable"]["user_id"]
    namespace = ("memories", user_id)

    existing_items = store.search(namespace)

    tool_name = "Memory"
    existing_memories = (
        [
            (existing_item.key, tool_name, existing_item.value)
            for existing_item in existing_items
        ]
        if existing_items
        else None
    )

    updated_messages = list(
        merge_message_runs(
            messages=(
                [SystemMessage(content=TRUSTCALL_INSTRUCTION)]
                + state["messages"]
            )
        )
    )

    result = trustcall_extractor.invoke(
        {
            "messages": updated_messages,
            "existing": existing_memories,
        }
    )

    for r, rmeta in zip(
        result["responses"],
        result["response_metadata"],
    ):
        store.put(
            namespace,
            rmeta.get("json_doc_id", str(uuid.uuid4())),
            r.model_dump(mode="json"),
        )
