LangGraph’ta Çoklu State Şemaları: Private State ve Input/Output Sözleşmeleri

Bu ders, LangGraph graph’larında tek bir state şemasıyla yetinmek yerine iç çalışma alanlarını, dış input sözleşmesini ve dış output sözleşmesini ayrı ayrı tasarlamanın neden gerekli olduğunu açıklar.

Kapsam ve Bağlam

LangGraph’ta çoğu başlangıç örneği tek bir state şeması kullanır: graph dışarıdan aynı şemayla veri alır, node’lar aynı şemadaki alanları okur ve graph tamamlandığında yine aynı state alanları döner. Bu yaklaşım basittir; ancak gerçek uygulamalarda graph’ın iç hesaplama alanları ile kullanıcının görmesi gereken giriş/çıkış alanları her zaman aynı değildir.

Bu Dersin Ana Tezi

Çoklu state şemaları, graph’ın iç veri dolaşımını dış API sözleşmesinden ayırır. PrivateState ara node iletişimi için, InputState dış girişin daraltılması için, OutputState ise dışarıya sunulacak sonucun sınırlandırılması için kullanılır.

Öğrenme Hedefleri

  • Tek overall state şemasının hangi durumlarda yeterli, hangi durumlarda fazla geniş olduğunu ayırt etmek.
  • Node fonksiyonlarında parametre tipi ve dönüş tipi üzerinden farklı state şemaları kullanabilmek.
  • PrivateState ile graph içi ara bilgiyi final çıktısından ayırmak.
  • input_schema ve output_schema argümanlarının graph dış sözleşmesini nasıl daralttığını açıklamak.
  • Graph akışında hangi node’un hangi state kanalını okuyup hangi kanala yazdığını izleyebilmek.
  • Çalıştırma çıktılarında görünen state alanlarını schema tasarımı açısından yorumlamak.

Ön Koşullar

Bu ders, Python fonksiyonları, dictionary erişimi, type hint yazımı ve TypedDict mantığına aşinalık varsayar. LangGraph tarafında StateGraph, node, edge, START, END ve invoke kavramlarının temel sezgisi yeterlidir.

Büyük Resim

Bu derste model veya tool çağrısı yoktur; odak doğrudan state sözleşmesindedir. LangGraph açısından kritik ayrım şudur: graph’ın içeride işlediği state alanları ile dış çağıranın vermesi veya görmesi gereken alanlar ayrı tasarlanabilir.

Dış inputKullanıcı yalnızca gerekli alanları verir.

Dış outputKullanıcıya yalnızca hedeflenen sonuç sunulur.

Ana Anlatım

Tek Şema ile Başlamak

Tek şemalı graph’ta her alan aynı düzlemde yer alır. Bu, küçük örneklerde anlaşılırdır; fakat ara not, geçici hesaplama veya node’lar arası yardımcı değer gibi bilgilerin final çıktıya karışma riskini artırır.

Private State Kullanmak

PrivateState, bir node’un ürettiği ve başka bir node’un okuyacağı ara alanları temsil eder. Bu derste node_1, foo değerinden baz üretir; node_2 ise baz değerini okuyup yeniden foo üretir. Böylece ara kanal graph içinde kalır.

Input ve Output Şemalarını Ayırmak

input_schema, graph’ın dışarıdan beklediği minimum alanları tanımlar. output_schema ise dışarıya gösterilmesi hedeflenen cevap alanlarını sınırlar. Bu ayrım, graph içindeki zengin state’i korurken dış API yüzeyini sade ve kontrollü tutmayı amaçlar.

Private state ile iç graph kanalını kurma

Bu blokta graph’ın dış sözleşmesi ile iç çalışma alanı ayrılır. OverallState dışarıdan görünen foo kanalını, PrivateState ise node’lar arasında taşınan baz kanalını temsil eder.

Private state ile iç graph kanalını kurma
from typing_extensions import TypedDict
from IPython.display import Image, display
from langgraph.graph import StateGraph, START, END


class OverallState(TypedDict):
    """
    Define the state schema used by the graph.
    """
    foo: int


class PrivateState(TypedDict):
    """
    Define the state schema used by the graph.
    """
    baz: int


def node_1(state: OverallState) -> PrivateState:
    """
    Run the node_1 helper.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    print("---Node 1---")
    return {"baz": state["foo"] + 1}


def node_2(state: PrivateState) -> OverallState:
    """
    Run the node_2 helper.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    print("---Node 2---")
    return {"foo": state["baz"] + 1}


# Build graph
builder = StateGraph(OverallState)
builder.add_node("node_1", node_1)
builder.add_node("node_2", node_2)

# Logic
builder.add_edge(START, "node_1")
builder.add_edge("node_1", "node_2")
builder.add_edge("node_2", END)

# Add
graph = builder.compile()

# View
display(Image(graph.get_graph().draw_mermaid_png()))

LangGraph açısından önemi

PrivateState, graph içinde kullanılan ama graph’ın dış giriş/çıkış sözleşmesinde yer alması gerekmeyen ara kanalları modellemek için kullanılır.

Dikkat edilmesi gereken nokta

Node parametre ve dönüş tipleri yalnızca dokümantasyon değildir; hangi node’un hangi state kanalını okuyup hangi kanala yazdığını öğrencinin takip etmesini sağlar.

Graph görseli

Çıktı Yorumu

Görsel çıktı, private kanal kullanan iki node’lu lineer graph topolojisini gösterir: başlangıç node_1 adımına, oradan node_2 adımına ve son olarak bitişe bağlanır.

Private state graph’ını çalıştırma

Bu çağrı graph’a yalnızca foo alanını verir. İlk node bu değerden private baz üretir; ikinci node private değeri okuyup tekrar dış state alanı olan foo değerini yazar.

Private state graph’ını çalıştırma
graph.invoke({"foo": 1})

LangGraph açısından önemi

Çıktının yalnızca foo içermesi, baz kanalının graph içinde hesaplama taşıdığı halde dış sonuca yansıtılmadığını gösterir.

Dikkat edilmesi gereken nokta

invoke girdisi OverallState içinde tanımlı dış alanlarla uyumlu olmalıdır. Private alanı başlangıç girdisi olarak vermek bu örneğin amacı değildir.

Terminal çıktısı
---Node 1---
---Node 2---
Python dict çıktısı

Çıktı Yorumu

Terminal satırları node çalışma sırasını doğrular. Final sözlükte baz bulunmaz; bu alan yalnızca graph içi geçişte kullanılmıştır.

Tek overall schema ile ara not alanı taşıma

Bu blokta tek OverallState hem giriş, hem ara çalışma alanı, hem de çıkış sözleşmesi olarak kullanılır. notes alanı graph içi akıl yürütme notu gibi taşınır ve final state’te görünür kalır.

Tek overall schema ile ara not alanı taşıma
class OverallState(TypedDict):
    """
    Define the state schema used by the graph.
    """
    question: str
    answer: str
    notes: str


def thinking_node(state: OverallState):
    """
    Run the thinking_node helper.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    return {"answer": "bye", "notes": "... his name is Lance"}


def answer_node(state: OverallState):
    """
    Run the answer_node helper.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    return {"answer": "bye Lance"}


graph = StateGraph(OverallState)
graph.add_node("answer_node", answer_node)
graph.add_node("thinking_node", thinking_node)
graph.add_edge(START, "thinking_node")
graph.add_edge("thinking_node", "answer_node")
graph.add_edge("answer_node", END)

graph = graph.compile()

# View
display(Image(graph.get_graph().draw_mermaid_png()))

LangGraph açısından önemi

Tek overall şema yaklaşımı hızlıdır; fakat iç çalışma alanlarının final state’te de görünebilmesi nedeniyle dış API sözleşmesi açısından daha gevşektir.

Dikkat edilmesi gereken nokta

notes gibi ara alanlar dış sözleşmeden gizlenmek isteniyorsa tek overall schema yeterli olmayabilir; sonraki blokta input/output filtreleri bu nedenle tanıtılır.

Dikkat edilmesi gereken nokta

Bu blokta ara notların görünür olması bilinçli bir gözlemdir; private state veya output schema kullanılmadığında bu alanlar dışarı sızabilir.

Çıktı Yorumu

Final state; giriş sorusunu, nihai cevabı ve ara notu birlikte döndürür. Bu, tek overall schema yaklaşımının dışarıya daha geniş state gösterebileceğini açık hale getirir.

Input ve output şemalarını ayrıştırma

Bu blok, dışarıdan alınan input şemasını, graph içinde kullanılan overall şemadan ve hedeflenen output şemasından ayırır. Amaç, kullanıcıya yalnızca gerekli giriş ve çıkış alanlarını açmaktır.

Input ve output şemalarını ayrıştırma
class InputState(TypedDict):
    """
    Define the state schema used by the graph.
    """
    question: str


class OutputState(TypedDict):
    """
    Define the state schema used by the graph.
    """
    answer: str


class OverallState(TypedDict):
    """
    Define the state schema used by the graph.
    """
    question: str
    answer: str
    notes: str


def thinking_node(state: InputState):
    """
    Run the thinking_node helper.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    return {"answer": "bye", "notes": "... his is name is Lance"}


def answer_node(state: OverallState) -> OutputState:
    """
    Run the answer_node helper.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    return {"answer": "bye Lance"}


graph = StateGraph(
    OverallState,
    input_schema=InputState,
    output_schema=OutputState,
)
graph.add_node("answer_node", answer_node)
graph.add_node("thinking_node", thinking_node)
graph.add_edge(START, "thinking_node")
graph.add_edge("thinking_node", "answer_node")
graph.add_edge("answer_node", END)

graph = graph.compile()

# View
display(Image(graph.get_graph().draw_mermaid_png()))

graph.invoke({"question": "hi"})

LangGraph açısından önemi

input_schema ve output_schema, overall state’i graph’ın iç belleği gibi bırakırken dış çağrı arayüzünü daha dar ve kontrollü hale getirmek için kullanılır.

Dikkat edilmesi gereken nokta

Görünen çalıştırma sonucu tüm state alanlarını göstermektedir. Bu farkın ortam ya da sürüm farkından doğup doğmadığı açıkça belirtilmiyor; bu nedenle çıktı değiştirilmeden korunmuştur.

Graph görseli
Python dict çıktısı
{'question': 'hi', 'answer': 'bye Lance', 'notes': '... his is name is Lance'}

Çıktı Yorumu

Bu blok hem graph görselini hem de çalıştırma sonucunu üretir. Sonuçta görünen alanların tamamı korunmuştur; dış output şemasının davranış farkı açıkça ayrıca sürümlendirilmemiştir.

Çıktıların Yorumlanması

Çıktılar üç ayrı fikri görünür kılar: private state final çıktıya taşınmaz, tek overall schema ara alanları da dışarı gösterebilir, input/output şemaları ise dış sözleşmeyi daraltmak için kullanılır. Görsel çıktılar graph topolojisini, terminal çıktıları node çalışma sırasını, dictionary çıktıları ise final state görünümünü doğrular.

Final ana kanal{"foo": 3}node_2 private değeri ana state’e geri yazar.
Soru akışı{"question": "hi", "answer": "bye Lance", "notes": "..."}Tek overall schema ara notu da final görünümde tutabilir.

Agent / Tool Etkileşimi

Bu derste agent döngüsü veya tool çağrısı kurulmaz. Buna rağmen çoklu schema mantığı agent graph’ları için doğrudan önemlidir: tool sonuçları, ara karar notları veya kullanıcıya gösterilmemesi gereken çalışma verileri private/internal state alanlarında tutulabilir.

Yaygın Hatalar

  • OverallState içindeki her alanın kullanıcıya gösterilmesi gerektiğini sanmak.
  • PrivateState alanlarını graph input’u gibi düşünmek.
  • Node dönüş tipinin yalnızca dekoratif olduğunu varsaymak; oysa hangi kanala yazıldığını belgeleyen kritik bir sözleşmedir.
  • input_schema ile output_schema farkını karıştırmak.
  • Graph compile edilmeden invoke çağırmaya çalışmak.
  • Tek overall schema kullanıldığında ara notların final çıktıda görünebileceğini gözden kaçırmak.
  • Çalıştırma çıktısındaki tüm alanları dış API tasarımı için zorunlu sanmak.

Son Çıkarımlar

  • LangGraph state’i tek bir dictionary değil, graph sözleşmesini taşıyan alanlar kümesidir.
  • Tek overall schema basit graph’larda yeterlidir, fakat dış arayüzü gereğinden genişletebilir.
  • PrivateState, ara hesaplamayı node’lar arasında taşırken final çıktıyı sade tutar.
  • Node parametre tipi okunan state sözleşmesini, dönüş tipi yazılan state sözleşmesini açıklar.
  • input_schema dış çağrı girdisini daraltır.
  • output_schema dışarıya verilmesi hedeflenen cevap alanlarını tanımlar.
  • add_edge şemaları değil, node çalışma sırasını belirler; şema davranışı node imzaları ve graph builder argümanlarıyla anlaşılır.
  • Graph görselleri topolojiyi gösterir; state alanlarının görünürlüğü ayrıca schema tasarımına bağlıdır.
  • Ara alanlar kullanıcıya gösterilmemeli ise private state veya output schema tasarımı erken düşünülmelidir.
