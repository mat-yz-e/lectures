LangGraph’ta Mesaj Geçmişi: Filtreleme ve Kırpma

Bu ders, uzun konuşma geçmişlerinde mesaj listesini nasıl yöneteceğimizi; eski mesajları state’ten silmeyi, modele gönderilen bağlamı daraltmayı ve token bütçesine göre kırpmayı teknik olarak açıklar.

Kapsam ve Bağlam

Chatbot ve agent graph’larında state’in en önemli parçalarından biri mesaj geçmişidir. Konuşma uzadıkça bu geçmiş model çağrısına daha fazla token taşır; bu da gecikme, maliyet ve context window sınırı problemlerini büyütür. Bu derste amaç, LangGraph içinde mesaj geçmişini yönetmenin üç düzeyini ayırmaktır: state listesinden eski mesajları silmek, state’i koruyup yalnızca modele giden listeyi daraltmak ve token bütçesine göre otomatik kırpma yapmak.

Bu Dersin Ana Tezi

MessagesState konuşma geçmişini taşır; fakat her çalıştırmada tüm geçmişi modele göndermek zorunda değildir. RemoveMessage state listesini azaltır, liste slice işlemleri model input’unu daraltır, trim_messages ise token bütçesine göre daha kontrollü bir kırpma kuralı sağlar.

Öğrenme Hedefleri

  • AIMessage ve HumanMessage nesneleriyle mesaj geçmişi kurmak.
  • MessagesState kullanarak mesaj listesini LangGraph state’i içinde taşımak.
  • RemoveMessage ile eski mesajları id tabanlı silme update’i olarak ifade etmek.
  • State listesini değiştirmek ile yalnızca model input’unu daraltmak arasındaki farkı açıklamak.
  • trim_messages fonksiyonunun max_tokens, strategy, token_counter ve allow_partial parametrelerini yorumlamak.
  • Uzun konuşma geçmişlerinde token bütçesi, latency ve maliyet ilişkisini teknik olarak değerlendirmek.

Ön Koşullar

Bu ders için Python listeleri, dictionary yapısı, fonksiyon tanımı, type hint okuma ve temel LLM mesaj kavramları bilinmelidir. LangGraph tarafında StateGraph, node, edge, MessagesState, reducer ve invoke kavramlarının temel düzeyde anlaşılması yeterlidir. Model çağrıları için API anahtarının ortam değişkeni olarak ayarlanması gerekir.

Bu derste mesaj yönetimi, graph topolojisinden çok node içindeki input hazırlama mantığıyla ilgilidir. Aynı MessagesState kanalında uzun bir geçmiş tutulabilir; fakat chat model node’u bu geçmişin tamamını, son birkaç mesajını veya token bütçesine göre kırpılmış alt listesini kullanabilir.

Ana Anlatım

Mesaj Geçmişi Neden Yönetilmelidir?

Bir chat graph’ı kısa bir konuşmada tüm mesajları modele gönderebilir. Ancak uzun süreli agent akışlarında onlarca mesaj birikir. Her model çağrısı bu geçmişi yeniden token olarak taşırsa maliyet, gecikme ve context sınırı problemi oluşur.

State’i Silmek ve Model Input’unu Daraltmak

RemoveMessage, graph state’indeki mesaj listesini gerçekten azaltır. Buna karşılık state["messages"][-1:] gibi bir slice yalnızca modele gönderilen listeyi azaltır; state’in kendisi korunabilir. Bu iki yaklaşım farklı tasarım kararlarıdır.

Token Bütçesine Göre Kırpma

trim_messages, sabit sayıda mesaj seçmek yerine token sayımıyla çalışır. Bu, model context window sınırlarını dikkate alan daha genel bir yöntemdir. strategy="last" en yeni mesajları öncelemeyi, allow_partial=False ise mesajları ortadan kesmemeyi ifade eder.

from langgraph.graph import MessagesState
from langgraph.graph import StateGraph, START, END


# Node
def chat_model_node(state: MessagesState):
    """
    Run the chat_model_node graph node.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    return {"messages": llm.invoke(state["messages"])}


# Build graph
builder = StateGraph(MessagesState)
builder.add_node("chat_model", chat_model_node)
builder.add_edge(START, "chat_model")
builder.add_edge("chat_model", END)

RemoveMessage ile eski mesajları filtreleyen graph kurma

Bu blok, RemoveMessage nesneleriyle eski mesajları state’ten silen bir filtre node’u ekler.

RemoveMessage ile eski mesajları filtreleyen graph kurma
from langchain_core.messages import RemoveMessage


# Nodes
def filter_messages(state: MessagesState):
    """
    Run the filter_messages graph node.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    # Delete all but the 2 most recent messages
    delete_messages = [
        RemoveMessage(id=m.id) for m in state["messages"][:-2]
    ]
    return {"messages": delete_messages}


def chat_model_node(state: MessagesState):
    """
    Run the chat_model_node graph node.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    return {"messages": [llm.invoke(state["messages"])]}


# Build graph
builder = StateGraph(MessagesState)
builder.add_node("filter", filter_messages)
builder.add_node("chat_model", chat_model_node)
builder.add_edge(START, "filter")
builder.add_edge("filter", "chat_model")
builder.add_edge("chat_model", END)
graph = builder.compile()

# View
display(Image(graph.get_graph().draw_mermaid_png()))

It can grow up to 10 feet (3 meters) long and is usually found in males, though some females may also develop smaller tusks. The tusk grows in a spiral pattern and is thought to have sensory capabilities, with millions of nerve endings.

- **Weight**: They can weigh between 1,760 to 3,530 pounds (800 to 1,600 kilograms).

### Habitat and Distribution
- Narwhals are native to the Arctic waters of Canada, Greenland, Norway, and Russia. They are especially common in the Baffin Bay and the waters surrounding Greenland.

- **Diving**: Narwhals are deep divers and can reach depths of up to 5,000 feet (1,500 meters) in search of food. They can hold their breath for up to 25 minutes.

Overall, narwhals are remarkable creatures with unique adaptations that allow them to thrive in some of the planet's harshest environments.

def chat_model_node(state: MessagesState):
    """
    Run the chat_model_node graph node.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.

Yaygın Hatalar

  • MessagesState içindeki tüm geçmişin her zaman modele gönderildiğini sanmak.
  • RemoveMessage nesnesini normal model mesajı gibi düşünmek.
  • Mesajlarda id yokken id tabanlı silme davranışına güvenmek.
  • State listesini silmek ile yalnızca model input’unu slice etmek arasındaki farkı kaçırmak.
  • trim_messages sonucunu model cevabı sanmak; bu fonksiyon yalnızca mesaj listesi döndürür.
  • allow_partial=False kullanıldığında kırpılmış sonucun beklenenden kısa olabileceğini gözden kaçırmak.
  • Token bütçesi küçük olduğunda önceki uzun cevabın tamamen atılabileceğini hesaba katmamak.
  • API anahtarını kod içine açık metin olarak yazmak.

Son Çıkarımlar

  • Uzun konuşma geçmişi token maliyeti ve gecikme üretir.
  • MessagesState, mesaj geçmişini graph state’i olarak taşır.
  • AIMessage ve HumanMessage mesaj rollerini standartlaştırır.
  • RemoveMessage, id tabanlı silme update’i üretir.
  • Silme update’i, MessagesState reducer’ı tarafından uygulanır.
  • Model input’unu slice etmek state’i silmekten farklıdır.

  • allow_partial=False, mesajların ortadan kesilmesini engeller.
