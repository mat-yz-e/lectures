LangGraph’ta State Reducer’lar: Paralel Güncellemeleri Güvenli Birleştirme

Bu ders, LangGraph state alanlarının varsayılan olarak nasıl güncellendiğini, paralel node çıktılarında neden çatışma oluştuğunu ve reducer fonksiyonlarının bu çatışmayı nasıl açık, denetlenebilir bir güncelleme kuralına dönüştürdüğünü açıklar.

Kapsam ve Bağlam

Bu bölümde amaç, LangGraph state’inin yalnızca bir Python sözlüğü gibi taşınmadığını; aynı zamanda graph yürütmesi sırasında güncellenme kurallarına sahip bir veri kanalı olduğunu kavramaktır. Basit bir graph’ta tek node aynı alanı güncellediğinde sonuç sezgiseldir. Ancak graph dallanıp birden fazla node aynı state alanına aynı yürütme adımında değer yazdığında, “hangi değer kazanmalı?” sorusu açık bir tasarım kararına dönüşür.

Bu Dersin Ana Tezi

Reducer, LangGraph’ta paralel veya ardışık güncellemelerin aynı state alanında nasıl birleştirileceğini tanımlayan açık ve denetlenebilir sözleşmedir. Reducer yoksa aynı key’e gelen birden fazla değer belirsizlik üretir; reducer varsa graph bu değerleri belirlenen kurala göre final state’e taşır.

Öğrenme Hedefleri

  • Reducer tanımlanmamış state alanlarında varsayılan overwrite davranışını açıklayabilmek.
  • Paralel branch’lerde aynı state key’ine yazıldığında neden güncelleme hatası oluştuğunu yorumlayabilmek.
  • Annotated ile state alanına reducer bağlayabilmek.
  • operator.add ve özel reducer fonksiyonları arasındaki farkı teknik olarak ayırt edebilmek.
  • None gibi sınır değerlerde reducer’ın veri normalizasyonu sorumluluğunu değerlendirebilmek.
  • MessagesState, AnyMessage, add_messages ve RemoveMessage ilişkisini mesaj state’i bağlamında açıklayabilmek.

Ön Koşullar

Bu dersi izlemek için Python fonksiyonları, sözlük ve liste veri yapıları, type hint kullanımı, basit exception handling ve sınıf tanımı konularına aşina olmak gerekir. LangGraph tarafında StateGraph, node, edge, START, END ve compile kavramlarını temel düzeyde bilmek yeterlidir.

Büyük Resim

LangGraph graph’ı state’i adım adım dönüştürür. Tek node tek alanı güncellediğinde bu dönüşüm basittir. Fakat graph dallandığında iki node aynı state alanına aynı anda katkı yapabilir. Reducer bu katkıların nasıl birleştirileceğini tanımlar.

Başlangıç state’iGraph’a foo alanı ile veri girer.
Node update’iNode yalnızca kısmi state döndürür.
Paralel branchBirden çok node aynı key’e yazabilir.
ReducerMevcut değer ile yeni değer birleştirilir.
Final stateGraph açık merge kuralıyla kapanır.

Ana Anlatım

State alanları reducer olmadan kullanıldığında LangGraph her key için tek güncelleme bekler. Bu model, lineer graph’larda genellikle yeterlidir. Paralel graph’larda ise aynı key’e birden fazla node değer döndürdüğünde LangGraph bu durumu belirsiz kabul eder ve hatayla görünür kılar. Bu davranış, rastgele bir sonucun seçilmesini engellediği için önemlidir.

Reducer’ın zihinsel modeli

Reducer iki değer alır: mevcut birikmiş değer ve yeni update. Çıktısı yine aynı state alanına yazılacak tek değerdir. Bu nedenle reducer, hem veri formatını hem de merge semantiğini açıkça tanımlar.

Mesaj state’i özel bir durumdur. Bir agent geçmişinde yeni mesaj eklemek, mevcut mesajı id ile güncellemek veya belirli mesajı silmek aynı liste alanı üzerinde gerçekleşir. add_messages bu üç davranışı tek reducer protokolünde toplar.

Varsayılan overwrite davranışını kurma

Bu blok, tek alanlı bir state şeması ve tek node’lu graph kurar. Amaç, reducer tanımlanmadan önce LangGraph’ın aynı key için varsayılan davranışını gözlemlemektir.

Varsayılan overwrite davranışını kurma
from typing_extensions import TypedDict
from IPython.display import Image, display
from langgraph.graph import StateGraph, START, END

class State(TypedDict):
    """
    Define the state schema used by the graph.
    """
    foo: int

def node_1(state):
    """
    Run the node_1 helper.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    print("---Node 1---")
    return {"foo": state['foo'] + 1}

# Build graph
builder = StateGraph(State)
builder.add_node("node_1", node_1)

# Logic
builder.add_edge(START, "node_1")
builder.add_edge("node_1", END)

# Add
graph = builder.compile()

# View
display(Image(graph.get_graph().draw_mermaid_png()))

Annotated ile reducer tanımlama

Bu blok, `Annotated` ile `foo` alanına liste birleştirme reducer’ı bağlar. LangGraph artık bu alanı yalnızca overwrite edilecek bir değer değil, birleştirilecek bir kanal gibi ele alır.

Annotated ile reducer tanımlama
from operator import add
from typing import Annotated

class State(TypedDict):
    """
    Define the state schema used by the graph.
    """
    foo: Annotated[list[int], add]

    """
    Run the node_1 helper.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    print("---Node 1---")
    return {"foo": [state['foo'][0] + 1]}

# Build graph
builder = StateGraph(State)
builder.add_node("node_1", node_1)

# Logic
builder.add_edge(START, "node_1")
builder.add_edge("node_1", END)

# Add
graph = builder.compile()

# View
display(Image(graph.get_graph().draw_mermaid_png()))

Özel reducer fonksiyonu tanımlama

Bu blok, `None` değerlerini boş liste kabul eden özel bir reducer tanımlar ve bu reducer’ı state alanına bağlar.

Özel reducer fonksiyonu tanımlama
def reduce_list(left: list | None, right: list | None) -> list:
    """Safely combine two lists.

    Handles cases where either or both inputs might be None.

    Args:
        left (list | None): The first list to combine, or None.
        right (list | None): The second list to combine, or None.

    Returns:
        list: A new list containing all elements from both input lists.
               If an input is None, it's treated as an empty list.
    """
    if not left:
        left = []
    if not right:
        right = []
    return left + right

class DefaultState(TypedDict):
    """
    Define the state schema used by the graph.
    """
    foo: Annotated[list[int], add]

class CustomReducerState(TypedDict):
    """
    Define the state schema used by the graph.
    """
    foo: Annotated[list[int], reduce_list]

Çıktıların Yorumlanması

Çıktılar üç ana davranışı görünür kılar: reducer yokken overwrite ve çatışma, reducer varken liste biriktirme, mesaj reducer’ında append/update/delete semantiği. Hata çıktıları bu derste başarısızlık olarak değil, state merge sözleşmesinin neden gerekli olduğunu gösteren gözlem noktaları olarak ele alınmalıdır.

Çıktı TürüNe Gösterir?Teknik Sonuç
Graph görselleriNode ve edge topolojisini gösterir.State güncellemesinin hangi akış içinde üretildiği anlaşılır.
Terminal satırlarıHangi node’un çalıştığını gösterir.Paralel branch’lerde birden fazla node’un aynı step’e katkı verdiği okunur.
Dict çıktılarıFinal state değerini gösterir.Reducer sonucunun state alanına nasıl yazıldığı doğrulanır.

Graph Akışı

STARTBaşlangıç state’i graph’a girer.
node_1İlk güncelleme üretilir ve branch’ler açılır.
node_2 / node_3İki branch aynı foo alanına katkı yapar.
reducerGelen liste güncellemeleri birleştirilir.
ENDBirleştirilmiş final state döner.

State’in Evrimi

Overwrite örneği{"foo": 1} girdisi, tek node sonrasında {"foo": 2} olur.
Reducer’sız paralelliknode_2 ve node_3 aynı key’e yazınca merge kuralı olmadığı için hata oluşur.
Liste reducer’ı{"foo": [1]} girdisi, node update’iyle {"foo": [1, 2]} haline gelir.
Paralel liste birikimiBranch’lerden gelen değerler final state’te [1, 2, 3, 3] biçiminde toplanır.
Custom reducerNone başlangıç değeri boş listeye çevrilir ve [2] sonucu üretilir.
Mesaj reducer’ıMesajlar id değerine göre eklenir, güncellenir veya silinir.

Agent / Tool Etkileşimi

Bu derste doğrudan tool çalıştıran bir agent döngüsü kurulmaz. Buna rağmen MessagesState ve add_messages örnekleri agent graph’larının temel zeminini hazırlar. Çünkü tool kullanan agent’larda model mesajları, tool çağrıları, tool sonuçları ve insan mesajları çoğunlukla aynı messages state alanında birikir.

Yaygın Hatalar

  • Reducer’ı yalnızca liste ekleme kolaylığı sanmak; aslında reducer state merge sözleşmesidir.
  • Paralel branch’lerde aynı key’e yazmanın otomatik olarak güvenli olduğunu varsaymak.
  • Annotated içindeki ikinci argümanın tip değil, reducer metadata’sı olduğunu gözden kaçırmak.
  • operator.add reducer’ının None değerlerini otomatik temizleyeceğini düşünmek.
  • Node fonksiyonunun tüm state’i döndürmesi gerektiğini sanmak; çoğu durumda kısmi update yeterlidir.
  • add_messages içinde aynı id değerinin append değil update davranışı doğurduğunu unutmak.
  • RemoveMessage nesnesini normal mesaj içeriği gibi düşünmek; bu nesne reducer için silme talimatıdır.

Son Çıkarımlar

  1. LangGraph state alanları varsayılan olarak tek güncelleme bekler.
  2. Paralel branch’lerde aynı key’e yazılıyorsa reducer tasarımı zorunlu hale gelir.
  3. Annotated, reducer’ı state şemasına bağlamanın temel yoludur.
  4. Reducer iki argüman alır: mevcut değer ve yeni değer.
  5. Hazır reducer’lar pratik olsa da sınır değerleri her zaman kapsamayabilir.
  6. Özel reducer, veri normalizasyonunu ve merge politikasını açık hale getirir.
  7. Graph topolojisi ile state merge davranışı birlikte tasarlanmalıdır.
  8. Mesaj state’i için add_messages append, update ve delete davranışlarını bir arada sağlar.
  9. Hata çıktıları, reducer ihtiyacını teşhis etmek için öğretici sinyallerdir.
  10. Agent graph’larında güvenilir mesaj geçmişi için reducer semantiği kritik önemdedir.

def reduce_list(left: list | None, right: list | None) -> list:
    """Safely combine two lists.

    Handles cases where either or both inputs might be None.

    Args:
        left (list | None): The first list to combine, or None.
        right (list | None): The second list to combine, or None.

    Returns:
        list: A new list containing all elements from both input lists.
               If an input is None, it's treated as an empty list.
    """
    if not left:
        left = []
    if not right:
        right = []
    return left + right
