LangGraph’ta State Schema: TypedDict, Dataclass ve Pydantic ile Durum Modelleme

Bu ders, LangGraph graph’larında state yapısının nasıl tanımlandığını, farklı Python şema yaklaşımlarının graph davranışına nasıl bağlandığını ve runtime validation ihtiyacının nerede ortaya çıktığını teknik olarak açıklar.

Kapsam ve Bağlam

Bu bölümde amaç, LangGraph içinde state’in yalnızca geçici bir Python değişkeni olmadığını; graph boyunca taşınan, node’lar tarafından okunan ve kısmi güncellemelerle değiştirilen merkezi veri sözleşmesi olduğunu netleştirmektir. Bir graph inşa edilirken verilen state schema, her node’un hangi alanlarla çalışacağını ve bu alanların hangi tipte düşünülmesi gerektiğini belirler.

Bu Dersin Ana Tezi

LangGraph’ta state schema, graph’ın veri arayüzüdür. `TypedDict`, `dataclass` ve `Pydantic` aynı graph topolojisini taşıyabilir; ancak okunabilirlik, erişim biçimi ve runtime validation açısından farklı mühendislik sonuçları doğurur.

Öğrenme Hedefleri

  • State schema kavramını graph’ın veri sözleşmesi olarak açıklayabilmek.
  • `TypedDict`, `dataclass` ve `Pydantic` tabanlı state tanımlarını karşılaştırabilmek.
  • Node fonksiyonlarının state’i nasıl okuyup partial dictionary ile nasıl güncellediğini yorumlayabilmek.
  • `add_conditional_edges` ile karar fonksiyonunun graph akışını nasıl değiştirdiğini takip edebilmek.
  • Runtime validation ihtiyacının nerede ortaya çıktığını ve Pydantic’in bu problemi nasıl çözdüğünü gösterebilmek.

Ön Koşullar

  • Python dictionary, class, decorator ve type hint sözdizimine aşinalık.
  • `TypedDict`, `Literal` ve `dataclass` kavramlarını okuyabilecek düzeyde Python bilgisi.
  • LangGraph’ta `StateGraph`, node, edge, `START`, `END`, `compile` ve `invoke` kavramlarına temel aşinalık.
  • Pydantic hakkında temel sezgi: model alanları, validation ve hata yakalama.

Ana Anlatım

State Schema Bir Veri Sözleşmesidir

`StateGraph` oluştururken verilen schema, graph’ın hangi veriyi taşıyacağını belirler. Bu schema node fonksiyonlarının anlaşmasını sağlar: node state’i beklenen biçimde okur ve güncellemek istediği alanları döndürür.

TypedDict: Esnek ve Hafif

`TypedDict`, dictionary tabanlı state için pratik bir çözümdür. Anahtar adları ve değer tipleri görünür olur; fakat runtime’da bu tiplerin otomatik olarak zorlanmadığı unutulmamalıdır.

Dataclass: Attribute Tabanlı Erişim

`dataclass`, state’i veri taşıyan bir nesne olarak sunar. Bu durumda `state["name"]` yerine `state.name` kullanılır. Buna rağmen node dönüşleri hâlâ dictionary olabilir; çünkü LangGraph state alanlarını ayrı channel’lar olarak güncelleyebilir.

Pydantic: Runtime Validation

Pydantic, state şemasını doğrulanabilir bir modele dönüştürür. Geçersiz `mood` değeri gibi durumlar graph’ın içine sessizce taşınmak yerine hata olarak yakalanabilir.

TypedDict ile temel state şeması tanımlama

Bu blok, state’in bir dictionary gibi taşınacağını ama anahtarların tip ipuçlarıyla belirleneceğini gösterir.

TypedDict ile temel state şeması tanımlama
from typing_extensions import TypedDict


class TypedDictState(TypedDict):
    """
    Define the state schema used by the graph.
    """
    foo: str
    bar: str

LangGraph açısından önemi

`TypedDictState`, graph’ın hangi state anahtarlarını beklediğini görünür hale getirir. Bu anahtarlar graph içinde channel gibi düşünülebilir.

Dikkat edilmesi gereken nokta

`TypedDict` tip ipucu sağlar; Python runtime’da değerlerin gerçekten bu tipe uyduğunu tek başına zorlamaz.

Literal ile değer kümesini daraltma

Bu blok, state içindeki `mood` alanının yalnızca belirli string değerleriyle düşünülmesini sağlar.

Literal ile değer kümesini daraltma
from typing import Literal


class TypedDictState(TypedDict):
    """
    Define the state schema used by the graph.
    """
    name: str
    mood: Literal["happy", "sad"]

LangGraph açısından önemi

`Literal` alanın beklenen değer uzayını dokümante eder; graph karar fonksiyonlarında hangi değerlerin anlamlı olduğunu netleştirir.

Dikkat edilmesi gereken nokta

`Literal` statik tip kontrolünde güçlüdür, fakat bu derste gösterildiği gibi her şema yaklaşımı runtime validation sağlamaz.

TypedDictState ile conditional graph kurma

Bu blok, `TypedDictState` şemasını `StateGraph` içine verir, üç node tanımlar ve `decide_mood` fonksiyonu ile koşullu yönlendirme kurar.

TypedDictState ile conditional graph kurma
import random
from IPython.display import Image, display
from langgraph.graph import END, START, StateGraph


def node_1(state):
    """
    Run the node_1 helper.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    print("---Node 1---")
    return {"name": state["name"] + " is ... "}


def node_2(state):
    """
    Run the node_2 helper.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    print("---Node 2---")
    return {"mood": "happy"}


def node_3(state):
    """
    Run the node_3 helper.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    print("---Node 3---")
    return {"mood": "sad"}


def decide_mood(state) -> Literal["node_2", "node_3"]:
    """
    Choose the next graph route for decide_mood.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    # Here, let's just do a 50 / 50 split between nodes 2, 3
    if random.random() < 0.5:
        # 50% of the time, we return Node 2
        return "node_2"

    # 50% of the time, we return Node 3
    return "node_3"


# Build graph
builder = StateGraph(TypedDictState)
builder.add_node("node_1", node_1)
builder.add_node("node_2", node_2)
builder.add_node("node_3", node_3)

# Logic
builder.add_edge(START, "node_1")
builder.add_conditional_edges("node_1", decide_mood)
builder.add_edge("node_2", END)
builder.add_edge("node_3", END)

# Add
graph = builder.compile()

# View
display(Image(graph.get_graph().draw_mermaid_png()))

LangGraph açısından önemi

Dataclass ile state şeması tanımlama

Bu blok, aynı state alanlarını Python `dataclass` yapısıyla tanımlar. Amaç, state’in yalnızca dictionary tabanlı olmak zorunda olmadığını göstermektir.

Dataclass ile state şeması tanımlama
from dataclasses import dataclass


@dataclass
class DataclassState:
    """
    Define the state schema used by the graph.
    """
    name: str
    mood: Literal["happy", "sad"]

LangGraph açısından önemi

Dikkat edilmesi gereken nokta

`dataclass` da tip ipuçlarını runtime’da otomatik doğrulamaz; geçersiz değer ataması hata üretmeyebilir.

Pydantic ile runtime validation tanımlama

Bu blok, state alanlarını Pydantic modelinde tanımlar ve `mood` alanı için runtime doğrulaması ekler.

Pydantic ile runtime validation tanımlama
from pydantic import BaseModel, field_validator, ValidationError


class PydanticState(BaseModel):
    """
    Define the state schema used by the graph.
    """
    name: str
    mood: str  # "happy" or "sad"

    @field_validator("mood")
    @classmethod
    def validate_mood(cls, value):
        """
        Run the validate_mood helper.

        Args:
            value: Value passed as value.

        Returns:
            Value produced for the surrounding example.
        """
        # Ensure the mood is either "happy" or "sad"
        if value not in ["happy", "sad"]:
            raise ValueError("Each mood must be either 'happy' or 'sad'")
        return value


try:
    state = PydanticState(name="John Doe", mood="mad")
except ValidationError as e:
    print("Validation Error:", e)

Pydantic, state şemasını yalnızca belgeleyen bir yapı olmaktan çıkarıp çalışma zamanında doğrulanan bir sözleşmeye dönüştürür.

Bu derste gerçek state alanları `name` ve `mood` olarak izlenir. Graph yürütmesi boyunca node’lar tüm state’i yeniden üretmek zorunda değildir; yalnızca değiştirdikleri alanları döndürür.

Agent / Tool Etkileşimi

Bu derste doğrudan agent-tool döngüsü kurulmaz. Ancak agent sistemlerinin güvenilir çalışması için state schema kritik önemdedir: tool çıktıları, model mesajları ve ara kararlar ilerleyen derslerde yine state alanları üzerinden taşınacaktır.

Yaygın Hatalar

  • `TypedDict` tip ipuçlarının runtime’da otomatik doğrulandığını sanmak.
  • Dataclass state kullanırken `state["name"]` biçiminde dictionary erişimi beklemek.
  • Node dönüşünün tüm state’i içermesi gerektiğini düşünmek; çoğu durumda partial update yeterlidir.
  • `add_conditional_edges` dönüş değerlerinin graph node adlarıyla uyumlu olması gerektiğini unutmak.
  • `compile()` çağrısından önce graph’ı çalıştırmaya çalışmak.
  • Pydantic validation’ı yalnızca dokümantasyon zannetmek; asıl farkı runtime’da hata üretmesidir.
  • Rastgele routing kullanılan örneklerde her çalıştırmada aynı output’u beklemek.

Son Çıkarımlar

  • State schema, LangGraph graph’ının veri arayüzüdür.
  • State içindeki her anahtar ayrı bir channel gibi düşünülebilir.
  • `TypedDict` hafif ve kullanışlıdır, fakat runtime validation sağlamaz.
  • `Literal`, izin verilen değerleri tip seviyesinde ifade eder.
  • `dataclass`, attribute tabanlı state erişimi sağlar.
  • LangGraph node’ları partial dictionary döndürerek state alanlarını güncelleyebilir.
  • `add_conditional_edges`, karar fonksiyonunun dönüşüne göre graph yönünü seçer.
  • Pydantic, state değerlerini runtime’da doğrulamak için güçlü bir seçenektir.
  • Geçersiz state değerlerini erken yakalamak agent sistemlerinde güvenilirliği artırır.
  • Aynı graph topolojisi farklı state schema temsilleriyle kurulabilir.

from langgraph.graph import END, START, StateGraph


def node_1(state):
    """
    Run the node_1 helper.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    print("---Node 1---")
    return {"name": state["name"] + " is ... "}


def node_2(state):
    """
    Run the node_2 helper.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    print("---Node 2---")
    return {"mood": "happy"}


def node_3(state):
    """
    Run the node_3 helper.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    print("---Node 3---")
    return {"mood": "sad"}


def decide_mood(state) -> Literal["node_2", "node_3"]:
    """
    Choose the next graph route for decide_mood.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    # Here, let's just do a 50 / 50 split between nodes 2, 3
    if random.random() < 0.5:
        # 50% of the time, we return Node 2
        return "node_2"

    # 50% of the time, we return Node 3
    return "node_3"

builder.add_node("node_2", node_2)
builder.add_node("node_3", node_3)

builder.add_conditional_edges("node_1", decide_mood)
builder.add_edge("node_2", END)
builder.add_edge("node_3", END)

from pydantic import BaseModel, field_validator, ValidationError


class PydanticState(BaseModel):
    """
    Define the state schema used by the graph.
    """
    name: str
    mood: str  # "happy" or "sad"

    @field_validator("mood")
    @classmethod
    def validate_mood(cls, value):
        """
        Run the validate_mood helper.

        Args:
            value: Value passed as value.

        Returns:
            Value produced for the surrounding example.
        """
        # Ensure the mood is either "happy" or "sad"
        if value not in ["happy", "sad"]:
            raise ValueError("Each mood must be either 'happy' or 'sad'")
        return value


try:
    state = PydanticState(name="John Doe", mood="mad")
except ValidationError as e:
    print("Validation Error:", e)
