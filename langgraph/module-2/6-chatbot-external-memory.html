Harici Veritabanı Belleği ile Kalıcı Chatbot State’i

Bu ders, özetlemeli chatbot state’inin yalnızca geçici oturum belleğinde değil, SQLite tabanlı harici bir checkpointer üzerinden kalıcı biçimde nasıl sürdürülebileceğini açıklar.

Kapsam ve Bağlam

Bu bölümde amaç, özetlemeli bir chatbot’un belleğini yalnızca çalışma sürecinin belleğine bağlı bırakmadan, harici bir veritabanı üzerinden sürdürebilmektir. Önceki yaklaşımda konuşma state’i bir checkpointer ile korunur; ancak bu koruma süreç sonlandığında veya geliştirme oturumu yeniden başlatıldığında kaybolabilir. Buradaki ana fikir, aynı LangGraph state sözleşmesini korurken checkpointer katmanını SQLite tabanlı hale getirmektir.

Bu Dersin Ana Tezi

LangGraph’ta uzun süreli chatbot belleği, yalnızca mesaj özetleme tekniğiyle değil, state’i thread bazlı olarak harici bir checkpointer’a yazmakla güvenilir hale gelir. SQLite, bu fikri yerel ve anlaşılır bir veritabanı üzerinden göstermek için uygun bir başlangıç noktasıdır.

Öğrenme Hedefleri

  • In-memory checkpointer ile dosya tabanlı SQLite checkpointer arasındaki farkı açıklayabilecek.
  • SqliteSaver nesnesinin graph compile aşamasında nasıl kullanıldığını gösterebilecek.
  • thread_id değerinin aynı konuşma state’ine erişimde neden kritik olduğunu yorumlayabilecek.
  • Özetleme node’u, mesaj silme işlemi ve kalıcı checkpoint ilişkisini kod üzerinden takip edebilecek.
  • graph.get_state(config) ile kalıcı state’in nasıl incelendiğini açıklayabilecek.
  • Studio/API ortamındaki yerleşik kalıcılık fikrini etkileşimli çalışma ortamındaki SQLite örneğiyle ilişkilendirebilecek.

Ön Koşullar

  • Python fonksiyonları, dictionary ve list yapıları.
  • Type hint kullanımı ve Literal tür ipucu.
  • LLM mesaj nesneleri: HumanMessage, SystemMessage, RemoveMessage.
  • LangGraph’ta StateGraph, node, edge ve compile mantığı.
  • Ortam değişkeni ile API anahtarı okuma yaklaşımı.
  • SQLite bağlantısının dosya tabanlı veya bellek içi çalışabileceğine dair temel sezgi.

Büyük Resim

Bu derste iki ayrı problem aynı graph içinde birleşir. Birinci problem, konuşma geçmişinin token maliyetini kontrol altında tutmaktır; bu amaçla eski mesajlar özetlenir ve state içinde summary alanı tutulur. İkinci problem, bu state’in geliştirme oturumu bittikten sonra da geri yüklenebilmesidir; bu amaçla SQLite tabanlı checkpointer kullanılır.

Ana Anlatım

Geçici Bellekten Kalıcı Belleğe Geçiş

In-memory checkpointer, graph state’ini çalışma süreci boyunca tutar. Bu, öğrenme ve hızlı deneme için yeterlidir; fakat süreç yeniden başlatıldığında geçmiş state silinir. Harici veritabanı checkpointer’ı ise state’i belleğin dışına taşır. Bu nedenle aynı graph yeniden derlense bile aynı thread_id üzerinden önceki state’e erişilebilir.

Kalıcı Belleğin Sınırı

SQLite checkpointer state’i diskte saklar; ancak modelin nasıl cevap vereceğini sabitlemez. Kalıcılık, konuşma state’inin saklanmasıyla ilgilidir. LLM çağrısının içeriği, gönderilen mesajlar ve model davranışı tarafından belirlenir.

Özetleme ve Checkpoint Birlikte Nasıl Çalışır?

Özetleme node’u, mesaj sayısı belirli bir eşiği aştığında eski mesajları sıkıştırır. RemoveMessage nesneleri eski mesajların state’ten çıkarılmasını ifade ederken, summary alanı uzun konuşmanın kısa temsilini korur. Checkpointer bu güncellenmiş state’i thread kimliğiyle saklar.

Model ve state şemasını tanımlama

Bu blok chatbot’un kullanacağı modeli ve summary alanı eklenmiş state şemasını tanımlar.

Model ve state şemasını tanımlama 
from typing_extensions import Literal

from langchain_core.messages import HumanMessage, RemoveMessage, SystemMessage
from langchain_openai import ChatOpenAI
from langgraph.graph import END, MessagesState


model = ChatOpenAI(model="gpt-4o", temperature=0)


class State(MessagesState):
    """
    Define the state schema used by the graph.
    """
    summary: str

MessagesState mesaj listesini taşır; State sınıfı buna özet alanı ekleyerek graph state sözleşmesini genişletir.

Model çağrısı node’unu yazma

Bu node varsa önceki konuşma özetini system mesajı olarak yeni mesajların önüne ekler ve modeli çağırır.

Model çağrısı node’unu yazma 
# Define the logic to call the model
def call_model(state: State):
    """
    Run the call_model graph node.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    # Get summary if it exists
    summary = state.get("summary", "")

    # If there is summary, then we add it
    if summary:
        # Add summary to system message
        system_message = f"Summary of conversation earlier: {summary}"

        # Append summary to any newer messages
        messages = [SystemMessage(content=system_message)] + state["messages"]
    else:
        messages = state["messages"]

    response = model.invoke(messages)
    return {"messages": response}

LangGraph açısından önemi

Model node’u state’i doğrudan değiştirmek yerine {"messages": response} güncellemesi döndürür. LangGraph bu güncellemeyi state sözleşmesine göre işler.

Dikkat edilmesi gereken nokta

Özetin system mesajı olarak eklenmesi kalıcı state’teki mesaj listesini değiştirmek zorunda değildir; burada amaç modele gönderilen bağlamı zenginleştirmektir.

Konuşmayı özetleyen node’u yazma

Bu node mevcut özet varsa onu genişletir, yoksa konuşma için yeni bir özet üretir. Ardından yalnızca son iki mesajı koruyacak şekilde eski mesajların kaldırılmasını ister.

Konuşmayı özetleyen node’u yazma 
def summarize_conversation(state: State):
    """
    Run the summarize_conversation graph node.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    # First, we get any existing summary
    summary = state.get("summary", "")

    # Create our summarization prompt
    if summary:
        # A summary already exists
        summary_message = (
            f"This is summary of the conversation to date: {summary}\n\n"
            "Extend the summary by taking into account the new messages above:"
        )
    else:
        summary_message = "Create a summary of the conversation above:"

    # Add prompt to our history
    messages = state["messages"] + [HumanMessage(content=summary_message)]
    response = model.invoke(messages)

    # Delete all but the 2 most recent messages
    delete_messages = [RemoveMessage(id=m.id) for m in state["messages"][:-2]]
    return {"summary": response.content, "messages": delete_messages}

LangGraph açısından önemi

RemoveMessage kullanımı, message reducer semantiğiyle uyumlu şekilde eski mesajları state’ten temizlerken summary alanını günceller.

Dikkat edilmesi gereken nokta

Mesajları Python listesi üzerinde doğrudan silmekle RemoveMessage döndürmek aynı şey değildir. LangGraph state güncellemesinde bu özel nesnenin anlamı vardır.

Özetleme kararını veren routing fonksiyonu

Bu fonksiyon konuşma mesajlarının sayısına bakar. Eşik aşılırsa özetleme node’una, aksi durumda graph bitişine yönlendirir.

Özetleme kararını veren routing fonksiyonu 
# Determine whether to end or summarize the conversation
def should_continue(state: State) -> Literal["summarize_conversation", END]:
    """Return the next node to execute."""

    messages = state["messages"]

    # If there are more than six messages, then we summarize the conversation
    if len(messages) > 6:
        return "summarize_conversation"

    # Otherwise we can just end
    return END

LangGraph açısından önemi

Conditional edge için routing kararını üretir. Böylece graph, sabit tek akış yerine state’e bağlı bir karar noktası kazanır.

Dikkat edilmesi gereken nokta

Eşik değeri uygulama tercihidir. Burada altı mesajdan sonra özetleme yapılır; bu değer token bütçesi ve kullanıcı deneyimine göre değiştirilebilir.

Graph’ı SQLite checkpointer ile derleme

Bu blok node’ları ve edge’leri graph içinde birleştirir, ardından SQLite checkpointer ile compile eder.

Graph’ı SQLite checkpointer ile derleme 
from IPython.display import Image, display
from langgraph.graph import START, StateGraph

# Define a new graph
workflow = StateGraph(State)
workflow.add_node("conversation", call_model)
workflow.add_node(summarize_conversation)

# Set the entrypoint as conversation
workflow.add_edge(START, "conversation")
workflow.add_conditional_edges("conversation", should_continue)
workflow.add_edge("summarize_conversation", END)

# Compile
graph = workflow.compile(checkpointer=memory)
display(Image(graph.get_graph().draw_mermaid_png()))

Model cümleleri çalışma anında küçük farklılıklar gösterebilir; buna karşın pretty_print() biçimi, StateSnapshot yapısı ve aynı thread_id ile state’in geri okunması dersin teknik sonucunu gösterir.

Graph Akışı

Graph akışı, tek bir konuşma node’u ve koşullu özetleme kararından oluşur. State içindeki mesaj sayısı belirli eşiği aşmadığında graph doğrudan biter; eşik aşıldığında özetleme node’u çalışır ve ardından graph sonlanır.

STARTSanal başlangıç noktasıdır.
conversationcall_model node’u LLM cevabı üretir.
should_continueMesaj sayısına göre rota üretir.
summarize_
conversationGerekirse summary üretir ve eski mesajları kaldırır.
ENDGraph yürütmesi tamamlanır.

Koşullu Akışın Kritik Noktası

workflow.add_conditional_edges("conversation", should_continue) satırı, conversation node’undan sonra kararın state’e bağlı verilmesini sağlar. Bu nedenle graph akışı yalnızca çizgisel değildir; konuşma uzunluğuna bağlı olarak özetleme node’u devreye girebilir.

State’in Evrimi

Bu dersin state’i iki temel alan üzerinden okunabilir: messages ve summary. Checkpointer bu alanların thread bazlı son durumunu saklar.

Agent / Tool Etkileşimi

Bu derste tam bir agent-tool döngüsü kurulmaz. Odak, chatbot state’inin özetleme ve harici checkpointer ile nasıl yönetildiğidir. Buna rağmen aynı kalıcılık yaklaşımı tool kullanan agent graph’larında da önemlidir; çünkü tool çağrıları arttıkça konuşma geçmişini, ara state’i ve thread kimliğini güvenilir biçimde saklamak gerekir.

KullanıcıYeni mesaj aynı thread kimliğiyle graph’a verilir.

CheckpointerGüncellenmiş state’i SQLite deposunda saklar.

Yaygın Hatalar

  • memory değişkenini LLM’in semantik belleği sanmak; bu derste memory bir checkpointer nesnesidir.
  • :memory: ile açılan SQLite bağlantısını dosya tabanlı kalıcılık sanmak.
  • Aynı konuşmayı sürdürmek için thread_id değerinin aynı kalması gerektiğini unutmak.
  • Graph yeniden tanımlanınca eski state’in otomatik olarak graph nesnesinin içinde kalacağını düşünmek.
  • RemoveMessage yerine Python listesinden doğrudan eleman silmeyi LangGraph state güncellemesiyle eşdeğer görmek.
  • Özetleme node’unun token maliyetini azalttığını, fakat kalıcılığı tek başına çözmediğini gözden kaçırmak.
  • Dosya tabanlı SQLite bağlantısının doğru dosyaya bağlandığını kontrol etmemek.
  • API anahtarını kod içine yazmak veya veritabanı dosyasına gizli bilgi koymak.
  • Studio’daki yerleşik kalıcılık katmanını bu dersteki SQLite örneğiyle aynı dağıtım modeli sanmak.

Son Çıkarımlar

  1. Uzun süreli chatbot belleği için özetleme ve checkpointing birbirini tamamlar.
  2. SqliteSaver, SQLite bağlantısını LangGraph checkpointer arayüzüne bağlar.
  3. :memory: hızlı deneme sağlar; dosya yolu ise yeniden başlatma sonrası kalıcılık sağlar.
  4. thread_id, checkpoint kayıtlarını doğru konuşmayla eşleştiren temel anahtardır.
  5. summary state alanı, eski konuşmayı kısa bağlam olarak korur.
  6. RemoveMessage, mesaj temizleme işlemini LangGraph reducer semantiğiyle uyumlu hale getirir.
  7. Graph’ın checkpointer ile compile edilmesi, state’in kalıcılık katmanına yazılabilmesi için gereklidir.
  8. graph.get_state(config), saklanan thread state’ini incelemek için kullanılır.
  9. Graph nesnesi yeniden oluşturulabilir; önemli olan aynı checkpointer deposu ve aynı thread kimliğidir.
  10. Studio/API bağlamındaki kalıcılık, burada gösterilen checkpointer fikrinin daha uygulama odaklı bir karşılığıdır.

from langgraph.checkpoint.sqlite import SqliteSaver

memory = SqliteSaver(conn)

from typing_extensions import Literal

from langchain_core.messages import HumanMessage, RemoveMessage, SystemMessage
from langchain_openai import ChatOpenAI
from langgraph.graph import END, MessagesState


model = ChatOpenAI(model="gpt-4o", temperature=0)


class State(MessagesState):
    """
    Define the state schema used by the graph.
    """
    summary: str

# Define the logic to call the model
def call_model(state: State):
    """
    Run the call_model graph node.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    # Get summary if it exists
    summary = state.get("summary", "")

    # If there is summary, then we add it
    if summary:
        # Add summary to system message
        system_message = f"Summary of conversation earlier: {summary}"

        # Append summary to any newer messages
        messages = [SystemMessage(content=system_message)] + state["messages"]
    else:
        messages = state["messages"]

    response = model.invoke(messages)
    return {"messages": response}

def summarize_conversation(state: State):
    """
    Run the summarize_conversation graph node.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    # First, we get any existing summary
    summary = state.get("summary", "")

    # Create our summarization prompt
    if summary:
        # A summary already exists
        summary_message = (
            f"This is summary of the conversation to date: {summary}\n\n"
            "Extend the summary by taking into account the new messages above:"
        )
    else:
        summary_message = "Create a summary of the conversation above:"

    # Add prompt to our history
    messages = state["messages"] + [HumanMessage(content=summary_message)]
    response = model.invoke(messages)

    # Delete all but the 2 most recent messages
    delete_messages = [RemoveMessage(id=m.id) for m in state["messages"][:-2]]
    return {"summary": response.content, "messages": delete_messages}

# Determine whether to end or summarize the conversation
def should_continue(state: State) -> Literal["summarize_conversation", END]:
    """Return the next node to execute."""

    messages = state["messages"]

    # If there are more than six messages, then we summarize the conversation
    if len(messages) > 6:
        return "summarize_conversation"

    # Otherwise we can just end
    return END

from IPython.display import Image, display
from langgraph.graph import START, StateGraph

# Define a new graph
workflow = StateGraph(State)
workflow.add_node("conversation", call_model)
workflow.add_node(summarize_conversation)

# Set the entrypoint as conversation
workflow.add_edge(START, "conversation")
workflow.add_conditional_edges("conversation", should_continue)
workflow.add_edge("summarize_conversation", END)

# Compile
graph = workflow.compile(checkpointer=memory)
display(Image(graph.get_graph().draw_mermaid_png()))
