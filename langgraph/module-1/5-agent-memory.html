LangGraph’ta Agent Belleği: Checkpoint ve Thread ile Durumu Koruma

Bu bölüm, ReAct agent akışında graph state’inin neden geçici olduğunu ve checkpointer ile aynı konuşma bağlamının nasıl sürdürüldüğünü açıklar.

Kapsam ve Bağlam

Bu derste amaç, tool kullanabilen ReAct agent yapısına bellek kazandırmaktır. Önce agent’ın tek bir graph çalıştırmasında doğru davrandığı, fakat ayrı bir çalıştırmada önceki sonucu hatırlamadığı gösterilir. Ardından aynı graph, bir checkpointer ile derlenerek geçmiş state değerlerini belirli bir thread altında saklayabilir hale getirilir.

Temel problem şudur: Belleksiz graph çalıştırmaları birbirinden bağımsızdır. İlk çağrıda 3 + 4 sonucu oluşsa bile, ikinci çağrıda “that” ifadesi bu sonucu otomatik olarak taşımaz. Checkpointing bu kopukluğu giderir.

Bu Dersin Ana Tezi

LangGraph’ta bellek, node fonksiyonlarının local değişkenlerinde değil, graph state’inin checkpoint olarak saklanmasında ortaya çıkar. Aynı thread_id ile yapılan sonraki çağrı, önceki checkpoint zincirinden devam edebilir.

Öğrenme Hedefleri

  • Graph state’inin varsayılan olarak tek çalıştırma ile sınırlı olduğunu açıklayabilmek.
  • Belleksiz agent çağrısı ile checkpoint kullanan agent çağrısı arasındaki farkı yorumlayabilmek.
  • MemorySaver, checkpointer, thread_id ve checkpoint kavramlarını ilişkilendirebilmek.
  • Aynı thread içinde ikinci çağrının önceki mesaj geçmişini nasıl kullandığını takip edebilmek.
  • Agent belleğinin tool çağrısı, mesaj geçmişi ve state sürekliliği açısından neden kritik olduğunu açıklayabilmek.

Ön Koşullar

  • Python fonksiyonları, list ve dictionary yapıları.
  • Type hint ve docstring ile tool şeması oluşturma fikri.
  • Chat model, tool call ve ReAct agent döngüsü kavramları.
  • MessagesState, ToolNode ve tools_condition hakkında temel bilgi.
  • Ortam değişkeni ve API anahtarı kullanımı.

Belleksiz agent her invoke çağrısında yeni bir state ile başlar. Bu nedenle önceki çağrıda oluşan 7 sonucu ikinci çağrıda bağlam olarak bulunmaz. Bellekli agent ise her graph adımından sonra checkpoint yazar ve bu checkpoint’leri bir thread altında toplar.

Ana Anlatım

Geçici State Problemi

LangGraph state’i, varsayılan durumda tek graph çalıştırmasının bağlamıdır. İlk çağrı tamamlandığında oluşan mesaj geçmişi sonraki bağımsız çağrıya otomatik olarak taşınmaz. Bu davranış güvenli ve açık bir varsayılandır; ancak konuşma sürekliliği gereken agent sistemlerinde yetersiz kalır.

Checkpoint Fikri

Checkpointer, graph’ın her önemli adımında state’in bir anlık görüntüsünü saklar. Bu kayıt yalnızca mesajları değil, graph’ın yürütme bağlamına ait ek bilgileri de taşıyabilir. Böylece sonraki çağrı aynı thread altında başlatıldığında graph kaldığı bağlamdan devam edebilir.

Thread Kimliği

thread_id, hangi checkpoint zincirinin kullanılacağını belirler. Aynı kimlik kullanıldığında ikinci çağrı ilk çağrının state geçmişini görür; farklı kimlik kullanıldığında bağımsız bir konuşma başlatılmış olur.

Üretim Açısından Not

MemorySaver eğitim ve prototip için kullanışlıdır; kalıcı üretim sistemlerinde daha dayanıklı bir saklama katmanı tercih edilir. Materyalde bu kalıcı katmanın ayrıntılı kurulumu ele alınmaz.

Kod Yürüyüşü

Kod akışı önce belleksiz agent davranışını gösterir, ardından aynı graph’ı checkpointer ile derleyip aynı thread üzerinden devam eden çağrıları çalıştırır.

Aritmetik tool’ları ve modeli hazırlama

Bu blok, üç aritmetik fonksiyonu tool olarak tanımlar ve chat modelini bu tool’ları çağırabilecek şekilde hazırlar.

Aritmetik tool’ları ve modeli hazırlama
from langchain_openai import ChatOpenAI


def multiply(a: int, b: int) -> int:
    """
    Multiply a and b.

    Args:
        a: first int
        b: second int
    """
    return a * b


# This will be a tool
def add(a: int, b: int) -> int:
    """
    Adds a and b.

    Args:
        a: first int
        b: second int
    """
    return a + b


def divide(a: int, b: int) -> float:
    """
    Divide a and b.

    Args:
        a: first int
        b: second int
    """
    return a / b


tools = [add, multiply, divide]
llm = ChatOpenAI(model="gpt-4o")
llm_with_tools = llm.bind_tools(tools)

LangGraph açısından önemi

Model doğal dil isteğini yapılandırılmış tool call değerlerine dönüştürebilir.

Dikkat edilmesi gereken nokta

Assistant node’unu tanımlama

Bu blok, sistem talimatını ve mevcut mesaj geçmişini modele veren graph node’unu kurar.

Assistant node’unu tanımlama
from langchain_core.messages import HumanMessage, SystemMessage
from langgraph.graph import MessagesState


# System message
sys_msg = SystemMessage(
    content=(
        "You are a helpful assistant tasked with performing arithmetic "
        "on a set of inputs."
    )
)


# Node
def assistant(state: MessagesState):
    """
    Run the assistant graph node.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    return {
        "messages": [
            llm_with_tools.invoke(
                [sys_msg] + state["messages"]
            )
        ]
    }

Belleksiz ReAct graph’ı kurma

Bu blok, tool çağrısı oldukça tools node’una, tool sonucundan sonra yeniden assistant node’una dönen agent graph’ını kurar.

Belleksiz ReAct graph’ı kurma
from IPython.display import Image, display
from langgraph.graph import START, StateGraph
from langgraph.prebuilt import ToolNode, tools_condition


# Graph
builder = StateGraph(MessagesState)

# Define nodes: these do the work
builder.add_node("assistant", assistant)
builder.add_node("tools", ToolNode(tools))

# Define edges: these determine how the control flow moves
builder.add_edge(START, "assistant")
builder.add_conditional_edges(
    "assistant",
    # If the latest message from assistant is a tool call,
    # tools_condition routes to tools.
    # If not, tools_condition routes to END.
    tools_condition,
)
builder.add_edge("tools", "assistant")
react_graph = builder.compile()

# Show
display(Image(react_graph.get_graph(xray=True).draw_mermaid_png()))

LangGraph açısından önemi

Bu graph tek çalıştırma içinde tool sonucunu modele geri besler; fakat ayrı çağrılar arasında state saklamaz.

Henüz checkpointer kullanılmadığı için graph uygulaması belleksizdir.

Bu derste state’in ana alanı messages listesidir. Checkpointer kullanılmadığında bu liste yalnızca tek çalıştırma içinde yaşar. Checkpointer kullanıldığında aynı thread içindeki sonraki çağrı bu listeyi önceki checkpoint’ten devam ettirir.

Agent / Tool Etkileşimi

Kullanıcı: 3 ile 4’ü topla.
Assistant: add(a=3, b=4) tool çağrısını üretir.
Tool: 7 sonucunu döndürür.
Checkpoint: Bu mesaj geçmişi seçili thread altında saklanır.
Kullanıcı: Bunu 2 ile çarp.
Assistant: Önceki checkpoint sayesinde that = 7 bağlamını kullanır.

Yaygın Hatalar

  • Graph state’ini Python local değişkeni gibi düşünmek; state varsayılan olarak çalıştırma kapsamındadır.
  • Checkpointer eklemeden agent’ın önceki çağrıları hatırlamasını beklemek.
  • thread_id vermeden belleğin hangi konuşmaya ait olacağını belirleyememek.
  • Farklı kullanıcıları aynı thread altında çalıştırarak state karışmasına yol açmak.
  • MemorySaver nesnesini kalıcı üretim veri deposu gibi görmek.
  • Tool sonucunu model cevabı ile karıştırmak; tool sonucu state’e eklenen ayrı bir mesajdır.
  • Tracing ile checkpointing’i aynı şey sanmak; biri gözlemleme, diğeri state saklama mekanizmasıdır.

Son Çıkarımlar

  • LangGraph state’i varsayılan olarak tek graph çalıştırmasına aittir.
  • Agent’ın konuşma sürekliliği için state’in checkpoint olarak saklanması gerekir.
  • MemorySaver, eğitim ve prototip için basit bir in-memory checkpointer sağlar.
  • Checkpointer, graph state’ini her adımda checkpoint olarak yazar.
  • thread_id, hangi checkpoint zincirinin kullanılacağını belirler.
  • Aynı thread ile yapılan sonraki çağrı önceki mesaj geçmişinden devam eder.
  • Bellekli agent, “that” gibi bağlama bağlı ifadeleri önceki state ile yorumlayabilir.
  • Tool çağrısı, tool sonucu ve assistant yanıtı mesaj geçmişinde farklı roller taşır.
  • Tracing gözlemlenebilirlik sağlar; checkpointing state sürekliliği sağlar.
  • Üretim sistemlerinde thread izolasyonu ve kalıcı saklama katmanı dikkatle tasarlanmalıdır.

builder.add_conditional_edges(
    "assistant",
    # If the latest message from assistant is a tool call,
    # tools_condition routes to tools.
    # If not, tools_condition routes to END.
    tools_condition,
)
builder.add_edge("tools", "assistant")
react_graph = builder.compile()

# Show
display(Image(react_graph.get_graph(xray=True).draw_mermaid_png()))

messages = [
    HumanMessage(
        content="Add 3 and 4."
    )
]
messages = react_graph.invoke({"messages": messages})
