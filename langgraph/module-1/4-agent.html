LangGraph’ta ReAct Agent Döngüsü: Tool Sonucunu Modele Geri Besleme

Bu bölüm, router desenini tool çıktısını tekrar modele besleyen çok adımlı agent döngüsüne dönüştürür.

Kapsam ve Bağlam

Bu derste amaç, önceki router fikrini daha genel bir agent mimarisine dönüştürmektir. Router yapısında model tool çağırırsa tool çalışır ve akış biter; burada ise tool çıktısı tekrar modele gönderilir. Bu küçük kenar değişikliği, modelin yeni gözleme göre bir sonraki adımı seçebilmesini sağlar.

Bu tasarım ReAct yaklaşımının temel sezgisini taşır: model eylem seçer, tool sonucu gözlemler, ardından bu gözleme göre yeniden akıl yürütür. Döngü, model artık tool çağırmayıp doğal dil yanıtı verdiğinde sona erer.

Bu Dersin Ana Tezi

Agent davranışı, tek bir model çağrısından değil, state içinde biriken mesaj geçmişi ve graph üzerinde tanımlanan geri dönüş kenarından doğar. tools node’undan assistant node’una dönen edge, tool sonucunu yeni karar için modele geri taşır.

Öğrenme Hedefleri

  • Router graph ile agent döngüsü arasındaki tek yapısal farkı açıklayabilmek.
  • ToolNode, tools_condition ve MessagesState bileşenlerinin birlikte nasıl çalıştığını yorumlayabilmek.
  • Bir model çıktısındaki tool call değerinin gerçek tool yürütmesine nasıl dönüştüğünü takip edebilmek.
  • Tool sonucunun tekrar modele verilmesiyle çok adımlı aritmetik planlamanın nasıl gerçekleştiğini açıklayabilmek.
  • Tracing’in agent döngüsünü gözlemleme ve hata ayıklama açısından neden yararlı olduğunu değerlendirebilmek.

Ön Koşullar

  • Python fonksiyonları, liste ve dictionary yapıları.
  • Type hint ve docstring ile fonksiyon şeması oluşturma fikri.
  • Chat model, mesaj listesi ve tool çağrısı kavramlarına temel aşinalık.
  • Ortam değişkeni ve API anahtarı kullanım mantığı.
  • StateGraph, node, edge ve conditional edge kavramlarının başlangıç düzeyinde bilinmesi.

Ana Anlatım

Router’dan Agent Döngüsüne

Router, model çıktısına göre iki yoldan birini seçer: doğrudan bitiş veya tool yürütme. Agent döngüsünde tool yürütme bitiş değildir; tool sonucu tekrar modele verilerek yeni bir karar noktası oluşturulur.

Act, Observe, Reason

Bu akışta model önce bir eylem seçer; örneğin add tool’unu çağırır. Tool sonucu yeni bir mesaj olarak state’e yazılır. Model bu sonucu gözlemleyerek bir sonraki tool’u seçer veya nihai cevabı üretir.

Döngünün Durma Mantığı

Döngü sonsuza kadar çalışmak zorunda değildir. tools_condition, son assistant mesajında tool call görmediğinde graph’ı END yönüne taşır. Böylece nihai doğal dil cevabı, durma sinyali gibi davranır.

Gözlemlenebilirlik

Agent döngülerinde hangi tool’un ne zaman çağrıldığını görmek önemlidir. Tracing, sistem mesajını, model çağrılarını, tool payload değerlerini, token kullanımını ve gecikmeleri incelemeyi sağlar.

Kod Yürüyüşü

Kod akışı, ortam hazırlığından başlayıp tool tanımlarına, assistant node’una, graph döngüsüne ve nihai agent çalıştırmasına ilerler.

Aritmetik tool’ları tanımlama ve modele bağlama

Bu blok, üç tip açıklamalı Python fonksiyonunu tool olarak tanımlar ve modeli bu tool şemalarıyla çalışacak şekilde hazırlar.

Aritmetik tool’ları tanımlama ve modele bağlama
from langchain_openai import ChatOpenAI


def multiply(a: int, b: int) -> int:
    """
    Multiply a and b.

    Args:
        a: first int
        b: second int
    """
    return a * b


# This will be a tool
def add(a: int, b: int) -> int:
    """
    Adds a and b.

    Args:
        a: first int
        b: second int
    """
    return a + b


def divide(a: int, b: int) -> float:
    """
    Divide a and b.

    Args:
        a: first int
        b: second int
    """
    return a / b


tools = [add, multiply, divide]
llm = ChatOpenAI(model="gpt-4o")

# For this lesson, parallel tool calling is disabled because
# arithmetic steps usually depend on the previous result.
llm_with_tools = llm.bind_tools(
    tools,
    parallel_tool_calls=False,
)

LangGraph açısından önemi

Model tool çağrısı üretir; gerçek yürütme daha sonra ToolNode tarafından yapılır.

Dikkat edilmesi gereken nokta

Sıralı aritmetik görevlerde paralel tool çağrısı kapatılır; aksi halde bağımlı işlemler yanlış sıraya düşebilir.

Assistant node’unu tanımlama

Bu blok, sistem talimatını ve mevcut mesaj geçmişini modele veren graph node’unu kurar.

Assistant node’unu tanımlama
from langchain_core.messages import HumanMessage, SystemMessage
from langgraph.graph import MessagesState


# System message
sys_msg = SystemMessage(
    content=(
        "You are a helpful assistant tasked with performing arithmetic "
        "on a set of inputs."
    )
)


# Node
def assistant(state: MessagesState):
    """
    Run the assistant graph node.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    return {
        "messages": [
            llm_with_tools.invoke(
                [sys_msg] + state["messages"]
            )
        ]
    }

LangGraph açısından önemi

Agent’ın karar merkezi bu node’dur; tool çağrısı veya nihai yanıt burada üretilir.

Dikkat edilmesi gereken nokta

Node yalnızca yeni mesajı döndürür; mesaj geçmişine ekleme davranışı MessagesState tarafından yönetilir.

ReAct graph döngüsünü kurma

Bu blok, assistant ve tools node’larını bağlar; kritik fark, tools node’undan tekrar assistant node’una dönen edge’dir.

ReAct graph döngüsünü kurma
from IPython.display import Image, display
from langgraph.graph import START, StateGraph
from langgraph.prebuilt import ToolNode, tools_condition


# Graph
builder = StateGraph(MessagesState)

# Define nodes: these do the work
builder.add_node("assistant", assistant)
builder.add_node("tools", ToolNode(tools))

# Define edges: these determine how the control flow moves
builder.add_edge(START, "assistant")
builder.add_conditional_edges(
    "assistant",
    # If the latest message from assistant is a tool call,
    # tools_condition routes to tools.
    # If not, tools_condition routes to END.
    tools_condition,
)
builder.add_edge("tools", "assistant")
react_graph = builder.compile()

# Show
display(Image(react_graph.get_graph(xray=True).draw_mermaid_png()))

LangGraph açısından önemi

builder.add_edge("tools", "assistant") ifadesi, tool sonucunu modelin yeni kararına girdi yapar.

Dikkat edilmesi gereken nokta

Model sürekli tool call üretirse döngü devam eder; gerçek sistemlerde recursion sınırı veya ek güvenlik koşulları düşünülmelidir.

Çıktı Yorumu

Akış önce insan mesajını, ardından add, multiply ve divide tool çağrılarını gösterir. Her tool sonucu yeniden modele döner; model ancak son tool sonucundan sonra nihai doğal dil yanıtı üretir.

Çıktıların Yorumlanması

Graph görseli yapısal akışı, mesaj çıktısı ise çalışma zamanındaki gerçek sıralamayı gösterir. Bu iki çıktı birlikte okunduğunda agent’ın kontrol akışı ile model-tool mesajlaşması arasındaki ilişki netleşir.

Mesaj geçmişindeki tool çağrıları modelin neyi yapmak istediğini, tool mesajları ise gerçekten neyin çalıştığını gösterir. Son assistant mesajı artık tool call içermediği için tools_condition graph’ı sonlandırır.

Graph Akışı

STARTBaşlangıç state’i graph’a girer.
assistantModel, mesaj geçmişine göre karar verir.
tools_conditionTool call var mı diye bakar.
toolsTool call gerçek fonksiyona dönüşür.
assistant / ENDTool sonucu döner veya nihai yanıtla biter.

State’in Evrimi

Bu derste gerçek state alanı messages adını taşır. Döngü ilerledikçe bu alan tek bir mesaj değil, insan mesajı, assistant tool call mesajı ve tool sonuç mesajlarından oluşan bir geçmiş haline gelir.

Yaygın Hatalar

  • bind_tools çağrısının tool’u çalıştırdığını sanmak; bu çağrı yalnızca tool şemasını modele tanıtır.
  • ToolNode çıktısının kullanıcıya doğrudan dönmesini beklemek; bu derste sonuç tekrar assistant node’una gider.
  • tools_condition fonksiyonunu normal if bloğu gibi görmek; bu fonksiyon graph geçişini belirler.
  • messages alanını yalnızca son mesaj sanmak; bu alan tüm konuşma ve tool geçmişini taşır.
  • Sıralı görevlerde paralel tool çağrısını açık bırakmak.
  • Agent döngülerinde durma koşulu ve recursion sınırını düşünmemek.
  • Tracing’i yalnızca loglama sanmak; tracing tool payload değerlerini, model çağrılarını ve performans bilgisini anlamak için kullanılır.

Son Çıkarımlar

  • ReAct agent, router yapısına tool sonucunu modele geri veren bir edge ekleyerek kurulabilir.
  • assistant node’u model kararını üretir; tools node’u bu kararı gerçek fonksiyon yürütmesine çevirir.
  • tools_condition, son assistant mesajında tool call olup olmadığını denetler.
  • Tool sonucu, yeni bir mesaj olarak state’e eklenir ve modelin sonraki kararına girdi olur.
  • Model doğal dil yanıtı verdiğinde ve tool call üretmediğinde graph biter.
  • Sıralı aritmetik görevlerde paralel tool çağrısını kapatmak daha güvenli bir tasarımdır.
  • MessagesState, agent geçmişinin tek merkezde taşınmasını sağlar.
  • Tracing, agent döngülerini anlamak ve hata ayıklamak için önemli bir tamamlayıcıdır.
  • Agent davranışı yalnızca prompt’tan değil, graph edge’lerinden ve state birleştirme davranışından da doğar.
