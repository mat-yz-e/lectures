LangGraph’ta Router: Conditional Edge ile Tool Node’a Yönlendirme

Bu bölüm, tool-aware model çıktısını okuyarak graph akışını doğrudan yanıt veya araç yürütme yoluna ayıran temel router desenini açıklar.

Kapsam ve Bağlam

Bu bölümde amaç, tool çağrısı üretebilen bir chat modelini gerçek bir graph kontrol akışına bağlamaktır. Önceki chain örneğinde model tool call üretebiliyordu; burada bu tool call artık graph içinde ayrı bir node tarafından yürütülür.

Router deseni, agent sistemlerinde kritik bir ayrım yapar: Bazı girdiler doğrudan model yanıtıyla tamamlanır, bazı girdiler ise dış bir aracı çalıştırmayı gerektirir. LangGraph bu ayrımı açık edge yapılarıyla temsil eder.

Bu Dersin Ana Tezi

Router, model çıktısını yalnızca metin olarak okumaz; çıktının yapısına bakarak graph’ın sonraki adımını seçer. Bu nedenle tool call, yalnızca bir model cevabı değil, uygulama kontrol akışını değiştiren yapılandırılmış bir sinyaldir.

Öğrenme Hedefleri

  • Tool call üreten model çıktısının graph akışını nasıl yönlendirdiğini açıklayabilmek.
  • ToolNode ile gerçek tool yürütme adımını graph node’u olarak kurabilmek.
  • tools_condition ve add_conditional_edges ilişkisini yorumlayabilmek.
  • MessagesState içinde insan mesajı, model mesajı ve tool mesajının nasıl taşındığını takip edebilmek.
  • Doğrudan yanıt yolu ile tool yürütme yolu arasındaki farkı agent tasarımı açısından ayırt edebilmek.

Ön Koşullar

  • Python fonksiyonları, type hint ve docstring yapısı.
  • Dictionary ve list veri yapıları.
  • Chat model çağrısı ve mesaj nesneleri hakkında temel sezgi.
  • Tool calling kavramı: modelin fonksiyon adı ve argüman üretmesi.
  • LangGraph’ta node, edge, state ve compile kavramları.

Büyük Resim

Bu derste kurulan graph bir agent döngüsünün en küçük ama önemli biçimlerinden biridir. Model önce kullanıcı girdisini değerlendirir. Eğer çıktı tool call içerirse graph tools node’una gider; aksi durumda graph biter.

Ana Anlatım

Router Mantığı

Router, bir graph’ın tek bir sabit sırayla ilerlemesini engeller; bunun yerine çalışma zamanındaki mesaja göre yol seçer. Bu derste karar, modelin son mesajında tool call olup olmamasına dayanır.

ToolNode’un Rolü

ToolNode, tool call bilgisini alır, ilgili Python fonksiyonunu çağırır ve sonucu mesaj geçmişine eklenebilecek bir tool çıktısına dönüştürür. Böylece tool yürütme işi model node’undan ayrılır.

Conditional Edge’in Önemi

add_conditional_edges, graph’ı doğrusal bir zincir olmaktan çıkarır. Model node’undan sonra karar fonksiyonu çalışır ve graph’ın sonraki hedefini belirler.

Öğrencinin Sorması Gereken Soru

Model yanıtı doğrudan kullanıcıya mı dönmeli, yoksa graph içinde başka bir node tarafından işlenmeli mi? Router tasarımının temel sorusu budur.

Kod Yürüyüşü

Kod akışı, önce tool-aware modeli hazırlar; ardından koşullu edge ile model çıktısına göre tool node veya bitiş yolunu seçen router graph’ı kurar.

Modeli ve çarpma aracını hazırlama

Bu blok, tip açıklamalı `multiply` fonksiyonunu tanımlar, chat modelini oluşturur ve fonksiyonu modele tool olarak bağlar.

Modeli ve çarpma aracını hazırlama
from langchain_openai import ChatOpenAI


def multiply(a: int, b: int) -> int:
    """
    Multiply a and b.

    Args:
        a: first int
        b: second int
    """
    return a * b


llm = ChatOpenAI(model="gpt-4o")
llm_with_tools = llm.bind_tools([multiply])

LangGraph açısından önemi

Router kararının ilk aşaması modelin tool call üretip üretmemesidir; bu nedenle model tool şemasını bilmelidir.

Dikkat edilmesi gereken nokta

`bind_tools` aracı çalıştırmaz; yalnızca modelin araç çağrısı üretebilmesi için şemayı sağlar.

ToolNode ve conditional edge ile router graph kurma

Bu blok, model çağrısını bir node olarak ekler; ardından model çıktısına göre tool node’a veya bitişe yönlenen koşullu edge’i kurar.

ToolNode ve conditional edge ile router graph kurma
from IPython.display import Image, display
from langgraph.graph import END, START, StateGraph
from langgraph.graph import MessagesState
from langgraph.prebuilt import ToolNode, tools_condition


# Node
def tool_calling_llm(state: MessagesState):
    """
    Run the tool_calling_llm graph node.

    Args:
        state: Current graph state.

    Returns:
        Value produced for the surrounding example.
    """
    return {
        "messages": [
            llm_with_tools.invoke(state["messages"]),
        ]
    }


# Build graph
builder = StateGraph(MessagesState)
builder.add_node("tool_calling_llm", tool_calling_llm)
builder.add_node("tools", ToolNode([multiply]))
builder.add_edge(START, "tool_calling_llm")
builder.add_conditional_edges(
    "tool_calling_llm",
    # If the latest assistant message is a tool call,
    # tools_condition routes to tools.
    # Otherwise, tools_condition routes to END.
    tools_condition,
)
builder.add_edge("tools", END)
graph = builder.compile()

# View
display(Image(graph.get_graph().draw_mermaid_png()))

LangGraph açısından önemi

`add_conditional_edges`, graph kontrol akışını model çıktısına göre değiştirir; bu dersin router davranışı burada oluşur.

Dikkat edilmesi gereken nokta

`ToolNode` yalnızca tool call varsa anlamlıdır; normal model yanıtları bu node’a gitmeden `END` yoluna yönlenir.

Çıktı Yorumu

Graph görseli, model node’undan sonra iki olası yol olduğunu gösterir: tool call varsa `tools`, yoksa `END`.

Çıktı

Router graph’ı insan mesajıyla çalıştırma

Bu blok, graph’a bir insan mesajı verir, graph yürütmesini başlatır ve oluşan mesaj geçmişini okunabilir biçimde yazdırır.

Router graph’ı insan mesajıyla çalıştırma
from langchain_core.messages import HumanMessage

messages = [
    HumanMessage(
        content="Hello, what is 2 multiplied by 2?",
    )
]
messages = graph.invoke(
    {
        "messages": messages,
    }
)
for m in messages["messages"]:
    m.pretty_print()

LangGraph açısından önemi

Aynı graph girdiye göre doğrudan yanıt veya tool yürütme yolu seçebilir; bu çağrı router’ın çalıştırılabilir yüzeyidir.

Dikkat edilmesi gereken nokta

Kayıtlı çıktı doğrudan yanıt yolunu gösterir; tool gerektiren girdilerde graph `tools` node’una yönlenebilir.

Çıktı Yorumu

Bu çıktı, mesaj geçmişinin insan mesajı ve model yanıtı olarak yazdırıldığını gösterir. Router davranışında belirleyici olan, model yanıtının tool call içerip içermemesidir.

Router graph görsel araçlarla incelenebilir; ancak bu deneyim kullanılan çalışma ortamına bağlıdır.

Dikkat edilmesi gereken nokta

Bu blok graph mantığını değiştirmez; yalnızca ortam uyumluluğunu kontrol eder.

Çıktıların Yorumlanması

Graph görseli, model node’u sonrasında koşullu ayrım olduğunu gösterir. Bu ayrım tool çağrısı içeren çıktıların tools node’una, normal model yanıtlarının ise END yoluna gitmesini sağlar.

Metin çıktısında mesaj geçmişi okunabilir biçimde görünür. Kayıtlı çıktı doğrudan yanıt yolunu gösterir; tool çağrısı içeren girdilerde aynı graph tool node üzerinden yürütme yapacak şekilde tasarlanmıştır.

Graph Akışı

STARTBaşlangıç state’i graph’a girer.
tool_calling_llmModel son mesaja göre yanıt veya tool call üretir.
tools_conditionSon mesaj tool call içeriyor mu diye bakar.
toolsTool call varsa multiply çalıştırılır.
ENDDoğrudan yanıt veya tool sonucu ile graph biter.

State’in Evrimi

Bu derste gerçek state alanı messages adını taşır. Model yanıtı, tool call ve tool sonucu aynı mesaj geçmişi üzerinden izlenir.

BaşlangıçHumanMessage girdisi messages alanına alınır.
Model node’uAIMessage üretir; bu mesaj tool call içerebilir.
Tool nodeTool call varsa ToolNode sonucu mesaj geçmişine ekler.
Nihai statemessages alanı insan, model ve varsa tool mesajlarını birlikte taşır.

Agent / Tool Etkileşimi

Doğrudan yanıt: Girdi tool gerektirmiyorsa model yanıtı graph’ı bitirir.
Tool yolu: Girdi aritmetik tool gerektiriyorsa model multiply için tool call üretir.
Yürütme: ToolNode tool call argümanlarını kullanarak aracı çalıştırır ve sonucu mesaj geçmişine ekler.

Yaygın Hatalar

  • bind_tools çağrısının tool’u çalıştırdığını sanmak; bu çağrı yalnızca modelin tool call üretebilmesini sağlar.
  • tools_condition fonksiyonunu sıradan Python if bloğu gibi düşünmek; bu yapı graph edge seçimi için kullanılır.
  • Tool call ile tool sonucu arasındaki ayrımı karıştırmak.
  • ToolNode eklemeden tool call üretimini gerçek tool yürütmesi sanmak.
  • Graph compile edilmeden invoke etmeye çalışmak.
  • State içindeki messages alanını yalnızca son mesaj sanmak; bu alan mesaj geçmişini temsil eder.

Son Çıkarımlar

  • Router, model çıktısına göre graph yolunu seçen temel agent desenidir.
  • Tool-aware model, doğrudan yanıt veya tool call üretebilir.
  • ToolNode, tool call bilgisini gerçek Python fonksiyonu yürütmesine bağlar.
  • tools_condition, hazır bir conditional edge karar fonksiyonudur.
  • add_conditional_edges, graph’ı doğrusal zincirden karar veren yapıya dönüştürür.
  • MessagesState, insan, model ve tool mesajlarını aynı state alanında taşır.
  • Tool call, tool sonucu değildir; tool sonucu ayrı yürütme adımıyla oluşur.
  • Router mantığı, daha gelişmiş agent loop tasarımlarının temelidir.
