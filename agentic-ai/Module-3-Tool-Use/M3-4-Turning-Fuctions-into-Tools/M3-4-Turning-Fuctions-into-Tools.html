Fonksiyonları Araçlara Dönüştürmek

Sıradan Python fonksiyonlarını, bir dil modelinin çağırabileceği araçlara dönüştürmek; modelin doğru aracı kendi seçtiğini, argümanları çıkardığını ve birden çok adımı doğru sırayla yürüttüğünü uygulamalı olarak görmek.

Kapsam ve Bağlam

Bu uygulamalı çalışmada bir dizi araç oluşturup bir dil modeline veriyoruz ve modelin bu araçları nasıl çağırdığını, görevle ilgili olanı nasıl seçtiğini gözlemliyoruz. Bütün altyapıyı AISuite adlı bir istemci kütüphanesi üstlenir: yazdığımız Python fonksiyonlarını modele tanımlanabilir araçlara çevirir, modelin çağrı talebini yakalar, fonksiyonu yerel ortamda çalıştırır ve sonucu modele geri besler.

Çalışmanın amacı, araç çağırma tasarım desenlerini bir ajan iş akışına uygulamaktır. Bunu yaparken modele Python fonksiyonlarına denetimli erişim verir, argüman geçişini ve yürütme akışını yönetir ve çok adımlı çıktıları doğrularız. Önceki bölümlerde araç çağrısının elle (özel bir metin kalıbı üretip arayarak) nasıl kurulduğunu görmüştük; burada aynı fikrin modern, kütüphane destekli karşılığını çalıştırıyoruz.

Bu Çalışmanın Ana Fikri

İyi belgelenmiş bir Python fonksiyonu (özellikle açık bir docstring ile), bir kütüphane aracılığıyla doğrudan bir araca dönüşebilir. Model bu aracı ne zaman ve hangi argümanlarla çağıracağına kendisi karar verir; çağrının yerel olarak çalıştırılıp sonucun modele döndürülmesi ise kütüphanenin işidir. Böylece model, salt metin üretmenin ötesine geçip gerçek eylemler gerçekleştirebilir.

Öğrenme Hedefleri

  • Bir Python fonksiyonunu, docstring’i sayesinde bir dil modeli aracına dönüştürebilmek.
  • Aracı modele otomatik olarak verme (max_turns ile) ile şemayı elle yazıp çağrıyı kendin yönetme yaklaşımlarını ayırt edebilmek.
  • Bir araç çağrısı yanıtının iç yapısını (araç çağrısı talebi, argümanlar, yerel çalıştırma, son yanıt) okuyabilmek.
  • Argüman alan ve almayan araçları tasarlayıp modele birlikte sunabilmek.
  • Model birden çok araç arasından doğru olanı seçtiğinde ve birkaç aracı sırayla kullandığında akışı izleyip yorumlayabilmek.
  • Çok adımlı bir araç dizisinde, bir aracın çıktısının sonraki adımı nasıl beslediğini açıklayabilmek.

Ön Koşullar

  • Python fonksiyonları, argümanlar, docstring ve return kavramlarına aşinalık.
  • Sözlük (dict) ve liste yapılarını okuyabilmek; JSON’un genel mantığı.
  • Bir dil modeline mesaj listesi gönderip yanıt alma (rol/içerik yapısı) kavramı.
  • Araç kullanımı temeli: modelin bir işlevin çağrılmasını talep etmesi, çalıştırmanın çağrıyı yapan tarafa ait olması.
  • Ortam değişkeni ve API anahtarı kullanımının genel mantığı.

Büyük Resim

Bir fonksiyonu araca dönüştürme döngüsü dört ana adımdan oluşur. Aşağıdaki akış, çalışmanın omurgasını tek bakışta gösterir: fonksiyonu tanımlarsın, istemciye araç olarak verirsin, model uygun olanı seçip çağırır ve sonuç son yanıta dönüşür.

1Fonksiyonu yazAçık bir docstring ile ne yaptığı belli bir Python fonksiyonu tanımlanır.
2Araç olarak verİstemciye araç listesi olarak sunulur; docstring şemaya dönüşür.
3Model seçer ve çağırırİsteme uygun aracı seçip argümanlarıyla çağrı talep eder.
4Çalıştır ve yanıtlaAraç yerel çalışır, sonucu geri beslenir, model son yanıtı verir.

Otomatik mod (max_turns)

  • Fonksiyonu doğrudan araç listesine koyarsın.
  • Çağrı yakalama ve çalıştırmayı kütüphane üstlenir.
  • Hızlı ve az kodludur.

Elle mod (şema)

  • Aracı ad/açıklama/parametre şemasıyla tanımlarsın.
  • Çağrıyı sen yakalar, fonksiyonu sen çalıştırırsın.
  • Akış üzerinde tam denetim sağlar.

İki yol da aynı çekirdek mantığı paylaşır: model yalnızca hangi aracı hangi argümanlarla çağıracağına karar verir; fonksiyonun gerçekten çalışması ve sonucun modele dönmesi çağrıyı yapan tarafça yürütülür. Fark, bu yürütmeyi kütüphanenin mi yoksa senin mi üstlendiğindir.

Ana Anlatım

Bir fonksiyonu araca dönüştürmenin sırrı, çoğu zaman tek bir şeyde gizlidir: iyi bir docstring. Kullandığımız istemci kütüphanesi, fonksiyonun adını, parametrelerini ve docstring’deki açıklamayı okuyarak modele “şu adda, şu işi yapan, şu parametreleri olan bir araca erişimin var” diyen bir tanım üretir. Model bu tanıma bakarak aracı ne zaman ve nasıl çağıracağına karar verir.

Aracı modele vermenin iki yolu vardır. Birinci yolda fonksiyonu doğrudan araç listesine koyar ve max_turns belirleriz; kütüphane çağrıyı yakalamayı, yerel çalıştırmayı ve sonucu modele geri beslemeyi kendisi yapar. İkinci yolda aracı elle bir şema (ad, açıklama, parametreler) olarak tanımlarız; bu durumda çağrıyı yakalamak ve fonksiyonu çalıştırmak bize düşer. İlk yol pratiktir; ikinci yol perde arkasında neler olduğunu açıkça gösterir.

Kod Yürüyüşü

Şimdi araçları parça parça inşa edeceğiz. Her adımda önce fikri açıklayacak, ardından ilgili kodu ve varsa ürettiği çıktıyı göstereceğiz. Kod satırlarının üzerine gelerek (ya da klavyeyle odaklanarak) o satırın ne yaptığına dair notları görebilirsiniz.

Başlangıçta ortam yüklenir ve birkaç paket içe aktarılır. Gizli anahtarlar ortam değişkenlerinden okunur; ayrıca araç çağrılarının iç adımlarını okunabilir biçimde gösterecek bir yardımcı görüntüleme modülü de hazır tutulur.

İlk aracın fonksiyonu

İlk araç olarak, güncel saati metin biçiminde döndüren bir fonksiyon tanımlanır. Buradaki docstring yalnızca bir açıklama değildir; kütüphane onu aracın amacını modele anlatmak için kullanır. Bu yüzden docstring’in açık ve doğru olması kritik bir tasarım kararıdır.

from datetime import datetime def get_current_time():    """    Returns the current time as a string.    """    return datetime.now().strftime("%H:%M:%S")

Fonksiyonu doğrudan çağırdığımızda ne döndürdüğünü görebiliriz. Bu, aracın LLM’den bağımsız olarak da çalışan sıradan bir Python fonksiyonu olduğunu hatırlatır.

get_current_time()

Saat dilimi notu

Çalışma ortamı varsayılan olarak Greenwich Ortalama Saati’ni (GMT) kullanır. Aynı fonksiyon yerel bir makinede çalıştırılırsa, onun yerine o makinenin yerel saatini döndürür.

Fonksiyonu bir LLM aracına dönüştürmek

Aracı modele vermek için önce mesaj yapısını kurarız. Mesaj listesi, kullanıcının istemini ve her mesajın bir role (örneğin “user”, “assistant”, “system”) ile content taşıdığı konuşma geçmişini temsil eder.

# Message structureprompt = "What time is it?"messages = [    {        "role": "user",        "content": prompt,    }]

Şimdi sohbet tamamlamasını (chat completion) kurarız. Bu çağrı LLM isteğini bizim için yapar ve sonucu döndürür. Parametreler şunlardır: model kullanılacak model; messages modele iletilen mesaj listesi; tools modelin erişebileceği araçların listesi; max_turns ise modelin yapabileceği azami mesaj sayısı — sonsuz döngüleri ve bir aracın tekrar tekrar çağrılmasını önler.

response = client.chat.completions.create(    model="openai:gpt-4o",    messages=messages,    tools=[get_current_time],    max_turns=5) # See the LLM responseprint(response.choices[0].message.content)

The current time is 21:52:43.

Model, isteği yanıtlamak için saat aracını çağırmaya karar verdi; çağrı kütüphane tarafından yakalanıp yerel olarak çalıştırıldı ve sonuç modele geri beslendi. Son yanıt, dönen saati doğal bir cümle içinde sunar. Burada fonksiyonu bir araca dönüştürmek için tek yaptığımız, onu tools listesine koymak ve max_turns vermek oldu.

Aracı Elle Tanımlamak

Docstring sayesinde fonksiyonun otomatik olarak araca dönüşmesi çok kullanışlıdır. Peki perde arkasında fonksiyon araca dönüşürken ne oluyor? Aslında aracın modele görünen hâli daha ayrıntılıdır. Araçlar yine bir liste içinde verilir; ama bu listedeki her araç belirli bir şema bekler. Bu şemanın önemli parçaları: name (yerelde tanımladığın fonksiyonun adı), description (fonksiyonun ne yaptığını anlatan ve modelin ne zaman kullanacağına karar vermesine yarayan açıklama) ve parameters (fonksiyonun parametreleri varsa, ad ve açıklamalarıyla).

tools = [{    "type": "function",    "function": {        "name": "get_current_time", # <--- Your functions name        "description": "Returns the current time as a string.", # <--- a description for the LLM        "parameters": {}    }}]

Şemayı elle tanımladığımız bu durumda çağrının çalıştırılmasını kütüphaneye bırakmayız; bu yüzden max_turns kullanılmaz ve çalıştırmayı kendimiz yöneteceğiz. Önce yanıtı oluşturalım.

response = client.chat.completions.create(    model="openai:gpt-4o",    messages=messages,    tools=tools, # <-- Your list of tools with get_current_time    # max_turns=5 # <-- When defining tools manually, you must handle calls yourself and cannot use max_turns)

Yanıtı ham hâliyle inceleyelim. Bu kez kütüphane çağrıyı bizim yerimize çalıştırmadığı için, modelin “bir araç çağırmak istiyorum” isteğini doğrudan görebiliriz.

Modele Daha Fazla Araç Vermek

Tek araçla mekanizmayı gördükten sonra, modele birden çok araç verip aralarından seçim yapmasını izleyebiliriz. Üç yeni araç tanımlıyoruz: konum bazlı hava durumu getiren get_weather_from_ip, belirtilen içerikle bir metin dosyası oluşturan write_txt_file ve bir görsel gömülü QR kodu üreten generate_qr_code. Üçü de yine sıradan Python fonksiyonlarıdır; docstring’leri sayesinde araca dönüşürler.

get_weather_from_ipIP’den konumu saptar, hava durumu API’sinden anlık, en yüksek ve en düşük sıcaklığı getirir. Argümansızdır.
write_txt_fileVerilen yola, verilen içerikle bir metin dosyası yazar. İki argüman alır: file_path ve content.

import requestsimport qrcodefrom qrcode.image.styledpil import StyledPilImage  def get_weather_from_ip():    """    Gets the current, high, and low temperature in Fahrenheit for the user's    location and returns it to the user. Args:        file_path (str): Destination path.        content (str): Text to write.    Returns:        str: Path to the written file.    """    with open(file_path, "w", encoding="utf-8") as f:        f.write(content)    return file_path  # Create a QR codedef generate_qr_code(data: str, filename: str, image_path: str):    """Generate a QR code image given data and an image path.     Args:        data: Text or URL to encode        filename: Name for the output PNG file (without extension)        image_path: Path to the image to be used in the QR code    """    qr = qrcode.QRCode(error_correction=qrcode.constants.ERROR_CORRECT_H)    qr.add_data(data)     img = qr.make_image(image_factory=StyledPilImage, embedded_image_path=image_path)    output_file = f"{filename}.png"    img.save(output_file)     return f"QR code saved as {output_file} containing: {data[:50]}..."

Argümanlı ve argümansız araçlar

Hava durumu ve saat araçları argüman almaz; dosya yazma ve QR araçları argüman alır. Model, hangi aracın hangi argümanlara ihtiyaç duyduğunu şemadan anlar ve değerleri istemden çıkarır.

Docstring neden bu kadar önemli?

Her fonksiyonun docstring’i, kütüphanenin ürettiği araç tanımının açıklama ve parametre kısmını besler. Açıklama ne kadar net olursa, model aracı o kadar isabetli seçer ve doğru argümanları geçirir.

Aynı anda birden çok araç

Son olarak, modelin tek bir istem için birkaç aracı sırayla kullanabildiğini görelim. Karmaşık istem, hem bir QR kodu üretmeyi hem de güncel hava durumunu içeren bir not yazmayı ister. Burada ince bir mantık vardır: istem notu önce yazmayı söylese de, notun içeriği (hava durumu) önce elde edilmelidir. Bu yüzden model, doğru bilgiyi doğru sırada toplamak için araçları uygun düzende çağırmak zorundadır.

Bu akışta nelere dikkat etmeli?

Model, kullanıcı isteğine göre hangi aracı kullanacağını kendisi seçer; argümanları (dosya adı, içerik, URL) kullanıcının mesajından çıkarır; her araç, modelin yanıtına kattığı bir bilgi döndürür; hava ve saat gibi argümansız araçlar hızlı bilgi istekleri için idealdir; ve karmaşık işlemler perde arkasında olup biterken konuşma doğal hisseder.

Yaygın Hatalar

Sık karşılaşılan yanlış anlamalar

  • Belirsiz docstring yazmak. Araç tanımının açıklaması docstring’den üretilir; muğlak bir docstring, modelin aracı yanlış zamanda seçmesine veya hiç seçmemesine yol açar.
  • Elle şema modunda max_turns beklemek. Şemayı kendin tanımladığında çağrıyı yakalama ve çalıştırma sana aittir; max_turns bu modda kullanılmaz.
  • Araç sonucunu geçmişe eklememek. Aracın çıktısı role="tool" mesajı olarak eklenip modele geri verilmezse, model son yanıtını üretecek bilgiye sahip olmaz.
  • Argümanların modelce üretildiğini unutmak. Dosya adı, içerik veya URL gibi argümanları model istemden çıkarır; kod yalnızca bunları işleve aktarır.
  • Bağımlı adımları sıralamamak. Bir aracın çıktısı başka bir aracın girdisiyse (önce hava durumu, sonra not), doğru sıra olmadan sonuç eksik kalır.

Son Çıkarımlar

Araç çağırma, dil modellerini salt metin üretmenin ötesine taşır: fonksiyonları, akıl yürütmelerinin bir parçası olarak kullanabilir hâle gelirler. Açık ve iyi belgelenmiş fonksiyonlar (özellikle net docstring’ler) modelin her aracı ne zaman ve nasıl kullanacağını bilmesini sağlar. Kullandığımız istemci kütüphanesi, Python fonksiyonlarını araç şemalarına çevirme ve çok adımlı iş akışlarını düzenleme karmaşıklığını üstlenir.

İki çalışma biçimini gördük: araçları max_turns ile otomatik vermek ya da şemayı yazıp ara adımları elle yönetmek. Tek araçlı basit bir saat sorgusundan, üç aracı doğru sırada kullanan karmaşık bir göreve kadar aynı çekirdek döngü işledi. Akışı (istem, araç çağrıları, sonuçlar, son yanıt) izlemek, ajan davranışını anlamanın ve hata ayıklamanın temel yoludur. Model seçimi de önemlidir: hafif modeller hızlı ve ucuz prototipleme için, güçlü modeller akıl yürütme yoğun, çok adımlı işler için uygundur. Bu öğelerle artık, LLM akıl yürütmesini gerçek araçlarla birleştiren, güvenilir ve genişletilebilir ajan iş akışları tasarlamanın temeline sahipsiniz.

Dersin Kod Akışı

Aşağıda, derste kullanılan çalıştırılabilir kod tek bir yerde toplanmıştır: önce ortam, istemci ve dört aracın tanımı; ardından, araç çağrılarının ara adımlarını okunabilir biçimde gösteren yardımcı görüntüleme modülü. Bütün bloklar kopyalanabilir.

Kurulum ve araç tanımları

Aşağıdaki blok, dört aracın eksiksiz tanımını bir arada toplar. Her fonksiyon, docstring’i sayesinde istemciye verildiğinde bir araca dönüşür.

from datetime import datetimeimport requestsimport qrcodefrom qrcode.image.styledpil import StyledPilImage  def get_current_time():    """    Returns the current time as a string.    """    return datetime.now().strftime("%H:%M:%S")  def get_weather_from_ip():    """    Gets the current, high, and low temperature in Fahrenheit for the user's    location and returns it to the user.    """    # Get location coordinates from the IP address    lat, lon = requests.get('https://ipinfo.io/json').json()['loc'].split(',')     # Set parameters for the weather API call    params = {        "latitude": lat,        "longitude": lon,        "current": "temperature_2m",        "daily": "temperature_2m_max,temperature_2m_min",        "temperature_unit": "fahrenheit",        "timezone": "auto"    }     # Get weather data    weather_data = requests.get("https://api.open-meteo.com/v1/forecast", params=params).json()     # Format and return the simplified string    return (        f"Current: {weather_data['current']['temperature_2m']}°F, "        f"High: {weather_data['daily']['temperature_2m_max'][0]}°F, "        f"Low: {weather_data['daily']['temperature_2m_min'][0]}°F"    )  # Write a text filedef write_txt_file(file_path: str, content: str):    """    Write a string into a .txt file (overwrites if exists).    Args:        file_path (str): Destination path.        content (str): Text to write.    Returns:        str: Path to the written file.    """    with open(file_path, "w", encoding="utf-8") as f:        f.write(content)    return file_path  # Create a QR codedef generate_qr_code(data: str, filename: str, image_path: str):    """Generate a QR code image given data and an image path.     Args:        data: Text or URL to encode        filename: Name for the output PNG file (without extension)        image_path: Path to the image to be used in the QR code    """    qr = qrcode.QRCode(error_correction=qrcode.constants.ERROR_CORRECT_H)    qr.add_data(data)     img = qr.make_image(image_factory=StyledPilImage, embedded_image_path=image_path)    output_file = f"{filename}.png"    img.save(output_file)     return f"QR code saved as {output_file} containing: {data[:50]}..."
